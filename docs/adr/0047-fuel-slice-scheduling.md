# 0047: マシンの中の燃料の配り方（スライスとラウンドロビン）

- 状態: 採用
- Issue: #47（task）。前提: ADR 0027（実行スレッド）、0028（燃料の計測）、0043（カーネルの構成）、0329（p1 の待ち点化）
- 後続: #205（サーバー全体の燃料配分）、#251（仮の値の確定）、#122（CPU のティアごとの値）

## 背景

CPU の性能は、もう 1 tick の燃料に反映されている（`PartTier.cpuFuelPerTick` → `MachineConfig.fuelPerTick`）。足りないのはマシンの中の配り方で、`FuelAccount.take` は CPU を取ったプロセスにマシンの燃料を全部渡していた。計算し続けるプロセスが1つあると、その tick の燃料を1人で使い切る。イベントで起こされた対話的なプロセス（シェルなど）は CPU の FIFO で待ち、順番が来ても燃料が 0 なので次の tick まで待つ。応答が tick の単位で遅れていた。

イベントを待つプロセスが燃料を使わないことは、もう満たしている（待機点型は待つ間スレッドも燃料も持たない。ブロッキング型は `block` で燃料を返す。補充は遅延なので、待つだけの台に tick ごとの処理はない）。

## 決めたこと

- **1回に渡すのはスライスまで。** `FuelAccount.take(now, limit)` は `grant = min(fuel, fuelSlice)` を渡し、残りはマシンに置く。CPU を持っている間の `KernelState.fuel` は、その tick の残り（0 以上）になる。
  - 返す規則（`giveBack`）は変えない。tick が進んでいれば、残りは 0 以上なので補充の結果は `fuelPerTick` になり、そこへ手持ちの `min(r, 0)` を足す。使わなかった分は、手持ちもマシンの残りも持ち越さず、行き過ぎた分だけ持ち越す（ADR 0028 の規則のまま）。1 tick に渡す合計は `fuelPerTick` まで。
- **スライスを使い切ったとき**（燃料切れの処理の3つの入口: 前借り・スレッドを持ったまま・巻き戻す）は、カーネルロックの中で次のどれかに分ける。
  1. **その場で足す**: 一時停止（マシンだけの quiesce も）でなく、手持ちを渡した tick の中（`FuelAccount.lastRefillTick` が今の tick）で、書き戻した後のマシンの燃料が正で、CPU を待つプロセス（`MachineCpu.waiting`）も燃料待ちもいない。残りを書き戻してから次のスライスを取り、戻り値で返す。CPU と許可を返さず、巻き戻しもしない。プロセスが1つだけの台は、同じ tick の中なら、今までどおり 1 tick に `fuelPerTick` まで使える。
     - **tick をまたいだら足さない（許可を回す）。** 許可（`PermitPool`）はサーバー全体で数が限られ（CPU スレッドの半分）、公平な順で回る。#47 より前は、燃料切れ（= `fuelPerTick` を使い切る）のたびに許可と CPU を返して並び直していたので、許可を持ち続けるのは `fuelPerTick` の間までだった。スライスにして足すだけだと、1 スライスが 1 tick より長くかかる台（サーバーが遅れを取り戻して tick を続けて回しているとき、遅い環境）が、tick が進んでもそのまま足し続けて、待つ・止める・一時停止が来るまで許可を持ち続け、許可の数以上の台がそうなるとほかの台が許可を取れなくなる。そこで、手持ちを渡した後に tick が進んでいたら、待つ者がいなくても、次の「譲る」と同じ道（許可と CPU を返して取り直す）に落とす。同じ tick の中は、1 tick に配る燃料が `fuelPerTick` までなので、許可を持つのは前と同じ長さまで。
  2. **譲る**: マシンの燃料が残っているが、待つ者がいるか、手持ちを渡した tick が進んでいる。今の燃料切れの道で CPU と許可を返し、FIFO の後ろに並び直す。待機点型の巻き戻せるところでは巻き戻してスレッドを返す（燃料待ちの列に入るが、マシンの燃料が正なので、書き戻したところで自分も起こされ、CPU の列に並ぶ）。ブロッキング型・巻き戻せないところでは、スレッドを持ったまま CPU を取り直す。状態は変えない（`WAITING_FUEL` にしない。燃料を待つのではないため）。
  3. **燃料を待つ**: マシンの燃料が残っていないか、一時停止。今までと同じ。
- **燃料切れの処理はグローバルを読まない・書かない**（ADR 0043）。その場で足すときも、残りは引数、新しい手持ちは戻り値。手持ちは燃料切れの処理を呼んだインスタンス（今の holder）に入るので、作っている途中・ホスト関数の中から呼んだゲストの中でも同じに扱える。
- **前借り（#477）より、その場で足すのを先に試す。** 譲る相手がいなければ前借りしない。いれば前借りで巻き戻せるところまで進み、そこで巻き戻して譲る。
- **優先度は入れない。** 公平さは、CPU の FIFO・スライス・燃料待ちの列の順で作る。計算し続けるプロセスが n 本あっても、イベントで起きたプロセスは最大で n スライス分の後に動く（同じ tick の中で動ける）。ゲストから優先度を変える口は、システムコールの ABI と保存形式に関わるので、ここでは作らない。
  - **tick をまたぐ順番**: 1 tick の燃料が尽きると、残りの全員が燃料待ちの列に入る（尽きたスライスを使ったプロセスが先頭、続いて CPU の待ち行列の順）。次の tick は、燃料待ちを**列に入った順（FIFO）に**起こし、起こされたスレッドを持たないプロセスはその順で CPU の待ち行列に並ぶ。先頭をずらす仕組み（以前の `fuelRotation`）は外した: 巻き戻して譲るたびにも起こす回数が増えて先頭の位置が実行の様子で変わり、プロセスの数が 1 tick のスライスの数（既定で4）より多いと、配分が偏った（5本・4スライスの手で追った例で、5 tick の間に動く回数が 5:3:3:5:4）。FIFO なら、同じ長さのスライスを使い切る n 本は、n tick で全員が同じ回数動く（n = 5、4 スライスで 4 回ずつ）。
  - ブロッキング型は、起こされたスレッドが `cpu.acquire` に着く順が実行の様子で変わるので、順番は厳密でない（スレッドの起き上がりのぶんだけぶれる）。待機点型（スレッドを持たない）は列の順どおり。
- **スライスの値（仮。確定は #251）**: `fuelPerTick` の 1/4 か 250,000 の大きいほう。ただし `fuelPerTick` まで（`MachineConfig.defaultFuelSlice`）。下限は、確かめる点の間の行き過ぎ（lua.wasm で最大約 7,000 命令。ADR 0028）と前借りの上限（50,000）より十分大きくして、毎回の行き過ぎで区切りが崩れないようにする。既定の `fuelPerTick` 1,000,000 では 250,000（1 tick に4回）、CREATIVE の 4,000,000 では 1,000,000。`fuelPerTick` が 250,000 以下の台は、今までと同じく1回に全部を渡す。
  - `MachineConfig.fuelSlice` は内部の項目（テストで小さくできる）。保存しない（`fuelPerTick` から毎回決める）。
- **一時停止・停止の上限はスライスまで縮む。** 止まるまでに実行中のプロセスが使うのは、手持ち（最大でスライス）まで。その場で足す道は、停止の印と一時停止を見て、立っていれば今の燃料切れの道に落とす。
- **保存形式・ABI・公開 API は変えない。** スライスの残りや順番は実行時だけ。待機点ではどのインスタンスの `kibi_fuel` も 0 のまま。`ProcessState` も増やさない。
- **台数に比例しない。** `tick()` で全台・全プロセスに配る処理は足さない（遅延補充のまま）。その場で足すのは、カーネルロックの中で CPU の待ち行列のロック（末端のロック）を1回読むだけ。譲るのは CPU を待つ者がいるときだけなので、計算し続けるプロセスが1つの台の費用は増えない（tick が進んだ後の最初のスライスの切れ目で、許可と CPU を返して取り直すのは、1 tick に1回まで。#47 より前の燃料切れごと = `fuelPerTick` ごとと同じ回数）。
- **数え口**（スケジューラの内部）: その場で足した回数（`fuelSliceRenewals`）と、燃料が残っている（一時停止でない）のに CPU と許可を返した回数（`fuelYields`。ほかに譲ったときと、tick が進んだので許可を回したときの両方）。`fuelUnwinds`・`fuelBlockingWaits` は、燃料が残っていない（か一時停止）ときだけ数える。一時停止で CPU を返したものは、`fuelBlockingWaits`・`fuelUnwinds` に数える。巻き戻すものは、巻き戻しの費用（退避した値の数 × `ASYNC_VALUE`）を引いた後のマシンの燃料が正のときだけ `fuelYields` に数える（引いた後に 0 以下なら、次の tick まで燃料を待つので `fuelUnwinds`）。

## 決めないこと

- 優先度と、それを変えるシステムコール（必要になったら別の Issue）
- サーバー全体の燃料の配分（#205）。マシンの燃料は `FuelAccount` の `fuelPerTick` だけで決まるので、後から外から変える口はここに足せる
- 作った後に `fuelPerTick` を変える口（サーバー全体の配分や、電力に応じた変更）。CPU のティアは作るときの `fuelPerTick` に反映済み（`PartTier.cpuFuelPerTick`）。ADR 0044 が #47 に送っていた「電力に応じて変える口」は、持ち主を #205 にする（電力の消費と不足は #128。燃料を絞る仕様は今ない）
- スライス・`fuelPerTick` の最終値（#251・#122）
- システムコールの燃料の費用（ADR 0063・0064 の「#47・#251」）。範囲が広いので別に扱う
