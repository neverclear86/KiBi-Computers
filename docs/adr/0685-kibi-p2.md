# 0685: `kibi:*` の p2 の interface（pollable・streams）と、仮置きの WIT の確定

- 状態: 採用
- Issue: #685（Epic #259）。前提は ADR 0073（`kibi:*` の WIT）、ADR 0263（リンク）、ADR 0265（resource のハンドル表）、ADR 0267（`wasi:*` の p2 のホスト）、#687（コンポーネントの exec）、各 interface の ADR（0074・0075・0077・0426・0427・0056・0306・0452・0453）
- プラン: #685 のコメント（オーナーのレビュー済み）。公開 API・セーブデータの形は変えない
- 後続: #269（コンポーネントのプロセスの保存）、#616（Component Model の層の検査の順）、#757（スレッドを持たない待ち）、#266・#268（p3）、`kibi:computer/memory` の p2・p3 の形（新しい Issue）、#251（仮の値の確定）
- 番号は Issue 番号にそろえている

## 背景

#687 で p2 のコマンドのコンポーネントが exec で動くようになったが、ホスト（`KernelDrivers.COMPONENT_HOST`）は `wasi:*` だけで、`kibi:*` を import すると `NOEXEC` だった。`kibi:*` の p2 の待ち方（`*-poll`）と `pipe-streams` は WIT だけの仮置きで、`wasi:*` の版も `@0.2.3` の仮のままだった。

## 決定

### 出す interface

各パッケージの `imports-p2` の world にある interface を出す（`kibi:*@0.1.0`。版は完全一致。ADR 0073 の Q5-A）:

- `kibi:kernel/{types, events, timers, events-poll, timers-poll}`
- `kibi:process/{process, process-poll}`
- `kibi:io/{tty, pipe-streams}`
- `kibi:fs/mounts`
- `kibi:device/{types, bus, bus-poll}`
- `kibi:computer/{clock, power}`（`kibi:computer` に `imports-p2` の world を足した）

出さないもの（読み込みで `NOEXEC`）: p1 だけの `kibi:io/fd`・`kibi:io/pipe`、p3 の `*-async`、`kibi:computer/memory`（p2・p3 での形は未定。新しい Issue で人に聞く）。

### WIT の確定

- 関数と型は仮置きのまま変えない。`wasi:*` の参照は `@0.2.3` から、ホストの基準の `@0.2.12`（ADR 0267 の `WasiP2Wit.BASE_VERSION`）にそろえた。ホストは `wasi:*@0.2.<n>` をどれも受けるので、ゲストの版はそろっていなくてよい
- ホストが読む WIT（`KibiP2Wit.TEXT`）は、`src/main/wit` の `imports-p2` の world をすべて import する中身のないコンポーネントを wasm-tools で作り、`component wit` で書き出したもののうち `package kibi:` の塊。`KibiP2HostTest` が `src/main/wit` から作り直したものと比べる

### ホスト

| 型 | 役目 |
| --- | --- |
| `KernelComponentHost` | `KernelDrivers.COMPONENT_HOST`。`wasi:` は `WasiP2Host`、`kibi:` は `KibiP2Host` に渡す。固定で状態を持たない |
| `KibiP2Host` | `kibi:*` の `ComponentHost`。`WitReader` で `KibiP2Wit.TEXT` を読み、関数の過不足を初回の参照で確かめる。resource の番号は `HostResourceIds.KIBI_FIRST`〜`KIBI_END`（`0x3000`） |
| `KibiP2Kernel`・`KibiP2Process`・`KibiP2Device` | 関数の本体。意味は p1 と同じ層（`wasi/kibi/Kibi*`）とカーネルの口を使う |
| `KernelEntry(handle, label)` | `kibi:*` の resource の実体（`HostResourceTable` に置く）。`label` は WIT の resource の名前 |

- `use wasi:io/poll@0.2.12.{pollable}` などの `wasi:*` の型は、`WasiP2Host` が読んだものに解決する（`WitReader` に、外で読んだ interface を渡せるようにした）。`pollable`・`input-stream`・`output-stream`・`descriptor` は `wasi:*` と同じ resource の番号・同じ dtor になり、`wasi:io/poll.poll` に並べて渡せる
- `WitReader` は、resource のメソッドと関数の型を、interface の型をすべて読んでから読むようにした（wasm-tools は resource を record より前に書くので、`event-queue.take` が後の `event-batch` を指す）

### カーネルの口

fd 版の口（p1）と同じ中身を、ハンドルの置き場だけ変えて使う。

- `HandlePlacement`（`kernel/fd`）: 新しいハンドルを置く場所。`FdPlacement` は fd 表、`KibiP2.placement` はプロセスの `HostResourceTable`。`Machine` の `openPendingDeviceCallLocked`・`openEventQueueLocked`・`execWithHandle`・`spawnInternal` などは置き場を受け取る。検査の順（`INVAL` → `NFILE` → `MFILE`、`pending-call` は `AGAIN` が `MFILE` より前）は p1 と同じ
- 既にあるハンドルは、表から引いた `HandleEntry` で受ける（`ProcessContext` の `takeEvents(HandleEntry, …)` など）。種類が違えば `BADF`（p2 では、ラベルの検査で先にトラップになる）
- `pending-call` の上限（`MAX_PENDING_CALLS` = 16）は、fd 表と `HostResourceTable` を合わせて数える
- 子のハンドル（`ProcessObject`）を p2 で drop したときも、fd を閉じたときと同じく `WakeSink.processHandleClosed` を呼ぶ（最後のハンドルなら、終わった子は刈り取り、動いている子は親なしにする）。最後かどうかは fd 表と `HostResourceTable` の両方を見る

### pollable

- `*-poll` の `subscribe` は、親（`event-queue`・`timer`・`process`・`pending-call`）の子の pollable（`PollableEntry.Object(parent, READABLE)`）を作る。`PollableEntry.Stream` を一般にしたもので、stream の pollable も同じ型
- pollable はカーネルのオブジェクトの参照を持たない。親の子の数に数え、子が残る親の drop はトラップ（ADR 0267 と同じ）
- そろう条件は p1 の `poll_oneoff` の `FD_READ` と同じ（`FdIo.pollEntryLocked`）。キューに送るタイマーはそろわない
- 待つのは `wasi:io/poll.poll`（`WasiP2Io.await`）だけで、新しい待ち方は足さない。`process.spawn` の読み込みと `device.invoke` のメインスレッドのメソッドは、p1 の BLOCK と同じカーネルの待ち（`ctx.execWithHandle`・`ctx.invokeDevice`）を使う

### エラー

- `error-code` は `kibi:kernel/types`（`KibiErrors`。p1 と同じ表）。デバイスは `call-error`
- `HostResourceTable` が満杯なら `mfile`、マシン全体の上限（`ResourceLimitException`）は `nfile`、`pending-call` の数は `again`。どれもトラップにしない（`wasi:*` の resource が満杯のときはトラップのまま。ADR 0267）
- 引数の上限は p1 の lift と同じ値・同じコード（path・cwd は 4096 バイトで `name-too-long`、`mount` の source は 4096 バイトで `invalid`、args・env の数と合計の大きさは `too-big`、fds は 256 個で `invalid`、method は 64 バイトで `name-too-long`、デバイスの引数は 32 個・64 KiB で `too-big`）
- 燃料は呼び出しごとに `WasiP1Fd.CALL_FUEL`（`P2.guard`）。一覧は件数分、`take` はイベントの数を足す
- `power.shutdown` は `ProcessKilledException` を投げて戻らない（トラップにしないので CRASHED にならない）。`reboot` は断られたら `not-supported`

### `kibi:process` の p2 の規則

- p2 のゲストの fd 表は 0/1/2 だけ。`spawn-options.fds` の `parent(n)` は n が 0..2 のときだけで、それ以外は `invalid`
- `spawn-with-handles`: `options.fds` を当ててから `handles` を当てる。同じ fd を 2 回（`handles` の中で、または `fds` と `handles` で）書いたら `invalid`。`handles` は 256 個まで（超えたら `invalid`）
- 渡せるもの: パイプの端・`Tty`・共有の位置の stream（`get-stdin` などで fd 0/1/2 を取ったもの）・`descriptor`（権利は flags の `read`・`write` から。どちらもなければ開いたときの権利）・`process`
- 自分の位置で読み書きするファイルの stream は `not-supported`（fd にすると共有の位置になり、意味が変わる。`descriptor` を渡す）。閉じた stream は `bad-descriptor`

### 保存

公開 API・セーブデータの形は変えない。`kibi:*` の resource を持つコンポーネントのプロセスは、`wasi:*` と同じく保存しない（UNSAVEABLE。#269）。戻したマシンの、まだ実行していないデバイスの呼び出しを回し直す走査（`Machine.redispatchRestoredDeviceCalls`）と、巻き直しで `pending-call` を引く口（`ProcessRunner` の `pendingDeviceCallFdOf`）は fd 表だけを見る。コンポーネントのプロセスは戻らないので今は困らず、`HostResourceTable` の `KernelEntry` も見るようにするのは #269 で扱う。

## 既知の違い

- p1 は文字列の lift で UTF-8 の誤り・範囲外のポインターを `invalid`・`fault` で返すが、Component Model の層は lift の時点でトラップになる（Canonical ABI の決まり。ADR 0264）
- `spawn` の検査の順（読み込みの前の検査とカーネルの検査）は、p1 と細部が違うところがある（#616 でそろえる）

## 確かめたこと

- `KibiP2HostTest`: WIT が `src/main/wit` から作ったものと同じ、出す interface の一覧、resource の番号の範囲と `wasi:*` との共有、版・出さない interface の拒否（読み込みの失敗）、全 world を import するダミーのコンポーネントのリンク
- `KibiP2BehaviourTest`: イベントキュー・タイマーと pollable、子の残る親の drop のトラップ、`pipe-streams` の読み書き、表が満杯の `mfile`、`spawn` と pollable と `status`、`spawn-with-handles` でパイプを子の標準出力にする、`spawn` の誤り（`no-entry`・`invalid`・`bad-descriptor`・`not-supported`）、子のハンドルの drop で刈り取る・親なしにする、プロセス・cwd・シグナル・マウント・時計・再起動、デバイスの `invoke`・`start`・`take` と `pending-call` の上限（fd と合わせて数える）。どのテストも、終わった後にホストの表が元の大きさに戻る（待っている間に resource が増えない）
