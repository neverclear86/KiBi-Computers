# 0104: 標準 OS のエディタ（vi 相当）

- 状態: 採用
- Issue: #104（task。Epic #97）。前提: ADR 0098（標準 OS のビルドと `kibi` ライブラリ）、0105（nano。画面・保存・待ち方の多くを同じにした）、0060（TTY）、0061（端末の解釈）、0427（`kibi:io/tty`）、0087（保存から戻ったときの描き直し）
- 番号は Issue 番号にそろえている

## 決めたこと（要約）

- `/bin/vi`（`os/bin/vi.zig` と `os/bin/vi/`）。`vi [+行 | +] [ファイル]`。POSIX vi のよく使う部分だけの、小さな vi
- 使うのは既存の import だけ（p1 の fd・path、`kibi:io/tty`、`kibi:computer/memory`、`kibi:kernel/events`）。新しいシステムコール・保存形式・公開 API は足していない
- `kibi.events`（restored のキュー）を使うので、`cabi_realloc` を export する（`core/build.gradle.kts` の `osReallocPrograms` に足した）
- 画面: 上から本文、いちばん下の 1 行（`-- INSERT --`・知らせ・`:` `/` `?` の入力）。テキストの終わりより後ろの行は `~`
- 知らせの言葉は英語（vim の知らせに近い固定文）。ソースのコメントは日本語
- テキストはバイト列のまま持ち、表示のときだけ解釈する。編集していないバイトは保存しても変えない。末尾に改行を足さない（nano と同じ）
- 待っている間は、標準入力の読み込みか、標準入力と restored のキューの `poll_oneoff`（時計なし）で止まるだけ。Esc の見分けにも時計を使わない
- 正規表現は `grep` のものを `kibi.regex`（`os/lib/kibi/regex.zig`）に移し、一致の位置を返す `find` を足した（下の「探す・置き換え」）
- 保存の手順・画面の出入り・表示の決まりは nano（ADR 0105）と同じ。部品はライブラリに移さず `os/bin/vi/` に写した（下の「nano との共有」）

## 起動と終わり

nano（ADR 0105「起動と終わり」）と同じ。違うところだけ書く。

- 引数は `+行`（その行の空白でない最初の文字から）、`+` だけ（最後の行）、`--`、`-h`/`--help`。ファイルは 1 つまで（2 つ以上は使い方の誤り 2）
- 開いたら `"名前" NL, NB`、ない名前は `"名前" [New]` を出す（行の数は vi の数え方。下の「行」）
- 終わるのは `:q`・`:q!`・`:wq`・`:x`・`ZZ`・`ZQ`。変更があれば `:q` は `No write since last change (add ! to override)` で断る
- 入力が終わった（TTY が閉じた）ときは、変更があれば `<名前>.save`（名前がなければ `vi.save`）に残す。同じ名前があれば番号を付けて避ける（nano と同じ）

## コマンド

normal モードで始まる。コマンドの前の数は回数（飽和の算術で受ける。`999999999dd` は全部の行）。

| 種類 | キー |
| --- | --- |
| 動き | `h j k l`・矢印・Backspace・Space・Ctrl+N・Ctrl+P、`w b e W B E`、`0 ^ $`・Home・End、`+ -`・Enter、`gg G`（数で行）、`H M L`、`f F t T` + 文字・`; ,`、`%`、`n N`、`/` `?` + 語 |
| 送る | Ctrl+F・PgDn・Ctrl+B・PgUp（1 画面 − 2 行）、Ctrl+D・Ctrl+U（半画面。数はその行数）、Ctrl+E・Ctrl+Y（1 行） |
| 入れる | `i a I A o O`・Insert。Esc か Ctrl+C で終わる。数を付けると打った分を繰り返す（途中で矢印などで動いたら繰り返さない） |
| 演算子 | `d c y` + 動き、`dd cc yy`（行）、`D C Y`、`s S`、`x X`・Delete |
| ほか | `p P`、`r` + 文字（Enter は改行 1 つ）、`J`、`~`（ASCII の大文字・小文字）、`u`・Ctrl+R、`.`、`ZZ`・`ZQ`、Ctrl+G（位置）、Ctrl+L（描き直す）、Ctrl+C（終わり方を出す） |

- 挿入の中では文字・Enter・Tab・Backspace（行の頭では前の行とつなぐ）・Delete・矢印・Home・End・PgUp・PgDn が効く
- `cw` は語の上なら語の終わりまで（空白を含めない）。`dw` などは、最後の語が行の終わりにあれば次の行へ出ない（vim と同じ）
- 含まない動き（`w` など）が次の行の頭で終わるときは、前の行の終わりまでにする（vim の `:help exclusive` の 1 つ目の決まり）
- 初心者向けに、normal の Ctrl+C で `Type :q! and press Enter to quit without saving`（変更がなければ `:q`）と出す
- レジスターは無名の 1 つだけ（`"x` はない）

### ex のコマンド

`:w [名前]`・`:w! 名前`、`:q[!]`、`:wq[!] [名前]`・`:x`、`:e!`（読み直す）、`:N`（行へ）、`:[範囲]s/語/置き換え/[g]`、`:[範囲]d`、`:set nu|nonu|ic|noic`（空なら今の値）、`:help`（man を案内）。範囲は `N`・`N,M`・`.`・`$`・`%`。知らない名前は `Not an editor command: ...`。

- `:w 名前` で、今の名前と違うファイルがあれば `File exists (add ! to override)` で断る
- 名前のないバッファは、`:w 名前` で書いた名前になる。別の名前に書いても、今のファイルの「変えた」は消えない（vim と同じ）

## Esc の見分け方

ADR 0105 は「素の Esc に大事な機能を割り当てない」と決めた（1 tick にまとめて届いたキーはつながって見えるため）。vi は Esc がいちばん大事なキーなので、次のように読む。

- 1 つのキーのバイト列は、1 回の入力として TTY に入る（`KeyboardDevice.input`、ADR 0060 の `splittable`）。読んだかたまりの最後の ESC は素の Esc（nano と同じ）
- `keys.Reader` に `split_escape` を足し、vi だけが立てる。立てると、ESC の後の文字（印字できる文字・UTF-8 の先頭バイト・制御文字）を Alt+文字にせず、素の Esc（1 バイト）と次のキーに分ける。速く打った「Esc → `:`」「Esc → `j`」「Esc → あ」が 1 回の入力で届いても、Esc と次のキーになる
- `ESC O` の後が表にない文字（A〜D・H・F・P〜S 以外）のときと、続きのない `ESC O` も、素の Esc と `O` に分ける（「Esc → `O`（上に行を開く）→ q」）
- `ESC [` は CSI のまま読む。`ESC O` + 表の文字（例: 「Esc → `O` → `A`」を 1 tick で打つ）も SS3 のまま（↑ になる）。矢印・F1〜F4 を読めなくなるので、このあいまいさは受け入れる（`ViEditorTest` で確かめている）
- 既定（nano・sh）の読み方は変えない。`split_escape` のない `keys.parse` はそのまま
- Alt+文字（`ESC x`）は vi では Esc と `x` になる（vim が meta を ESC で受けるときと同じ）
- 時計で待って見分ける（vim の `ttimeout`）ことはしない。待っているだけの台が起きることになるため（ADR 0087・ADR 0105）。カーネルに入力の境目を残す仕組みを足すのも、ABI の変更になるのでしない

## 表示

nano（ADR 0105「表示」）と同じ: 違う行だけを書く（FNV-1a のハッシュ）、縦に動いたらスクロール領域と `CSI S`・`CSI T`、読んだキーは全部処理してから 1 回描く、大きさは描く前に `generation` を比べる、制御文字は `^X`・DEL は `^?`・不正な UTF-8 は U+FFFD、タブは 8 桁、結合文字は前の文字とまとめる。

- 長い行は nano と同じく、カーソルのある行だけを横に送る（端に `$`）。vim の既定の折り返し表示は、画面の行とテキストの行の対応が複雑になるので v1 では入れない
- normal のカーソルは、行の最後の文字の上に置く（空の行では頭）。全角の文字の上では左のセル。テキストの終わりの改行の後ろには置かない
- `:set nu` で行の番号（`max(3, 桁数) + 1` 桁。画面が狭くて本文が 8 桁を切るなら出さない）
- 知らせのうち誤りは反転（SGR 7）で出す
- 小さな画面: 2 行以上は「本文 = 行数 − 1」。1 行の画面は、`:` などの入力か知らせがあるときだけ、いちばん下の行が本文を覆う（`-- INSERT --` は覆わない）。覆っている間は、知らせだけならカーソルを隠す（nano の #623 と同じ考え方）。本文が 1 行のときはスクロール領域を使わない

## 行

- vi の数え方: 改行で終わるテキストの、最後の改行の後ろ（空）は行に数えない（`"a\n"` は 1 行、`""` も 1 行）。挿入でテキストの終わりの改行の後ろに居るときだけ、その空の行も描く
- 行単位で写したもの（`dd`・`yy`・`yG` など）は必ず改行で終わる。改行で終わらない最後の行を消すときは、前の行の改行を消す。最後の行が改行で終わらないファイルの後ろに `p` で貼るときは、前に改行を入れて、貼ったものの最後の改行を取る。こうして、改行で終わらないファイルは改行で終わらないままにする（決まりは `lineRange` と `put` の 2 か所）
- 行の番号は増減で持つ（キーごとにテキスト全体をなめない）。カーソルを飛ばすときは、飛んだ間の改行を数える

## テキストと上限

- ギャップバッファ（nano の `buffer.zig` と同じ形）。上限は 4 MiB（仮の値。nano と同じ）。64 KiB ずつ `commit` で先に数え、数えられなければ `Not enough memory` で、その操作だけを断る
- レジスターも 4 MiB（触った分だけ数える）。入らなければ `Not enough memory to yank` で、消す操作も断る（消したものをどこにも残さないことを避ける）
- 回数での繰り返し（`3ix<Esc>`・`100p`・`5r`）は、合計の長さを先に確かめ、ギャップを 1 回で広げてから入れる（途中まで入れて止まらない。`999999999ix` は `The buffer is full` で断り、1 回分だけ残る）
- `:%s` は前から順に置き換え、ギャップを前へ単調に動かす（1 件ごとにテキスト全体を `memmove` しない）。行の終わりは長さの差から求め、置き換えのたびに行をなめ直さない。1 件ごとに `undo` の記録が 2 件できる
- 実行ファイルは約 57 KB（`ReleaseSmall`・`-fstrip`）

## 元に戻す

- 1 つのコマンド（挿入の 1 回、`:s` の 1 回、`.` の 1 回を含む）を 1 組にまとめる。組の中には「入れた（位置・バイト列）」「消した（位置・バイト列）」を順に並べ、戻すときは逆順に逆を当てる。挿入で続けて打った文字は 1 件につなげる（キーごとに記録を作らない）
- 記録の領域は 4 MiB（仮の値）で、静的に置き、使う分だけ `commit` で数える。足りなければ古い組から捨てる。1 組が領域より大きいか RAM が足りなければ、記録を全部捨てて `Not enough room to undo this change` と出す（編集そのものは断らない。トラップで落ちて、保存していない編集を失わないため）
- 戻す・やり直すの前に、入れる分のギャップと RAM を先に取る（途中まで戻して止まらないため）。要る量は、組の中を当てる順に「入れた分を足し、取り除く分を引く」と、途中でいちばん増えたところ（正味で大きさが変わらない組は、上限の近くでも戻せる）
- 戻したら、カーソルはそのコマンドの前の位置へ。戻してから新しく変えると、やり直せる組は捨てる
- 段数の上限は領域の大きさだけ（組の数では数えない）。戻して保存した時点と同じになっても「変えた」のまま（vim と違う）

## 繰り返し（`.`）

- テキストを変えるコマンド（`d c x X D C s S r J ~ p P i a I A o O`）のキー（数の後ろから、挿入で打った文字と Esc まで）を覚え、`.` はそれを読み直して当てる。`.` に数を付けると、元の数の代わりにその数
- 覚えるのは 1 コマンド 4,096 キーまで。超えた（大きな貼り付けを挿入したなど）コマンドは繰り返せない（`No previous command to repeat`）

## 探す・置き換え

- `/`・`?`・`n`・`N`・`:s` は、`kibi.regex`（POSIX の基本正規表現のうち `grep` と同じ部分。組・選択・回数・後方参照はない）で 1 行ずつ照合する。行はギャップバッファから写さず、`len` と `at(i)` を持つ `buffer.Line` として渡す
- `grep` の正規表現を `os/bin/grep/regex.zig` から `os/lib/kibi/regex.zig` に移した。ほかのコマンドのディレクトリを `@import` すると、Gradle の入力の追跡（`os/bin/<名前>/**` と `os/lib/kibi/**`）から漏れて古いまま残るため。照合を「スライスか、`len`・`at(i)` を持つ型」に広げ、一致した範囲を返す `find` を足した。`vi` は文章を書き換えるので、照合の単位を UTF-8 の 1 文字にした（`grep` も同じ照合を使う。下の「文字の単位」）
- 文字の単位: `.`・`[...]`・`[^...]` は UTF-8 の 1 文字を丸ごと 1 つとして合わせ、文字の途中のバイトには合わせない（`:s/^./X/` が「あ」を割って不正な UTF-8 を残さない）。`[あ-ん]` のような範囲・多バイトの文字への `*` も 1 文字単位。`[...]` に書ける ASCII でない文字の範囲は 8 つまで（超えると `Invalid pattern`）。不正なバイト列のバイトは 1 バイトで 1 文字。`:set ic` は ASCII だけ
- 語は 256 バイトまで（`/`・`?`・`:s` で同じ）。超えたら切り詰めずに `Pattern is too long` で断り、前の語を変えない（切り詰めると文字や `\` の途中で切れて、別の語になるため）
- 1 文字ずつ進む・戻る（探すの次の一致、空の一致の後、`x`・`X`・`l`・`h` などの回数）は、行の頭から数え直さない。次の文字はその位置だけで決まり、前の文字は文字の頭だと言える位置（ASCII・幅のある文字の頭など）まで戻ってから読む。4 MiB の 1 行でも、行の長さの 2 乗にならない
- 探すのは後ろへ（`?` は前へ）、終わりまでなければ頭から（`search hit BOTTOM, continuing at TOP`）。`:set ic` で ASCII の大文字・小文字を区別しない
- `:s` の置き換えでは `&` が一致したもの、`\&`・`\/` などは文字、`\r`・`\n` は改行。フラグは `g` だけ。語を空にすると前の語。範囲の行の中で、置き換えに改行が入っても、元の行の続きから探す。`g` では、空でない一致のすぐ後ろの空の一致は置き換えず、行の終わりの空の一致は置き換える（vim・sed と同じ。`baaac` に `:s/a*/-/g` で `-b-c-`）。置き換えの文字列が 4,096 バイトに入りきらないとき（`&` で長い一致を写すときを含む）は、その一致を置き換えず `Replacement is too long` で止める

## 保存

nano（ADR 0105「保存」）と同じ手順: `lstat` で調べ、シンボリックリンクなら先にそのまま書き、それ以外は同じディレクトリの `.<名前>.vi<0-9>` に排他で書いて `rename` で置き換える。一時ファイルが作れない（`NOSPC`・`DQUOT`・`NAMETOOLONG`）ときは、元より大きくならない場合に限って直接書く。失敗したら `Error writing <名前>: <説明>` を出し、バッファはそのままで編集を続ける。書けたら `"名前" NL, NB written`。

追記（#837）: 直接書く道は、切り詰めずに先頭から上書きしてから新しい長さに切る（nano と同じ。ADR 0105「保存」の追記）。途中で失敗しても空にはならないが、途中までの上書き（新しい先頭と元の残り）は残りうる。`close` の失敗も `Error writing` にする。

`:e!` は、ファイルがない（`NOENT`）ときだけ空の新しいファイルとして読み直す（起動の読み込み・保存と同じ）。ほかのエラー（`IO`・`ACCES`・`NOTDIR` など）では、そのエラーを出し、バッファ・元に戻す記録・変えた印に触らない（#837）。

## nano との共有

画面・保存・待ち方の部品は nano とほぼ同じだが、`kibi` ライブラリには移さず `os/bin/vi/` に写した。

- nano の `os/bin/nano/` を vi から `@import` すると、Gradle の入力の追跡から漏れる（上の「探す・置き換え」と同じ理由）
- ライブラリに移すと nano も書き換えることになり、この Issue の範囲で nano の振る舞いを変えるおそれがある。vi では行の数え方・カーソルの決まり・割り付けが違い、そのまま共有できる部分は保存の手順くらいしかない
- 保存の手順をライブラリに移すのは、3 つ目の使い手ができたときに別に行う

## 今の制限

- マクロ（`q`）、ビジュアルモード、マーク（`m`・`'`）、名前付きのレジスター、`R`（上書きのモード）、`>>`・`<<`、複数のファイル（`:n`・`:e ファイル`）、外のコマンド（`:!`・`:r !`）、`:g`、折り返し表示はない
- normal モードで Ctrl+V・Shift+Insert（クライアントの貼り付け）を使うと、中身がコマンドとして動く（本物の vi と同じ。貼り付けの目印がないので見分けられない）。先に `i` を押す
- 自動の字下げはしない（nano と同じ理由。貼り付けた Lua の字下げが二重になるため）
- 1 tick にまとめて届いた「Esc → `O` → 表の文字」は SS3 のキーになる（上の「Esc の見分け方」）
- 正規表現は 1 行の中だけ。改行にまたがる語は探せない
- 正規表現の 1 文字はコードポイントで、画面の 1 文字（結合文字を含む）とは違う。`.` は結合文字の前の文字だけに合い、結合文字は置き換えの後ろに残る
- 画面の大きさを変えても、次のキーまで描き直さない（nano と同じ）
