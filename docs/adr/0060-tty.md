# 0060: TTY デバイス（行編集モード・raw モード）

- 状態: 採用
- Issue: #60（task）。前提: ADR 0043（カーネル全体の設計）、0044（MC 層との境界）、0058（fd 表と標準入出力）
- 後続: #46（強制終了）、#54（`/dev/tty`）、#61（端末の解釈）、#63（イベントキュー）、#73（`kibi:*` の WIT）、#82（保存の形）、#102（シェル）、#142・#65・#66（接続層からの入力と画面の大きさ）
- 番号は Issue 番号にそろえている

## 決めたこと（要約）

- コードは `core.kernel.tty`。どれも `internal`。公開 API・ABI・保存のバイト形式は足さない
- コンソールの入出力2つの `ByteStream`（ADR 0058）を、TTY のカーネルオブジェクト `Tty` 1つに置き換えた。fd 0 は `(consoleTtyId, READ)`、fd 1・2 は `(consoleTtyId, WRITE)`。3つとも同じオブジェクトなので、TTY かどうかはどの fd でもわかる（p1 の `fd_fdstat_get` は `Tty` を `CHARACTER_DEVICE` にする）
- モードは termios の必要な分だけのビット（`TtyMode`）。ビットは個別に効く。`COOKED`（全部オン。既定）と `RAW`（全部オフ）を用意する
- Ctrl+C・Ctrl+\ は TTY がシグナルを返し、`Machine.ttySignalHandler` に渡すところまで（強制終了は #46）
- 画面の大きさは `Tty` が持ち、変わったことは世代の数（`sizeGeneration`）で知る。待てる形の知らせは #63
- 出力がたまった知らせは、待ち手を起こさない `WakeSink.outputPending` で行う（バイトを積むたびに呼ぶ）
- 改行は TTY の出力でもカーネルのメッセージ（`Machine.writeConsole`）でも CR LF にする。`onConsoleOutput` はいつも CR LF を見る

## モードのビット（`TtyMode`）

| ビット | termios | 意味 |
| --- | --- | --- |
| `CANONICAL` | ICANON | 行単位の入力と行編集 |
| `ECHO` | ECHO | 入力をエコーする（canonical の消去の表示を含む） |
| `SIGNALS` | ISIG | Ctrl+C・Ctrl+\ をシグナルにする |
| `CR_TO_NL` | ICRNL | 入力の CR を LF にする |
| `NL_TO_CRNL` | OPOST\|ONLCR | 出力の LF を CR LF にする |

- `VMIN`・`VTIME`・特別な文字の変更・ジョブ制御（Ctrl+Z）は扱わない（Ctrl+Z はただのバイト）
- 知らないビットは受け付けない（`IllegalArgumentException`）
- よく使う組: パスワード入力は `COOKED − ECHO`、cbreak 相当は `COOKED − CANONICAL`、エディタ・シェル（#102）は `RAW`

## 入力の処理

1バイトずつ、次の順で処理する。どのモードでも途中で止めない（捨てた数を `TtyInputResult.dropped` で返す）。

1. `crToNl` なら CR を LF にする
2. `signals` なら Ctrl+C（`INTERRUPT`）・Ctrl+\（`QUIT`）をシグナルにする。編集中の行・読める入力・Ctrl+D の印を捨て、`echo` なら `^C`（`^\`）と改行をエコーする。入力がいっぱいでも必ず処理する
3. canonical なら行編集（下の表）、そうでなければ読める入力の後ろに足す
4. `echo` なら、エコーを出力に積む。普通の文字・LF・タブはそのまま、ほかの制御文字は `^X`（ESC は `^[`、DEL は `^?`）

### canonical の行編集

| 入力 | 振る舞い |
| --- | --- |
| LF | 行を確定する（LF を含む） |
| DEL・BS | 最後の1文字（UTF-8 の1文字）を消す。エコーは表示の幅（全角・`^X` は2セル）の分だけ `\b`・空白・`\b`。タブは行の始まりの桁から数え直し、`\b` だけを出す |
| Ctrl+U | 行を全部消す（1文字ずつ消すのと同じエコー） |
| Ctrl+W | 直前の単語を消す（後ろの空白・タブ、続いてそれ以外） |
| Ctrl+D | 行が空なら「終わり」の印（読むと `Eof` を1回）。続けて押しても印は1つ。行に文字があれば改行なしで確定。エコーしない |
| ほか | 行に入れる |

- 1回の読み取りは行の境目を越えない。行の一部だけ読んだら、残りは次の読み取りで返す
- 行の始まりの桁は、空の行に最初の文字が入ったときの出力の桁。出力の桁は、TTY が出したバイト（プロセスの書き込みとエコー）の CR・LF・BS・タブ・文字の幅で数える（`writeConsole` は数えない）

### 非 canonical

- 入力はそのまま読める入力に足す（DEL・Ctrl+U・Ctrl+W・Ctrl+D もただのバイト）。読むときはたまっている分だけ返す（`VMIN=1`・`VTIME=0` 相当）。`Eof` は返さない

### 入力の上限

- `inputCapacity`（コンソールは 4 KiB。仮の値）は「読める入力＋編集中の行」の合計の上限
- canonical で行に入れる文字は、合計が `inputCapacity − 1` 以下のときだけ入る（確定の LF の1バイトをいつも残す）。1行は 4095 バイトまで（仮の値）。入らなければ捨てて数え（`droppedInputBytes`）、`echo` なら BEL
- 非 canonical は合計が `inputCapacity` まで入る
- 消去・Ctrl+C は場所を使わない（空ける）ので、いつも処理する

### モードの切り替え

- canonical → 非 canonical: 編集中の行を読める入力の後ろに移す（合計で数えているのであふれない）。行の区切りと Ctrl+D の印は捨てる
- 非 canonical → canonical: たまった入力は確定した1つの塊として残す
- 切り替えで読めるようになったら `(id, READABLE)` を知らせる

## 知らせ

- `(id, READABLE)` は「fd 0 に読める入力（または Ctrl+D の印）がある」が偽から真になったときだけ知らせる（`input` の終わりに1回。Ctrl+C で流した後にまた読めるようになったときも）。出力やエコーでは知らせないので、fd 0 を待つプロセスは出力では起きない
- 出力を積んだら（プロセスの書き込み・エコーのたびに）`WakeSink.outputPending(id)` を呼ぶ。`WaitRegistry` は何もせず、`Machine.wakeSink` だけがコンソールの TTY の ID を見て、次の tick で配る印を付ける。空から空でなくなったときだけにしないのは、配っていない出力を持ったまま保存から戻したときに止まらないため
- `drainOutput` で、書けなかった状態から空いたら `(id, WRITABLE)` を知らせる

## 出力

- `write` は空いている分だけ書く（一部だけのことがある）。`nlToCrNl` なら LF を CR LF にし、広げた後のバイト数で空きを数える
- `WRITABLE` は「空きが2バイト以上」（LF が必ず入る）。空き1バイトで LF を書こうとすると `WouldBlock` で、`WRITABLE` も偽なので、待ちが空回りしない。空き1バイトでも LF でなければ書ける
- エコーは待たせられない（接続層のスレッドから来る）ので、出力の上限を 1 KiB（仮の値）まで超えて積み、それも超えたら捨てて数える（`droppedEchoBytes`）
- `Machine.writeConsole`（カーネルのメッセージ用。TTY を通らない）も LF を CR LF にする。#61 の解釈器は LF を「1行下へ」だけとして扱えばよい

## 画面の大きさ

- 既定は 80x25（仮の値）。`Machine.resizeConsole` で変える（画面のデバイスから。つなぐのは #65・#66）。1 未満は `IllegalArgumentException`
- 大きさが変わったときだけ `sizeGeneration` を1つ進める。待ち手は起こさない
- 変更を待つ条件（`WaitCondition`）は足さない。今の待ちは「起きた後に `isReady` で求め直す」レベルの判定なので、出来事を待つには、プロセスごとに「知らせていない変更」を持つ必要がある。それは #63 のイベントキューの役目なので、そちらで `resizeConsole` からプロセスごとのキューに積む

## fd を通した操作（`TtyControl`）

ABI 層（#73）が使う。カーネルロックは自分で取る。fd が開いていなければ `BADF`、TTY でなければ `NOTTY`。fd の権利は問わない。

| 関数 | 中身 |
| --- | --- |
| `isTty(fd)` | TTY を指すか |
| `mode(fd)`・`setMode(fd, mode)` | モード |
| `size(fd)`・`sizeGeneration(fd)` | 画面の大きさと世代 |
| `foreground(fd)`・`setForeground(fd, pid)` | Ctrl+C を送る相手（0 = なし。負は `INVAL`） |

## 保存（#82 への申し送り）

`Tty` は番号・真偽・バイト列だけを持つ（`KernelStateIsolationTest`）。

| 状態 | 型 |
| --- | --- |
| モード | `Int` |
| 画面の大きさ・世代 | `Int` ×2・`Long` |
| 前のプロセス | `Int` |
| 読める入力 | バイト列（先頭・長さ） |
| 行の区切り | `IntArray`（行ごとの長さ。0 は Ctrl+D の印）と先頭・数 |
| 編集中の行 | バイト列 |
| 行の始まりの桁・今の桁、出力の UTF-8 の途中の文字 | `Int` ×4 |
| 配っていない出力 | バイト列 |
| 捨てた入力・エコーの数 | `Long` ×2 |

- バッファは使うときに小さく確保して倍に広げ、空になったら手放す（1,000台の大半はコンソールが空）
- `KernelState` は `consoleTtyId` を持つ（ADR 0058 の `consoleInputId`・`consoleOutputId` は廃止。保存の形はまだないので互換は要らない）
- 復元の後に配っていない出力があっても、次に積んだときに `outputPending` で配られる。すぐ配るなら、復元の側でコンソールに印を付ける

## 仮の値（確定は #251）

入力 4 KiB、出力 16 KiB、1行 4095 バイト、エコーの超過 1 KiB、画面 80x25、タブ幅 8。
