# 0051: VFS の中核（マウントテーブル・パス解決・開いたファイル）

- 状態: 採用
- Issue: #51（task）。前提: ADR 0043（カーネル全体の設計）、0044（MC 層との境界）
- 後続: #52（ホストのディレクトリを背面にしたディスク FS）、#53（`/tmp`）、#54（`/dev`）、#55（読み取り専用イメージ）、#56（抜き差しとマウント）、#58（fd）、#81・#82（保存）
- 番号は Issue 番号にそろえている

## 決めたこと（要約）

- コードは `core.kernel.vfs`。どれも `internal`。`pro.ikili.kibicomputers.api` には何も足さない（他 MOD がファイルシステムを足す口は #65 で決める）
- **シンボリックリンクは扱わない**（v1）。`..` はパスの名前の並びの上で取り除く
- エラーは `FsException(Errno)`。`Errno` は WASI p1 の `errno` と同じ値（0〜76 のすべて）
- マウントの表（`MountTable`）は `KernelState.mounts`（保存の対象）。ファイルシステム（`FileSystem`）は実行時だけのもので、`Machine.vfs`（`Vfs`）がマウントの ID で引く
- 開いたファイル（`OpenFile`）は `KernelObject`。ファイルシステムを参照せず、`(マウントの ID, node)`・位置・権利・開いたときのパスだけを持つ

## パス（`VfsPath`）

- 正規化した絶対パス（名前の並び）。`.`・空の名前は飛ばし、`..` は1つ上へ。根の上は根
- `resolveBeneath(base, text)` は WASI の「ディレクトリの fd から辿る」規則用。絶対パスと、`..` で `base` より上へ出るもの（途中で出て戻ってくるものも）は `NOTCAPABLE`
- 名前は UTF-8 で 255 バイト、パス全体は 4,096 バイトまで（`NAMETOOLONG`）。NUL・`/` は `INVAL`、対になっていないサロゲートは `ILSEQ`、空のパスは `NOENT`
- 末尾の `/` は `hasTrailingSlash` で見て、`Vfs.open` に渡す（ディレクトリでなければ `NOTDIR`）

### シンボリックリンクを扱わない理由

- ホストのディレクトリを背面にしたディスク（#52）で、ホストのリンクを辿るとディレクトリの外へ出られる。扱わなければ、ホストのリンクは見せない・作らないだけでよい
- `..` を名前の並びの上で解けるので、パス解決が FS をまたがず単純（マウントの境目で迷わない）
- WASI p1 の `path_symlink`・`path_readlink` は `NOTSUP` を返せばよい（libc は動く）。要るようになったら `FileType` に足し、パス解決を1段ずつ辿る形に変える

## マウント

- パスは、いちばん長く一致するマウントの位置のファイルシステムに属する。ファイルシステムに渡すのは、その根からのパス
- マウントの位置は、なくてもよい（ディレクトリ以外のものがあれば `NOTDIR`）。1つの位置に重ねてマウントしない（`BUSY`）
- **マウントの位置の祖先は、下の FS になくてもディレクトリとして見える**（根に何もマウントしていないときの `/` も）。中身はマウントの位置へ向かう名前だけで、書けない（`ROFS`）。属性は `device = 0`、`node = 0`。ディスクを `/mnt/<名前>` にマウントするときに、根のディスクに `/mnt` を作らなくてよいように
- ディレクトリの中身には、マウントの位置へ向かう名前を足す（同じ名前があればマウントの側）。並びは名前の順。`.` と `..` は含めない（ABI 層が足す）
- マウントの位置と、その祖先は消せない・名前を変えられない（`BUSY`。普通のファイルとして消そうとしたら `ISDIR`）。マウントをまたぐ名前の変更は `XDEV`
- 外すのは、下に別のマウントがないときだけ（`BUSY`）。マウントの ID は使い回さないので、同じ位置にマウントし直しても、前のマウントで開いたファイルは戻らない
- 読み取り専用は、マウントの指定とファイルシステムの `readOnly` のどちらか。書く操作は `ROFS`
- `MountEntry.source` はマウントしたものの手がかり（`disk:<識別子>`、`tmp` など）。復元のときに、これを見てファイルシステムを作り直し、`Vfs.attach` でつなぐ（#56・#82）

## ファイルシステムの抽象（`FileSystem`）

- パスで引く操作（`stat`・`createFile`・`createDirectory`・`removeFile`・`removeDirectory`・`rename`）と、node で引く操作（`statNode`・`read`・`write`・`setSize`・`readDirectory`・`sync`）
- **開く・閉じるをファイルシステムに伝えない。** 開いたファイルの状態を保存できる値だけにするため（ファイルシステムの参照もホストのチャンネルも持たない）。ホストの資源を開いたままにしたいファイルシステムは、自分の側で持って自分で閉じる（#52）
- node はファイルシステムが割り当て、名前を変えても変わらない番号。消えた node は `STALE`。開いたまま消したファイルを読み続けられるかは、ファイルシステムが決める
- 呼ばれるのは CPU を持つプロセスのスレッドで、カーネルロックの中。ファイルの読み書きのほかに待たない（ロック・条件変数・メインスレッドを待たない）

## 開いたファイル（`OpenFile`）

- POSIX の「オープンファイル記述」。fd（`HandleEntry`）からオブジェクトIDで指す。fd を複製すると位置を共有する
- 持つもの: マウントの ID、node、種類、開いたときの VFS のパス、読む・書く・追記の権利、位置
- 開いたときのパスは、ディレクトリの fd から辿るとき（`path_open`）と、中身にマウントの位置を足すときに使う。開いた後の名前の変更は追わない
- マウントが外れた後の操作は `IO`
- 普通のファイルは、いつでも読める・書ける（`canWait`・`isReady` は true。POSIX の poll と同じ）。デバイスファイルは #54 で別の型にする

### 開くときの規則（`Vfs.open`）

| 場合 | 結果 |
| --- | --- |
| `create` と `directory` を一緒に | `INVAL` |
| `truncate`・`append` を書く権利なしで | `INVAL` |
| ある・`create` と `exclusive` | `EXIST` |
| ディレクトリを書く権利・`truncate` で | `ISDIR` |
| 普通のファイルを `directory`・末尾の `/` で | `NOTDIR` |
| ない・`create` なし | `NOENT` |
| ない・末尾の `/` で `create` | `ISDIR` |
| 読み取り専用・マウントの祖先のディレクトリに書く・作る | `ROFS` |

- 追記の書き込みは、毎回その時の大きさの位置に書く。`pwrite` は追記でも指定の位置に書く
- `seek` は負になれば `INVAL`、桁あふれは `OVERFLOW`。ディレクトリは `ISDIR`（WASI はディレクトリを cookie で読む）
- 権利のない読み書き・大きさの変更は `BADF`。バッファの範囲外は `FAULT`

## 保存（#81・#82 への申し送り）

保存のバイト形式は決めない。メモリ上の持ち方だけ。

- `KernelState.mounts`（`MountTable`: ID・位置・読み取り専用・source・次の ID）と、オブジェクト表の `OpenFile` は、番号・文字列・列挙だけでできている（`KernelStateIsolationTest` で確かめる）
- ファイルシステムの中身（`/tmp` のデータ、ディスクの node の割り当て）は、それぞれのファイルシステムが保存する（#52・#53）。**node は保存と復元をまたいで同じファイルを指すこと**（開いたファイルが node で指すため）
