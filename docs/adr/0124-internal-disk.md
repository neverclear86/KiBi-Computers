# 0124: 内蔵ディスク（HDD）のアイテム、識別子とワールドの中の置き場所

- 状態: 採用
- Issue: #124（task）。前提: ADR 0049（起動の流れ）、0052（ホストのディレクトリのディスク FS）、#121（ケース）
- 後続: #56（起動ディスク以外のマウントと抜き差し）、#82（開いたファイルの保存と復元）、#224（1.20.1 への移植）、#251（容量の確定値）
- 識別子の形・アイテムの持ち方・消えたときの扱いは、オーナーの回答（Issue #124、論点1: A、論点2: 推奨、論点3: X）による

## 決めたこと（要約）

- ディスクのアイテムは `storage_1`〜`storage_4`（1.21.1）。検証用の `creative_storage` も同じディスクのアイテム（`DiskItem`）にする
- 識別子は **UUID の小文字の文字列**（ハイフン付き 36 文字。`DiskStore.newId`）。数え上げの状態を持たないので、割り当てで I/O せず、
  クラッシュ・ロールバックで重ならない
- 識別子は **電源を入れたとき（遅延）** に、ディスクのスロットの識別子のないアイテムにだけ付ける。クラフトしたときには付けない
  （重ねられない・クリエイティブタブのアイテムが全部同じ識別子になる、を避ける）
- アイテムのデータは、1.21.1 はデータコンポーネント `kibicomputers:disk_id`（文字列。クライアントにも同期して説明欄に出す）。
  1.20.1（#224 で移植）は NBT の `DiskId`（文字列）
- 中身は `<world>/kibicomputers/disks/<id>/`（ディメンションによらずワールドの直下に1つ）。中は普通のファイルとディレクトリだけ（ADR 0052）。
  管理用のファイルは置かない。ディレクトリはマシンが初めて開くときにカーネルが作る（`DiskFileSystem.open`）
- **アイテムが消えても、フォルダは消さない**（CC・OC と同じ）。溶岩・奈落・時間切れ・`/clear`・ほかの MOD のゴミ箱などで消えても残す。
  片付けはサーバーの管理者の手作業（自動の片付けが要れば `scope: future` の別 Issue）
- 形の正しくない識別子（`/give`・`/data` で書いたもの）は「識別子なし」として扱い、起動の候補にも入れず、**上書きもしない**。
  フォルダの外を指させないため、識別子の検査（`DiskStore.isValidId`。UUID の正規の小文字の形だけ）とディレクトリの解決は `core` の `DiskStore` が行う

## 容量

ティアで決まる（`PartTier.diskBytes`・`diskEntries`）。仮の値で、確定は #251。

| アイテム | 容量 | 項目の数 |
| --- | --- | --- |
| `storage_1` | 1 MiB | 1,024 |
| `storage_2` | 2 MiB | 2,048 |
| `storage_3` | 4 MiB | 4,096 |
| `storage_4` | 8 MiB | 8,192 |
| `creative_storage` | 64 MiB | 65,536 |

- 容量は `DiskResolver.resolve` の戻り値 `ResolvedDisk`（ディレクトリ・バイト・項目の数）でカーネルに渡し、`BootVolumeOpener.forDisks` が
  `DiskQuota` にする。`MachineLimits.DISK_CAPACITY_BYTES` は `DiskQuota()` の既定値としてだけ残る
- `PartTier` に正式なティア `TIER_1`〜`TIER_4` を足した（`CREATIVE` はいつも最後）。今アイテムとして登録するのはディスクだけ。
  CPU・RAM の正式な値は #122・#123 で決めるので、正式なティアの CPU・RAM には今は `MachineConfig.DEFAULT` と同じ値を入れる

## 電源を入れたとき

メインスレッドで、ケースのブロックエンティティが次を行う（`CaseBlockEntity.pressPowerButton`）。

1. ディスクのスロットの、識別子のないディスクに `newId()` を付ける（I/O なし）
2. 挿さっているディスクの「識別子 → ティア」から、変わらない写し（`DiskStore.snapshot`）を作り、`MachineEnvironment.disks` に渡す。
   プロセスのスレッド・起動のワーカーは、ワールドにもアイテムにも触らない。写しはその起動の間変わらない
3. 起動の候補は「ディスクのスロットの順のディスク → `image:os`」（ADR 0049 の「init がある最初のディスク」。#461 で `image:testboot` から替えた。ADR 0461）

## 動いている間にディスクを抜いたとき

- 判断は `core` の `ComputerCase`。接続層は、挿さっているディスクの識別子を `InstalledParts.diskIdAt` で答えるだけ
- #56 で変えた（ADR 0056）: `bootDiskIds` は消し、接続層は部品が変わるたびに（動いている間だけ）今のディスクの写しを作り直して
  `partsChanged(parts, disks)` に渡す。マシン（`Machine.disksChanged`）は、`/`・`/home` のディスク（と起動・復元の途中で頼るディスク）が抜けたときだけ
  「止めるべき」と答え、`partsChanged` が `ComputerError.MISSING_PARTS` にする。`missingParts` は不足の種類に `STORAGE` を足して `PartKind` の順に並べる
  （ほかのディスクが残っていても `[STORAGE]`）
- それ以外のディスクは、抜いても止めない（マウントを外して `disk-removed`）。足したディスクは `/mnt` に自動でマウントする（`disk-inserted`）
- `InstalledParts.diskIdAt` は既定の実装（`null`）を持つので、`fun interface` のままで、ディスクを答えない実装は今までどおり動く

## 同じ識別子のアイテムが2つあるとき

クリエイティブでの複製などで同じ識別子のアイテムが2つでき、両方の台が動いたときは、ADR 0052 のリースで後から開いた方が勝ち、
古い方の操作は `IO` になる。防がない。
