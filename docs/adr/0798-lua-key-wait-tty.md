# 0798: Lua のキー待ちの間の端末のモード

- 状態: 採用
- Issue: #798（task）、#838（読み捨てが待つ道を直した）。前提: ADR 0060（TTY）、0427（kibi:io/tty）、0724（Lua の term・keys）、0102（sh の行編集）、0094（Lua 向けの KiBi API）
- 方針: ABI・カーネル・保存形式・公開 API は変えない。変えたのは `lua.wasm`（C）と man だけ（#838 も `lua.wasm` だけ）

## 問題

`os.pullEvent("key")` でキーを待つ CC: Tweaked 風のプログラムでは、コンソールの TTY が既定（cooked: canonical＋echo）のままなので、

- 待つ間に打った文字（英字・Enter・Esc・矢印など）を TTY がエコーし、`term` で描いた絵が崩れる
- 打った文字は TTY の入力に溜まり、Lua が終わると `sh` がそれを先打ちとして読む（ADR 0102）

## 決めたこと（要約）

- メインスレッドの `os.pullEvent`・`pullEventRaw`（`parallel` のメインの待ちも同じ `pull()` を通る）が、filter なし・`"key"`・`"key_up"` で待ち始めるとき、標準入力（fd 0）が端末で、モードがちょうど cooked（`0x1f`）なら、モードを `signals | nl-to-crnl`（`0x14`）にする
  - echo と canonical を切る。signals は残す（Ctrl+C で止められる）。nl-to-crnl は残す（`print`・`term` の LF が CR LF のまま）
  - canonical も切るのは、`sh` が「子が canonical を外したまま終わったら cooked に戻す」（`os/bin/sh/edit.zig` の `readLine`）ため。echo だけ切ると、殺されたときに `sh` がそのモードを引き継ぎ、エコーが消えたままになる
- 切っている間は、`pull()` が `poll_oneoff` で待つ直前に毎回、標準入力の今読める分を待たずに読み捨てる
- 一度切ったら、**標準入力を読む前**か**終わるとき**まで戻さない
  - `io.read`・`io.lines`・`file:read` の入り口（liolib.c の `g_read` の先頭の `clearerr(f)`）を、`kibi_wasi.h` の `#define clearerr(f) kibi_lua_before_read(f)` で包む。`f == stdin` なら戻してから本物の `clearerr` を呼ぶ
  - 引数なしの `dofile()`・`loadfile()` は、lauxlib.c の `luaL_loadfilex` が標準入力を `getc`・`fread` で直接読み、`g_read` を通らない。最初の読み取りが `getc`（`skipBOM`）なので、`#define getc(f) kibi_lua_getc(f)` でも包み、`f == stdin` なら戻してから本物の `getc` を呼ぶ（`g_read` の後の `getc` も通るが、戻した後は状態を見るだけ）
  - REPL（lua.c の `lua_readline`）は `kibi_wasi.h` で定義し直し、`fgets` の前に戻す（`lua_readline` を定義したので `lua_initreadline`・`lua_saveline`・`lua_freeline` も定義する。中身は Lua の既定と同じ）
  - 終わるとき（`main` から戻る、`os.exit`、捕まえられなかったエラー）は `atexit`。登録は初めて切るときに1回だけ。登録できなければ切らない
- 戻す手順: 切ったまま読み捨てる → 今のモードがまだ `0x14` なら元のモードに戻す（ほかのプロセスが変えたものは上書きしない）→ canonical に戻したことで残った「確定した1つの塊」があれば、もう一度読み捨てる
- 状態（未確認・端末でない・切っていない・切っている・cooked でなかったので切らなかった）と元のモードは C の静的変数（`kibi_lua_tty.c`）に持つ。`is-tty(0)` は初めの1回だけ呼んで覚える。切った後と、切っていないときの読み取りでは import を呼ばない
  - 見たときのモードが cooked でなかったら、そう覚えて、次に標準入力を読むか終わるまでは `get-mode` を呼び直さない（filter なしの待ちで、イベントを1つ受けるたびに import を呼ばないように）。読んだ後は、プログラムやほかのプロセスがモードを変えているかもしれないので、次の待ちでもう一度見る
- **新しい import（tcflush 相当）は足さない。** 使う import は、もうある `kibi:io/tty@0.1.0` の `is-tty`・`get-mode`・`set-mode` と、WASI p1 の `poll_oneoff`・`fd_read`・`fd_fdstat_get`・`fd_fdstat_set_flags` だけ（後の2つは #838 で足した。どれも実装済みの p1 の関数で、ABI は変わらない）。捨てる量は TTY の入力（4 KiB）と待ちの列（#609。8 KiB）までなので、待たない読み取りのループで消せる

## 読み捨て

- まず `poll_oneoff` で、標準入力の `FD_READ` と相対 0 の単調時計を1回で購読する（`sh` の `inputReadyNow` と同じ形。#769）。時計がすぐ鳴るので待機点にならず、カーネルのタイマーも作らない。`FD_READ` が（エラーなしで）返らなければ、それだけで戻る（待つ前のほとんどはこの道）
- 読めると返ったときだけ、`fd_fdstat_get(0)` で今の fdflags を取り、`NONBLOCK` を足して `fd_fdstat_set_flags` で立て、`fd_read` を `AGAIN`・0・エラー・回数の上限のどれかまで繰り返し、取った fdflags をそのまま書き戻す（#838）
  - 見てから読むまでの間に、同じ TTY を読むほかのプロセス（`/dev/tty` を開いたもの、Lua と同時に動く子）が読み切っても、`fd_read` は `AGAIN` で戻り、次の入力を待たない。前は、読めることを見てから別の呼び出しで待つ `fd_read` をしていたので、そこで次の入力まで止まった（キーの待ちならタイマーも受けずに止まり、終わるときなら終わらない）
  - `NONBLOCK` は、プロセスごとの fd 表の項目（`HandleEntry.flags`）に持つ。`/dev/tty` の fd も `Tty` を直接指し、`fd_fdstat_set_flags` は共有のオブジェクトの側を変えない（変えるのは `OpenFile` の `APPEND` だけ）ので、同じ TTY を指すほかのプロセスの fd には効かない
  - 元から `NONBLOCK` なら（親が立てた fd を受け継いだなど）、立てる・戻すを飛ばす。書くのは「元の値に `NONBLOCK` を足したもの」と「元の値」だけで、`APPEND` などのほかのビットは元どおりに残す
  - `fd_fdstat_get` か、立てる側の `fd_fdstat_set_flags` が失敗したら、読まずに戻る（待つ `fd_read` に進まない）
  - 立てている間は `drain` の中だけで、C だけで Lua を呼ばないので、`longjmp` では抜けない。抜けるのはプロセスが死ぬとき（Ctrl+C・kill）だけで、そのときは fd 表の項目もプロセスと一緒に消えるので、`sh` などには残らない。そのため、前に「戻し忘れると `io.read` が `EAGAIN` になる」として使わなかった `NONBLOCK` を、この範囲に限って使う。切っている間（`STATE_SWITCHED`）ずっと立てる形は取らない（その間に起動した子が `NONBLOCK` の stdin を受け継ぐ。`kibi_lua_before_read` を通らない読み方が `EAGAIN` になる）
  - 最後の `fd_read` は、捨てる量があるときはいつも、空の TTY を読んで `AGAIN` で止まる。`NONBLOCK` が効いていなければ、そこで必ず待つので、今の読み捨てのテストが付け忘れを捕まえる
  - 燃料切れで読み捨ての途中が待機点になって保存されても、fd 表の項目（`flags` は保存している）と線形メモリはそろって戻り、続きから元の fdflags に戻す。保存形式は変えていない
- 待つ `fd_read(0)` は使わない（読めないと待機点で止まる）
- 読む領域はスタックの 256 バイト（Lua の確保と `malloc` を通さない。#729 の「包みを通らない書き込み」と、静的な領域で書き込む区画が増えるのを避ける）。回数の上限は 96 回（12 KiB 分と少し）。`fd_read` が 0（EOF・Ctrl+D の印）を返したらやめる。キーを押し続けても終わる

## 選ばなかった形

- **起きたらすぐ戻す（Issue の候補そのまま）**: クライアントは英字のキーで押下（`KeyDown`）を先に、文字（`Text`）を後で送る（`KeyboardInputScreen`。文字は次のキーか tick の flush で送る）。サーバーでも `KeyboardDevice.input` はイベントと TTY のバイトを別々に入れる。`key` で起きた直後に戻すと、後から来た文字が cooked の TTY に入ってエコーされ、溜まる。待ちのたびに切ったままにしておけば、次の待ちの前の読み捨てで消える
- **`pull()` の出口でだけ戻す**: `collect`・FIFO・メモリ不足で `pull()` の途中に Lua のエラー（longjmp）が出ると、`pcall` や REPL に受けられたときにモードが切れたまま残る。読む前と終わるときに戻す形なら、どこで抜けても次に読む前に戻る
- **戻してから読み捨てる**: 待ちの列の残りが canonical の編集中の行に入り、読み捨てで取れず、次の `io.read` の行に混ざる
- **Lua で `io.read` を上書きする**: 標準の `io` を上書きしない方針（ADR 0724。#237 の範囲）。C のマクロで前に処理を1つ足すだけにした
- **カーネルで、前のプロセスが終わったらモードを戻す**: nano などのほかのプログラムの振る舞いも変わる。対話型の `sh` が戻すので足りる

## filter の範囲

- 切るのは filter なし・`"key"`・`"key_up"` のときだけ。`"timer"` などだけを待つプログラム（`sleep` の代わりなど）では、打ったものを `sh` への先打ちとして残す（ADR 0102 の考え方）
- 一度切ると、その後に `"timer"` などを待っても、読む前か終わるまでは切ったまま（待つ前に読み捨てる）
- メインスレッドの `os.sleep` は時計だけを待ち、`pull()` を通らないので、切らない。切った後の `os.sleep` の間に打ったものは溜まり（エコーはしない）、次の待ちか、戻すときに捨てる
- コルーチンの中の `os.pullEvent` は yield するだけで、待つのは resume する側（`parallel` ならメインの `pull()`。filter なしなので切る）

## 切らないとき

- 標準入力が端末でない（パイプ、`sh` の後ろのジョブは stdin を閉じて起動する）: `is-tty(0)` が偽なので何もしない。fd 1 のモードは変えられるが、fd 1 は書く権利しかなく読み捨てられないので、触らない
- 元のモードが cooked でない（`0x1f` 以外。ほかのプログラムが変えたもの）: 触らない。次に標準入力を読むまでは見直さない（上の「状態」）。その間にモードが cooked に戻っても、読むまでは切らない

## 殺されたとき

- シグナルで殺されると `atexit` は走らない（ADR 0046。`term` の後始末と同じ前提）
- Ctrl+C: TTY は編集中の行・読める入力・Ctrl+D の印を捨てる（ADR 0060）。対話型の `sh` は canonical が切れているのを見て cooked に戻す。echo を切っているので、`^C` はエコーされない
- `kill`（ほかのプロセスから）: 読める入力が残り、`sh` が先打ちとして読む
- 対話でない `sh`（スクリプト）は戻さないので、続く子は切れたままのモードを見る
- これらは man（keys(3)）に書いた

## 残ること

- プログラムが読み始めた（戻した）直後や、終わった直後に届いた文字は、cooked の TTY に入ってエコーされ、残る。押下と文字が別々に届くため（上の「選ばなかった形」）。キーを受けてすぐ `io.read` するか終わるプログラムでは、受けたキーの文字が、Lua が戻した後に届くことがある。実際には、文字は押下と同じパケットか直後に届き、Lua が起きて戻すまでの間に入ることが多いので、終わるときの読み捨てで消えることが多い。必ずではない（テストでは文字を押下より先に送って確かめている）

## 保存と復元

- TTY のモードはカーネルの保存（`Tty` の写し）に入り、Lua の静的変数は線形メモリにあるので、同じ待機点で保存され、そろって戻る。保存形式は変えていない
- `lua.wasm` が変わるので ModuleHash が変わり、古い Lua のプロセスは `MODULE_MISMATCH` で冷えた起動になる（ADR 0088。v0.1.0 の前なので互換は要らない）

## 規模

- tick ごとの処理・スレッド・タイマーは足さない。切り替えは、標準入力を読んでから最初の、キーの待ち始めの1回（import 2〜3 回。cooked でなくて切らなかったときは `get-mode` の1回）、読み捨ては待つ直前の `poll_oneoff` 1回。読めるものがあったときだけ、`fd_fdstat_get` 1回と `fd_fdstat_set_flags` 2回、`fd_read` を `AGAIN` まで（#838）。待っているだけの台の負荷は変わらない

## テスト

- `LuaTermFsKeysTest`
  - `pullEvent("key")` の待ちで、Lua が `key` を受けた後に文字（`Text`）を送り、Enter・Esc・上の矢印を送っても、エコーされない。終わった後、モードが cooked で、TTY の入力（読める入力・編集中の行・待ちの列）が空
  - 待ちの後の `io.read` は、エコーと行の編集（Backspace）が戻り、待つ間に打ったものが行に混ざらない
  - `error()`・`os.exit()` で終わっても cooked に戻り、入力が空
  - `pullEvent("timer")` だけを待つときはモードを変えず、打ったものが残る
  - 標準入力が閉じている（端末でない）とき、元のモードが cooked でないときは、モードを変えず、打ったものを捨てない
  - `parallel` のコルーチンが `pullEvent("key")` で待つとき（メインの `pull()` は filter なし）も切れ、打ったものがエコーされず、終わると cooked に戻る
  - `pcall` で `pullEvent("key")` のエラー（`Terminated`）を受けた後も切ったままで、その後に `"timer"` だけを待ったり `os.sleep` したりしても、次の `io.read` の前に戻る（待つ間に打ったものは混ざらない）。`pull()` の出口で戻す形にしなかった理由（上の「選ばなかった形」）を確かめる
  - 待った後の引数なしの `dofile()` は、モードが戻ってから標準入力を読む（エコーされ、待つ間に打ったものは混ざらない）
  - 同じ TTY を1バイトずつ読むほかのプロセスと一緒に動かし、入力を送るたびに次を送らずにタイマーで起きるのを待っても止まらず、終わるときも止まらない。ほかのプロセスの fd 0 は一度も `NONBLOCK` にならず、待っている間の Lua の fd 0 も元に戻っている（#838）。割り込みの窓が狭く順を決められないので、直す前のコードでも手元では止まらなかった。`NONBLOCK` の付け忘れ・戻し忘れは、上の読み捨てのテスト（最後の `fd_read` が待つ）と `io.read` のテスト（`EAGAIN`）が捕まえる
  - fd 0 が元から `NONBLOCK` なら、読み捨ての後も `NONBLOCK` のまま（#838）
  - 対話型の `sh` から起動した `lua` を、キー待ちの間に Ctrl+C・kill で止めても、次のコマンドが動く間は端末が cooked に戻っている
- `LuaReplTest`: REPL で filter なしで待つ間に打ったものはエコーされず捨てられ、次の行はエコーされて評価され、履歴（上の矢印）も使える
- `LuaWasmTest`・PoC のスタブに `get-mode`・`set-mode` を足した
