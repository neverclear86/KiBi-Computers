# 0101: 標準 OS のシェル `/bin/sh`（構文と実行）

- 状態: 採用
- Issue: #101（task）。前提: ADR 0098（標準 OS のビルドと `kibi` ライブラリ）、0100（`/sbin/init`）、0074（`kibi:process`）、0075（パイプ・dup）、0427（`kibi:io/tty`）
- 後続: #102（行編集・補完・履歴。ADR 0102）、#103（基本コマンド）
- 番号は Issue 番号にそろえている

## 決めたこと（要約）

- ソースは `os/bin/sh.zig` と `os/bin/sh/`（`parse`・`expand`・`exec`・`builtins`・`vars`・`mem`・`state`・`util`）。同梱イメージ `os` の `/bin/sh` になる
  - 大きなプログラムを分けて置けるよう、`core/build.gradle.kts` の `osPrograms` は `os/<dir>/<名前>/` の `.zig` も入力に足す（中のファイルはコマンドにならない）
  - スタックは 256 KiB（ほかは 64 KiB）。構文の入れ子・関数の呼び出しで再帰するため。触るまで RAM に数えない
- POSIX sh の文法のうち、よく使う部分を読む。fork がないので、サブシェルは同じ `sh` を子として起こす
- 新しいシステムコール・保存形式・公開 API は足していない。`kibi` ライブラリの上限を 2 つ上げた（引数・環境変数の領域 16 KiB → 64 KiB、`spawn` の引数 64 → 256）

## 起こし方

```
sh [-eufxvC] [-c コマンド [名前 [引数...]]]
sh [-eufxvC] スクリプト [引数...]
sh [-eufxvC] [-s] [-i] [引数...]       # 標準入力から読む
```

- 標準入力と標準エラー出力が TTY なら会話的（`-i` でも）。会話的なシェルは `PS1`（既定 `$ `）・`PS2`（既定 `> `）を標準エラー出力に書き、誤りで終わらず、Ctrl+C・Ctrl+\ を無視する（前景の子に届く）。前景がなければ（init を通さずに起こされた）自分を前景にする
- 入力が尽きたら（Ctrl+D）終わる。会話的なら改行を 1 つ書く
- 環境変数はすべて export された変数になる。`PWD` は起動時の cwd にそろえる

## 構文

- 語・引用（`'...'`・`"..."`・`\`）・コメント・行の継続（`\` 改行）
- 単純なコマンド（代入・語・リダイレクト）、パイプライン（`!`）、`&&`・`||`、`;`・`&`・改行
- `{ ...; }`・`( ... )`・`if`/`elif`/`else`・`while`・`until`・`for`（`in` なしは `"$@"`）・`case`（`|`・`(pat)`）・関数 `name() 複合コマンド`
- リダイレクト: `<`・`>`・`>>`・`>|`・`<>`・`<&`・`>&`（`-` で閉じる）・`<<`・`<<-`。fd は 0〜9（3 は根の preopen なので使えない）
- 入力が途中で切れているとき（引用・`if` などが閉じていない）、構文の読み手は `Incomplete` を返し、続きを読んで頭から読み直す（途中の状態を持たない）。会話的なら `PS2` を出す
- 語は元の文字列のまま持ち、展開が読み直す。`$(` の終わりは中をコマンドとして読んで見つける（`case` の `)` を数え違えない）

## 展開

チルダ（`~`・`~/...`。`HOME`）、パラメーター（`$name`・`${name}`・`$1`〜・`${10}`・`$@`・`$*`・`$#`・`$?`・`$$`・`$!`・`$-`・`$0`、
`${x:-w}`・`${x-w}`・`:=`・`:?`・`:+`・`${#x}`・`${x#p}`・`##`・`%`・`%%`）、コマンド置換（`$(...)`・`` `...` ``）、
算術（`$((...))`。64 ビット整数、C の演算子と優先順位、`=`・`+=` などの代入、10・16・8 進。0 での割り算は誤り、`INT64_MIN / -1` は `INT64_MIN`・`%` は 0。`&&`・`||`・`?:` の評価しない側では誤りにしない）、IFS でのフィールド分割、パス名（`*`・`?`・`[...]`。名前の順。合わなければそのまま）、引用の除去。

- 引用された文字は、展開の途中の文字列で印（0x01）を前に付け、パターンとして効かせない。最後に外す
- `"$@"` は引数ごとのフィールド。引数がなければフィールドなし
- `case` の語・代入の値・リダイレクトの先は分割・パス名の展開をしない

## 実行

| 種類 | どこで動かすか |
| --- | --- |
| 組み込み・関数・複合コマンド | シェルの中 |
| 外のプログラム | 子（`PATH` で探す。既定 `/bin:/sbin`） |
| `( ... )` | サブシェル（子の `sh`）。子として起こすもの（パイプラインの段・`&`・`$(...)`）で、中身が外のプログラム 1 つなら、サブシェルを挟まずそのまま子にする（括弧のリダイレクトは外から順に重ねる。語に `$(...)`・`` ` ``・`${...=...}` など親の状態を変えうる展開があればサブシェルで） |
| パイプラインの各段 | 外のプログラムはそのまま子、ほかはサブシェル。ただし「標準入力を読まず状態を変えない組み込み」（`echo`・`printf`・`pwd`・`test`・`[`・`true`・`false`・`:`）は、ほかの段を起こした後にシェルの中で動かす。途中の段の出力はシェルの中に集めて、子を待つ間に書く |
| `cmd &` | 子（標準入力は閉じる）。`$!`・`wait`。ヒアドキュメントは待たずに渡す（パイプに入りきらなければ書くだけの子のシェルに任せる）ので、外のプログラムはそのまま子で、`$!` は本来のコマンド |
| `$(...)` | 上と同じ組み込み 1 つならシェルの中で出力を集める。外のプログラム 1 つならそのまま子、ほかはサブシェル。出力はパイプで読む（子を待つ間に、ヒアドキュメントを書きながら読む） |

- サブシェル: `sh --kibi-sub=<$?>,<$$>,<$!> --kibi-prelude=<頭> -c <中身> <$0> <引数...>` で起こす。頭は export していない変数の代入・`export`（値のないもの）・`readonly`・関数の定義・`set -<オプション>`。
  子は頭を動かしてから `$?` を入れる。`$$` は親のシェルの pid。中身にヒアドキュメントがあれば、その中身を後ろに足して渡す
- WASM でないファイル（spawn が `NOEXEC`）: 頭が `#!` ならそのプログラム（引数 1 つまで）で、なければこのシェルで、スクリプトとして動かす
- 見つからない: `sh: <名前>: not found`・127。起こせない: 126。知らせはそのコマンドの `2>` の先に書く
- 終了コード: シグナルで止まったら 128 + 番号（Ctrl+C は 130、Ctrl+\ は 131、terminate は 143、kill は 137）。落ちた（トラップ）は 139
- 前景: 標準入力が TTY で、シェルが前景なら、待つ間は子として起こした最後の段を前景にする（最後の段がシェルの中で動いても、Ctrl+C が子に届く）。前景にした段が先に終わったら、まだ動いている最後の段に前景を移す。どれかの段が Ctrl+C・Ctrl+\ で止まったら残りの段も止める（子を待つ間だけでなく、途中の段の大きい出力の空きを待つ間も）。会話的でないシェルは、そのとき自分も Ctrl+C で止まる（スクリプトごと止まる）
- シェルの中のリダイレクトは、前の fd を 100 以上に写して覚え、終わったら戻す。後ろのジョブのハンドルは 200 以上に移す（ユーザーの `4>` などとぶつからない）。`exec 4>file` で開いた 4〜9 は子に引き継ぐ
- ヒアドキュメント: 子（外のプログラム・サブシェル）には、子を起こした後、子を待つ間に、パイプの空き（`poll_oneoff` の `FD_WRITE` の `nbytes`）の分ずつ書く。シェルは書くことで止まらないので、パイプラインの途中や `$(...)` でも、大きさの制限はない（中身は残る領域に写して持つ。写せなければ、その場で全部書く）。後ろで動かすもの（`cmd <<EOF &`）は待たないので、サブシェルに書かせる。シェルの中で動かすもの（組み込み・複合コマンド）には、パイプの大きさ（4 KiB）までしか渡せない
- 後ろの複合コマンド（`(a; b) &`・`{ a; b; } &` など）の `$!` はサブシェルの pid。`kill $!` で止まるのはサブシェルだけで、中で動いているコマンドは親なしになって残る（POSIX の sh と同じ。カーネルは止めたプロセスの子を止めない。ADR 0046）。
  まとめて止める（`kill %1` のような）のは、ジョブ制御とプロセスグループを入れるときに考える（#471）
- `set -e` は、条件（`if`・`while` の条件、`&&`・`||` の左、`!`）の外の単純なコマンド・パイプライン・サブシェルが失敗したら終わる

## 組み込み

特別な組み込み（代入が残り、関数より先）: `:` `.` `eval` `exec` `exit` `export` `readonly` `return` `set` `shift` `unset` `break` `continue` `local`。
ほか: `history`（#102。ADR 0102） `true` `false` `echo`（`-n`）`printf`（`%s %b %c %d %i %u %o %x %X %%`、フラグ・幅・精度、書式の繰り返し）`cd`（`-`・`HOME`・`PWD`・`OLDPWD`）`pwd` `read`（`-r`）`test`/`[` `wait` `command`（`-v`・`-V`）`type` `source`。

- `exec cmd` は置き換えられないので、動かしてその終了コードで終わる。`exec` だけならリダイレクトをシェルに残す
- `test -r/-w/-x` は、持ち主・権限がまだない（#110）ので、あれば真
- `local` は関数の中だけ。値を書かなければ今の値のまま
- `.` で読めるファイルは、残る領域の半分（256 KiB）まで。超えたら `file too large`、残る領域が足りなければ `not enough memory to read the file`

## 領域

Zig の標準ライブラリのアロケーターは使わない（ADR 0098）。静的な領域に置く（触るまで RAM に数えない）:

- 積み上げの領域 2 つ（構文木・argv など 512 KiB、展開の途中の文字列 512 KiB）。1 つのコマンドの終わりで戻す
- 残る領域（512 KiB）: 変数・関数の本体の文字列・位置パラメーター。先頭から探す空きリスト
- 入力の領域 64 KiB（1 つの完結したコマンドの大きさの上限）。変数 1,024、関数 256、後ろのジョブ 32、パイプラインの段 32、関数の呼び出しの深さ 100（仮の値）

## 今の制限（必要になったら足す）

- `trap`・`alias`・`getopts`・`umask`・`jobs`/`fg`/`bg`（ジョブ制御）はない
- 標準入力がファイル・パイプのとき、まとめて読むので、後に動かすコマンドが同じ標準入力の続きを読めないことがある
- `$(...)` の中のヒアドキュメント、`${x:=w}` などの副作用がサブシェルの側で起きるときの細部は POSIX と違うことがある

## 確かめ方

`core` の `ShellTest`: メモリの FS に、イメージの `/bin/sh`・`echo`・`true`・`false` と `os/test/shprobe.zig`（`cat`・`args`・`envget`・`exitwith`・`errout`）を置いて動かす。
引数と引用、パイプとリダイレクト・ヒアドキュメント、変数・環境変数・`$?`・パラメーターの展開・算術、`if`・`for`・`while`・`until`・`case`・関数・`local`・`break`/`continue`・`return`、
コマンド置換・サブシェル（状態が漏れない・`$?`・`$$`・関数と export していない変数が見える）、スクリプト（`sh file`・`#!`・`#!` なし・`.`・`set -e`）、誤り、パス名の展開と後ろのジョブ、
TTY での会話（プロンプト・続きの行）、Ctrl+C が前景の子だけを止めること。
