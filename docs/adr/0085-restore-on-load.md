# 0085: ワールド・チャンク読み込み時の復元

- 状態: 採用
- Issue: #85（task）。前提: ADR 0081（待機点保存のライフサイクル）、ADR 0082（節の中身）、ADR 0083（差分）、ADR 0084（書き込みのスレッド）、ADR 0049（起動）
- 後続: #86（殺したプロセスへの通知）、#87（止まっていた時間のイベント・画面の再描画）、#88（MOD のバージョン違い）、#132（アンロード中の休止）、#251（仮の値の確定）

## 決めたこと（要約）

- **電源の状態をケースの NBT に書く**（`PoweredOn`。回答 A）。電源の状態の判断は `core` の `ComputerCase`（`poweredOn`）に置き、接続層は読み書きするだけ。タグのない古いセーブデータは電源が切れている
- 電源が入っていたケースは、サーバーでの読み込み（`onLoad`）・チャンクが FULL に戻ったときに**復元の順番待ち**（`RestoreQueue`）に入り、tick ごとに仮 16 台まで始める。その ID の書き込みが終わっていない台は後回しにし、仮 2 秒を過ぎたら冷えた起動にする（ADR 0084 の規則 9。メインスレッドは待たない）
- 復元は **前段（カーネルを変えない）→ 後段（ロックの中で表に入れる）** の2段。前段は起動用のスレッド（`bootExecutor`）で動き、読み・復号・モジュールの読み込み・マウントの開き直し・インスタンスの作り直しをする。どこかで失敗したら作ったものをすべて返し、表は空のまま冷えた起動にする
- 前段は**モジュールの読み込みを、起動用のスレッドを持たずに待つ**（#577）。読み込みが終わったら続きを起動用のスレッドに積み直し、混んでいたらタイマーで少し後に積み直す。待つ間に持つのは、圧縮のままの写しと読み込んだモジュールだけで、前段が終われば（戻した・冷えた起動にした・取り消した）どれも持たない（#587）
- 戻したマシンは、**終わりの知らせ（`RestoreListener`）が返るまで `quiesce` で止めたまま**にする。受け手（`ComputerCase`）はその中でデバイスをつなぎ、まだ実行していないデバイスの呼び出しを回し直す。知らせが返ってから step を割り当てる
- 保存データの読み手は `SnapshotDecoder` 1つにし、`SnapshotInspection.inspect` と復元で共有する

## 電源の状態（`PoweredOn`）の変わり方

| 出来事 | `poweredOn` |
| --- | --- |
| 電源を入れてマシンを作った（`turnOn`）・復元でマシンを作った（`startRestore`） | 真 |
| 電源を切った（`turnOff`）・起動に要る部品・`/`・`/home` のディスクが抜けて止めた（ADR 0056）（`partsChanged`）・電力が尽きた（`powerLost`） | 偽 |
| マシンが CRASHED になった・ゲストが止めた（再起動の途中でない STOPPED。`poweroff`・init の終了）・起動に失敗した（`onBootFailed`） | 偽 |
| 部品が足りない・電力がないので作れなかった | 偽 |
| チャンクのアンロード・FULL でなくなった・`setRemoved`・マシンを作れなかった（サーバーの停止の途中など） | 変えない |

変わったら `setChanged` する（チャンクの NBT に載る）。

追記（#640）: ゲストが止めたとき（再起動の途中でも起動の途中でもない STOPPED）は、`poweredOn` を偽にするだけでなく、状態の表示も OFF にしてマシンを外す（`turnOff` と同じ後始末。接続層は結線も外す）。#85 のときは表示を変えなかったが、その理由はこの ADR にも ADR 0049 にもなく、ゲストが自分から止められる（#306）ようになって、GUI に「動作中」と出たままになり、電源ボタンの1回目が空振りに見えていた。外したマシンは自動保存・アンロード・停止の取り出しの対象から外れる。reboot・起動の途中の STOPPED は今までどおり（表示も `poweredOn` も変えない）。`PoweredOn` の意味と NBT は変えない。

追記（#641）: 起動に失敗したとき（`onBootFailed`。電源を入れた後・reboot の後・復元できずに冷えた起動にした後のどれも）は、`poweredOn` を偽にするだけでなく、マシンを外して状態の表示をエラー（`ComputerError.BOOT_FAILED`）にする（CRASHED と同じ後始末。接続層は結線も外す）。起動の失敗では状態の通知が出ない（ADR 0049）ので、ケースは `onBootFailed` で拾う。OFF でなくエラーにするのは、ゲストが自分で止めた正常な停止（#640）と区別し、画面をつないでいない台でも GUI で失敗が分かるようにするため。理由の詳細（`BootFailure`）はメニューに同期せず、画面のコンソールの1行に任せる。知らせが届くまでに同じマシンがもう起動し直していたら（`isRunningOrBooting`）外さない。`stop()` で取り消した起動は知らせが出ないので対象外（本番で外から `stop()` を呼ぶ道はない）。`PoweredOn` の意味と NBT は変えない（`ComputerStatus`・`ComputerError` は保存しない）。

追記（#698）: CRASHED の知らせはケースに次の `MachineManager.tick` で届くので、CRASHED になってからケースが外すまでの間に保存の経路が走りうる（自動保存は同じ tick の `tick` の後、アンロード・FULL でなくなった・停止はいつでも。停止では tick が回らないので、最後の tick の後や停止の待ちの間に CRASHED になった台は必ずこの間に入る）。#671 の後段の失敗の台は `restoreHandle` を下ろすので「復元の途中」の除外にもかからない。これまでは CRASHED の台をそのまま写して書いていた（読み込むと `NO_LIVE_INIT` などの冷えた起動になり、壊れた台が電源の入ったまま動き出す）。さらに、アンロード・停止では外した後の知らせが捨てられるので、`PoweredOn` が真のまま残っていた。ゲストが止めた・起動に失敗した STOPPED の台も、電源の状態について同じだった。そこで次のようにした。

- `Machine.captureCopy` は CRASHED の台を、どちらの方針でも断る（`null`。取り出しの番号・差分の基準に触らない）。#696 の「直さずにこの形」（後段の失敗の崩れた表）が置き場に書かれないことは、これで成り立つ。STOPPED は断らない（再起動の途中の `REBOOT_PENDING` の規則を守る）。`Machine.isSettlingForSave` は CRASHED で偽（再起動を求めた後に CRASHED になると `saveReadiness` が `TRANSIENT` のまま残り、解けない待ちで予算を使い切るため。ADR 0635）
- `ComputerCase.settleStoppedMachine()` は、今のマシンが CRASHED か、ゲストが止めた・起動に失敗した STOPPED（復元の途中・起動の途中・再起動の途中でない）なら、知らせを待たずに同じ後始末をする（外す・表示・`poweredOn` を偽・`events` に中継して結線も外す）。起動に失敗した台は、ここを通ると表示が BOOT_FAILED でなく OFF になる（見分ける印は足さない。この経路の直後に、どちらもマシンを外して表示が OFF になるため）
- 1.21.1 の `ServerMachines` は、アンロード・FULL でなくなった（`saveForUnload`）と停止（`saveForStop`）で、取り出す台を絞る前と、取り出した後に `settleStoppedMachine` を呼ぶ。アンロード・FULL でなくなったでは、変わったらチャンクに `setUnsaved(true)` を付ける（`setChanged` が効かないため。ADR 0084 の規則 4・5）。停止では `setChanged` → `saveAllChunks` で NBT に載り、CRASHED の台を warn でログに残す（core のクラッシュのログは tick で出るため）。写した後に CRASHED になった台は、写した世代が残るが、電源が切れているので戻されない。自動保存では呼ばない（次の tick で知らせが届き、チャンクは FULL なので `setChanged` が効く）
- 保存形式（NBT のタグ・世代ファイル・`KernelStateCopy` の符号化）は変えない。変わるのは写すかどうかと、`PoweredOn=false` を書く時点だけ

## 冷えた起動にする場面（`ColdBootCause`）

| 場面 | 理由 |
| --- | --- |
| 電源は入っていたが ID がない（取り出す前に落ちた・`owner.bin` が書けない） | `NO_IDENTITY` |
| `claim` が新しい ID を振った（`NEW_ID_*`） | `NEW_ID` |
| その ID の書き込みが期限までに終わらない | `WRITES_PENDING` |
| 戻せる世代がない（`restorableGeneration` が空。ADR 0084 の規則 9・10） | `NO_GENERATION` |
| 保存データを書いた MOD のバージョンが今のものと違う（差分の基準のものを含む。`KILLED` 節より先に比べる。#88、ADR 0088） | `MOD_VERSION` |
| `KILLED` 節の理由が 0 以外（起動中・再起動の待ち・init を殺した写し） | `KILLED_SECTION` |
| 読めない・壊れている・`KILLED` 節が読めない（`0xFF`）・差分の基準がない・合わない・pid 表が不正 | `UNREADABLE` |
| モジュールが置き場にない | `MODULE_MISSING` |
| 読み込み直したモジュールのハッシュが保存データと合わない・読み込めない・計測ありのモジュールの変換器の版が今のものと違う（読み込まない。ADR 0088） | `MODULE_MISMATCH` |
| 戻せないプロセス（ABI 層が p1 でない・入口と状態の組み合わせが下の表にない・BLOCKING のドライバー） | `UNSUPPORTED_PROCESS` |
| init が終わっている・表にない | `NO_LIVE_INIT` |
| 根・`/home` のディスク・イメージが開けない・`/tmp` の `TMPFS` 節がない・知らないマウント（それ以外のディスクが開けなければ、そのマウントだけ落とす。ADR 0056） | `MOUNT` |
| RAM が足りない（インスタンスの区画・テーブル・`/tmp`）。インスタンスは、プロセスの RAM の勘定（`ProcessMemory`）が確保を断ったときだけ（#576） | `NO_MEMORY` |
| そのほか（インスタンスを作り直せない（状態が合わない・start 関数を持つ・リンクできない）・内部の例外・モジュールの読み込みが混み続けた） | `RESTORE_FAILED` |

「ID はあるが世代がない」は ADR 0084 の規則 9・10 にそろえた（NBT が欠番を指していれば直下の世代に戻し、それもなければ `NO_GENERATION`）。

## 入口と状態の組み合わせ

前段はプロセスごとに、保存した状態・p1 の層の入口（`ENTRY_*`）・`wait` が次のどれかであることを確かめる。

| 状態 | 入口 | `wait` | 戻し方（後段） |
| --- | --- | --- | --- |
| `CREATED` | `NO_INSTANCE` | `null` | CPU の待ち行列に入れる（最初の step で読み込み直して start する） |
| `WAITING_EVENT` | `REWIND` | 空でない | 待ちを登録し直す。そろっていれば（か `wakeOnRestore`）起こす |
| `WAITING_EVENT` | `REWIND` | 空（`wakeOnRestore` のときだけ） | `restoreWake` を立てて起こす（そろいを見ずに resume） |
| `RUNNABLE` | `REWIND` | `null`（燃料待ちの巻き戻し）・空でない・空（`wakeOnRestore`） | 待ちがあれば登録し直し、燃料待ちの列に入れる |

`wakeOnRestore`（ADR 0082。ホスト側の処理の待ちを写しから外した）は、実行時の印 `ProcessRuntime.restoreWake` にし、最初の step で使うまで残す。
使う前にもう一度保存したら、写しにも `wakeOnRestore` を立てる。

## 前段と後段

前段（`MachineRestore`。起動用のスレッド、カーネルロックの外）:

1. `restorableGeneration` で戻す世代を決め（NBT の世代と違えば warn）、読み（差分なら基準も）、`KILLED` 節を見る。`SnapshotDecoder.moduleSources` で、`PROCESS_ABI` 節の p1 の層の先頭にあるモジュールの参照だけを読む（区画は展開しない。読み手は `SnapshotDecoder` のまま）。ここで断るのは `decode` も必ず断るものだけ（節の版・p1 の層の版、節の数が `KERNEL` 節の表のプロセスの数の上限 `KernelLimits.maxTableProcesses`（`maxProcesses * 2 + 64`）を超える。#587）。そのため、先に読んでも冷えた起動の理由は変わらない
2. 別々のモジュールを**順に1つずつ**、置き場の元のバイト列から、保存したときと同じ読み込み方（燃料の計測・待ち合わせる import）で `ProgramCache` を通して読み込む（#577）。
   - 読み込みが終わっていなければ、終わったときに続きを起動用のスレッドに積み直し、スレッドを返す（共有済みならその場で次へ進む）
   - 読み込みの待ち行列が上限（`ProgramLoadBusyException`）なら、`TimerService` で仮 20 ms 後に起動用のスレッドへ積み直す。最初に混んでいたときから仮 60 秒を過ぎたら `RESTORE_FAILED`
   - 並べて頼まない（モジュールが 9 個以上ある台が、自分の読み込みで上限に当たるため）
   - 置き場にない・読み込めないモジュールは覚えておき、3. でそれを使う終わっていないプロセスに当たったときに `MODULE_MISSING`・`MODULE_MISMATCH` にする（読み込みを復号より先にしても、冷えた起動の理由の優先は前と同じ。使わないモジュールで落とさない）
   - 読み込み完了・タイマー・取り消しのスレッドでは、積み直す・読み込みを取り消す以外のことをしない。起動用のスレッドが受け付けなければ（スケジューラの停止後）何もしない（停止は先に全台を止めるので、取り消し済み）
3. `SnapshotDecoder.decode` で復号・検査し（`inspect` と同じ確かめ。`TMPFS` 節も読む）、上の表と init・pid 表を確かめ、読み込んだモジュールの後のハッシュを照らす
4. マウントを開き直す（`disk:<id>` は起動と同じ口 `BootVolumeOpener`、`tmp` は `TMPFS` 節から、`dev` は新しく作る）。ディスクの持ち主の移し替え（lease）は開くだけで済む。ただし、開くときに `isRestoreCancelled` を渡し、取り消された前段は世代を進めない（リースのロックの中で見る。ADR 0052「排他とリース」。#588）。開けなかったときは、まず `checkCancelled()` してから `MOUNT` にする（取り消された前段を冷えた起動に流さない）。#56 からは、開く前に予約（ADR 0056）を取り、根・`/home` 以外のディスクが開けなければ `MOUNT` にせず、そのマウントだけを落として戻し、`disk-removed` を出す
5. 開いたファイルの node を、まだマウントしていないディスクに登録する（`DiskFileSystem.adoptNode`。ホストの I/O はしない）。消えていれば、使ったときに `STALE`
6. インスタンスを作り直す（`load` と同じ設定。燃料 0。退避した値を戻す）

後段（`Machine.completeRestore`。カーネルロックの中）: 表（プロセス・オブジェクト・イベントの索引・マウント・燃料（1 tick 分で頭打ち）・コンソール・init・時計）に入れ、
ファイルシステムをつなぎ、上の表のとおりに実行時の部分（待ちの登録・燃料待ち・CPU の待ち行列）を作って RUNNING にする。

- **後段で失敗したら**（表に入れかけた後）、カーネルの不整合として CRASHED にする（`inconsistencyLocked`）。知らせ（`RestoreListener`）は送らない。ケースは CRASHED の規則（マシンを外して ERROR、電源を切る）で受ける。
  `completeRestore` は `false` を返し、前段で作ったもの（インスタンス・ファイルシステム）は起動用のスレッドが**ロックの外で全部** `discard` する（#576。ロックの中で I/O をしない ADR 0052 の規則）。
  表に入れ終えて `stopLocked` が閉じたものにも重ねて呼ぶが、`WasmInstance.close`・`FileSystem.retire`・`TmpFileSystem.onUnmounted` は2回目に何もしない。
  失敗の位置によらず、サーバー全体の RAM の勘定（マシンを閉じても戻らない）・表のプロセスが持ったままの `/tmp`・ディスクのリースが返る。半端な表は巻き戻さない。
  追記（#671）: `stopLocked` が `runtimes` のプロセスを終えた後に、表にあって `runtimes` に入っていない終わっていないプロセスを KILLED にする（状態と待ちを書き換えるだけ。表から外さず、fd・オブジェクトは片付けない）。
  先に KILLED にすると、採用済みの親の終わりが終わった子を刈り取る（表から外し、オブジェクトの参照を返す）ので、後にする。
  `stopLocked` は `runtimes` のプロセスしか止めないので、これがないと `awaitTermination` が返らない。`/tmp` は `stopLocked` の `checkAllDoneLocked` が外す（2回目の `onUnmounted` は何もしないので二重に返らない）。
  `stopLocked` の一般の掃除にしないのは、spawn の途中（表に足した後、`runtimes` に足す前）のプロセスを巻き込まないため。
  追記（#696）: 上の KILLED は終わりの記録（`ExitBookkeeping.recordExit`）を通さないので、そのプロセスについて表の不変条件が崩れたまま残る。
  `ProcessObject.status` は null のまま（終了コード・`termSignal` も入らない）、親のないものも `orphanZombies` に入らない（古い順の刈り取りにもかからない）、
  親に知らせない（`pendingChildExits`・`CHILD_EXITED`）、子の付け替えも子のゾンビの刈り取りもしない、init でも `kernel.initPid` を下ろさない、
  fd・`waitTimers`・オブジェクトの参照を返さない（前段で作ったものは discard が返す）。
  `runtimes` は pid の昇順で作るので、混ざる位置は2通りある。採用済みの親と未採用の子なら、子は親の終わりで親なしに付け替えられ、表に残ったまま KILLED になる。
  採用済みの子と未採用の親（pid の使い回しで、子の pid が親より小さい）なら、子は先に終わって親に知らせ（`pendingChildExits` が増える）、
  終わった親を指す親付きのゾンビとして残る。親の `status` は null のまま。どちらもテストで固定している（`MachineRestoreTest`）。
  台は CRASHED のまま使い続けない（`boot`・`reboot` は断り、ケースは CRASHED の知らせでマシンを外して閉じる）ので、直さずにこの形にしておく
- 取り消し（`stop()`・`close()`）は前段のどこでも効き、作ったものを返す。読み込みを待っている間なら、`restoreCancelSignal` に復元1回につき1つ付けた登録が、待っている読み込みを取り消す（始まっていなければ読み込まない。#363）。登録は待っている読み込みの入れ物だけを持ち、`restoreCancelSignal` は取り消し（`stopLocked`）に加えて前段の終わり（`completeRestore`・`restoreFellBack`）でも終えるので、終わった台に登録は残らない（#587）。後段に入る前に取り消されたら入れない。知らせは `CANCELLED`。
  前段が冷えた起動待ちに切り替えた（`COLD_BOOT` を積んだ）後、配る前に取り消したときも、配るときに `CANCELLED` に替える（`stopLocked` は前段の途中のときだけ `CANCELLED` を積む）。
  知らせは復元1回につき1回で、取り消した台を冷えた起動に数えない（#576）
- 取り消したマシンの `restore()` は断る（`restoreCancelled` は下ろさない。#576）。取り消された古い前段がまだ起動用スレッドで走っていても、その印で止まり、古い prepared を表に入れない。ケースは毎回新しいマシンを作るので、呼び手は変わらない

## 2 つの印

| 印 | 立つ | 下りる | 効き目 |
| --- | --- | --- | --- |
| `restoringValue` | `restore` を受け付けた | 後段を終えた・前段が冷えた起動に切り替えた・取り消した | コンソールの入力・大きさの変更を断り、コンソールの TTY を作らない（表を空のまま保つ） |
| `restoreHandle`（`quiesce`。`isRestoring`） | `restore` を受け付けた | 終わりの知らせが返った後・取り消した（`stopLocked`）・`coldBootAfterRestore` | step を割り当てない。保存しない（`TRANSIENT`）。`boot` を断る |

冷えた起動待ち（`coldBootPending`）の間も保存せず `boot` を断り、`coldBootAfterRestore` が印を下ろして起動を始める（同じロックの中で `bootingValue` を立てる）。
画面のデバイスは知らせの中でつなぐので、そのときにはもう `restoringValue` が下りていて、画面の大きさがコンソールに入る（冷えた起動でも残る）。

**知らせが返るまで保存しない**（#589）: 後段が `restoringValue` を下ろしてから、知らせ（`RESTORED`）が返って `restoreHandle` を閉じるまでの間も、
保存しない（`saveReadiness` は `TRANSIENT`、`isAtWaitPoint` は偽、`captureSnapshot` はどちらの方針でも `null`）。`Machine` の
`restoreTransient` は `restoringValue || restoreHandle != null || coldBootPending` で、「`isRestoring` の間は保存しない」が core の中で1つの印で成り立つ。

- 実装を ADR に合わせた（ADR を「知らせの中では保存できる」に書き直さなかった）理由: 知らせの中で保存できると困る経路は、今のコードには見つからなかった
  （写しにデバイスは入らず、回し直す前の呼び出しは `Queued` のまま写り、`quiesce` で止まっているので写すのは戻したのと同じ状態）。
  それでも、呼び手が `isRestoring` の1つの印に頼れるほうが、`MachineManager.capture` の呼び手や 1.20.1 への移植（#224）がフィルタを忘れても安全で、
  受け手（`redispatchRestoredDeviceCalls` など）が知らせの中で状態を動かし始めても、その途中を写さない。保存しなくても失うものは、ほとんどない
  （NBT は戻したばかりの世代を指している。アンロードの扱いと同じ）。保存形式は変わらない
- 失うものが「ない」わけではない窓: 後段が `restoringValue` を下ろしてから知らせが返るまでは、入力（`offerConsoleInput`）と画面の大きさの変更
  （`resizeConsole`）が `restoringValue` だけを見て受け付けられ、知らせの中の `redispatchRestoredDeviceCalls` もカーネルの状態を動かす。
  その間に進んだ分は、知らせが返った後の最初の保存で拾う（高々 1 tick。接続層は以前から `isRestoring` の台を保存していない）
- 知らせはメインスレッドで配る（通知の列）。メインスレッドで READY を待つ呼び手（停止・アンロードの待ち、自動保存）は、`isRestoring` の台を先に外す
  （外さないと、知らせが配られないまま期限いっぱい待つ）。接続層は今もそうしている
- `restoringValue` を下ろす時点は、知らせの後に遅らせない（上のとおり、知らせの中で画面の大きさをコンソールに入れるため）

**止めている間のプロセス**: 起こされたプロセスはワーカーで step に入るが、`tryGrantLocked` が燃料を渡さない（`quiesce` の間は `tryActivate` が偽）ので、
`NO_FUEL` で燃料待ちの列に入る。`driver.start`・`resume` は呼ばれず、`CREATED` は `CREATED` のまま、`restoreWake` は残る。`quiesce` を閉じると燃料待ちを起こす。

**知らせは `close()` の後も配られる**（通知の列。ADR 0044）。受け手は、そのマシンが今の自分のマシン（`slot.machine`）かを確かめてから、デバイスをつなぐ・
呼び出しを回し直す・冷えた起動を始める。電源を切った・アンロードした後に届いた知らせでは何もしない。

## 接続層（1.21.1 NeoForge）

- `CaseBlockEntity`: `PoweredOn` を読み書きし、`onLoad` で順番待ちに入る。順番が来たら（`startRestore`）ID・`claim` の判定・書き込みの期限から
  `RestoreSource` を決めて `ComputerCase.startRestore` に渡す。ID は今の ID（`currentIdentity`。書き込み中なら予約の世代）を使う（#575）。
  FULL でなくなったときの取り出しは完了を受け取るまで `identity` を進めないので、`identity` を使うと、書き込みが `processCompletions` の後に
  終わったときに1つ前の世代から戻ってしまう。予約の世代が書けていなければ、規則 9 で直下の世代に落ちる。
  `claim` が `NEW_ID_*` の台を冷えた起動にするのは、振った直後（世代 0）だけ。その後に書いた世代があれば（FULL に戻ったときなど）戻す。
  デバイスは知らせの中で `TestComputerWiring.attach`（起動しない）でつなぐ
- `ServerMachines`: 順番待ちを tick の始めに回す。チャンクが FULL に戻ったら（チケットの段階が 33 以下に上がった。`fullStatus` はチケットの段階から
  その場で決まる）、次の tick の終わりに順番待ちに入れる。アンロード・FULL でなくなった・停止の取り出しは、復元の途中の台を飛ばす（NBT は前の世代と電源の状態を
  指したまま。外すと復元を取り消し、次に読み込んだときに戻し直す）。数え口（`Stats`）に戻した数・冷えた起動の数を足す

## 比べた案

- **B. 電源の状態を保存データ（世代のファイル）の側に持つ**: 電源を切っただけで世代を書く必要があり、書き込みの失敗・欠番で電源の状態が巻き戻る。NBT なら `setChanged` で済む
- **C. 状態を持たず、ID と世代があれば戻す**: 電源を切った台も次の読み込みで動き出す（切った後に書いた世代が残る）。切ったときにディレクトリを消すと、運んだ BE の写しと区別できない
- **D. 前段と後段を分けず、ロックの中で表を作りながら戻す**: 失敗したときに表が半端に残り、冷えた起動にできない（CRASHED にするしかない）。モジュールの読み込み・ファイルシステムの I/O をロックの中でしない規則（ADR 0052）にも反する

## 失う場面

- **電源を切った直後に落ちた**: `PoweredOn` が偽になったチャンクの NBT がディスクに行く前にクラッシュすると、前の NBT（真）と前の世代が残り、次に読み込んだときに電源を切る前の状態に戻る。
  電源ボタンは `setChanged` するだけで、すぐには書かない（チャンクの保存を待つ）。プレイヤーがもう一度切ればよい
- 戻した直後の画面は、OS が描き直すまで空（画面の中身は保存しない。描き直しの合図は #87）
- 止まっていた間の時間のイベントは出さない（#87）
  - 追記（#87）: 後段の成功の経路（`completeRestore`。RUNNING にした後、RESTORED の知らせを積む前、同じロックの中）で `restored` イベント（値は実時間・ゲーム内時間の飛び）を出すようにした。冷えた起動・取り消し・CRASHED では出さない。起きたプロセスは知らせの受け手が返るまで動かないので、標準 OS の `sh`・`nano` は画面をつないだ後で描き直す（ADR 0087）

## コスト

- メインスレッド: 順番待ちを見る（書き込みの終わりは待たずに見る）・マシンを作る・知らせでデバイスをつなぐだけ。読み・復号・コンパイル・インスタンスの作り直しは起動用のスレッド
- 読み込んだ台が多いときは tick ごとの上限（仮 16 台。`MachineSaveConfig.restoresPerTick`）で均す。モジュールのコンパイルは `ProgramCache` で同じモジュールを1回にする（サーバー全体）
- コンパイルを待つ台は、起動用のスレッドを持たない（#577）。待っている台が多くても、ほかの台の起動・復元・冷えた起動は起動用のスレッドの本数で進む。待つ間のヒープは台ごとに圧縮のままの写し（標準 OS の 1 台で約 6.4 KB）だけで（前段が終われば残らない。#587）、復号（区画の展開。約 93 KB）は読み込みが終わってから起動用のスレッドで行う。相乗りした台の続きは読み込みの完了でまとめて積まれるが、起動用のスレッドの本数で均される
