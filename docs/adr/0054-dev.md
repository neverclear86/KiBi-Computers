# 0054: `/dev`（デバイスファイル）

- 状態: 採用
- Issue: #54（task）。前提: ADR 0051（VFS）、0058（fd 表）、0060（TTY）、0065（デバイスのモデル。Q5）、0066（開いたデバイスからの呼び出し）。`null`・`zero`・`tty` は #485・#493 で先に入れた分を、ここにまとめる
- 後続: #77（WASM からデバイスを呼ぶ import）、#267・#268（p2・p3 の `wasi:filesystem`。同じ差し替えの口を通る）
- 番号は Issue 番号にそろえている

## 決めたこと（要約）

- `/dev` は `DevFileSystem`（`core.kernel.vfs`。`internal`）。起動の始めに `mountDev` がマウントし、復元では作り直す（`MachineRestore`）。状態を持たない（RAM に数えない。保存するものもない）
- 中身（名前の順）: `device/`、`null`、`random`、`tty`、`urandom`、`zero`
- デバイスを `/dev` のファイルとして見せるかは、#65 の Q5 でオーナーが A（`/dev/device/<address>`）に決めた。種類ごとの名前（`/dev/screen0`）や、`/dev` の直下に並べる形は採らない
- 公開 API・ABI（関数の形）・保存のバイト形式は足さない。保存に乗る `/dev` の node の番号を3つ足すだけ（下の「保存」）

## 中身

| 名前 | node | 種類 | 読む | 書く |
| --- | --- | --- | --- | --- |
| （根） | 1 | ディレクトリ | | |
| `null` | 2 | キャラクターデバイス | 終わり（0 バイト） | 捨てる |
| `zero` | 3 | キャラクターデバイス | 0 で埋まる | 捨てる |
| `tty` | 4 | キャラクターデバイス | 開くと端末に差し替え | 同左 |
| `random` | 5 | キャラクターデバイス | 乱数 | 捨てる |
| `urandom` | 6 | キャラクターデバイス | 乱数（`random` と同じ） | 捨てる |
| `device/` | 7 | ディレクトリ | | |
| `device/<address>` | address から決める | キャラクターデバイス | 開くとデバイスのハンドルに差し替え | 同左 |

- 大きさはどれも 0。`O_TRUNC`・時刻の変更は受け付けて何もしない（`> /dev/null`・`touch /dev/null` が通る。`> /dev/device/<address>` も、差し替えの前に `O_TRUNC` が来るので受け付ける）
- 作る・消す・名前を変えるは `ACCES`。根は `BUSY`、`device/` を `rmdir` すると `ACCES`、`unlink` すると `ISDIR`
- `/dev/null/x`・`/dev/device/<address>/x` は `NOTDIR`。`/dev/device/` の下の知らない名前は `NOENT`（address は小文字の UUID だけ。大文字や形の違う名前も `NOENT`。例外は投げない）

### `random`・`urandom`

- 乱数の元は `random_get` と同じ `MachineEnvironment.entropy`（既定は全マシンで共有の `SecureRandom`）。マシンごとに `SecureRandom` を作らない（台数分のメモリとシードのコストを増やさない）
- Linux 5.6 以降と同じく、どちらも待たない（中身は同じ）。`urandom` は既存のプログラム（`/dev/urandom` を読むもの）のために置く
- 燃料は `fd_read` と同じ（読んだ 64 バイトごとに 1、1回の上限 1 MiB）。`random_get` と同じ割合なので、どちらで読んでも量は変わらない
- 読むのはカーネルロックの外（ファイルの読みはすべてそう。ADR 0052）。`EntropySource.fill` は配列全体を埋めるので、`fd_read` のふつうの形（バッファ全体）ならそのまま埋め、一部なら 64 KiB までの一時配列を使う

### `device/`

- 一覧は、読むたびに `DeviceBus.list()`（ロックなしの copy-on-write の表）を読む。`/dev` は表を購読しない・写しを持たない（tick ごとのコストも、台数に比例する状態も足さない）
- node は address から計算で決める: UUID の上位と下位の 64 ビットの XOR の下位 62 ビットに、ビット 62 を立てる。固定の番号（1〜7）と重ならず、address → node の表を持たない。node から address は引かない（#693）。62 ビットのハッシュなので別の address が同じ node になりうる（XOR なので上位と下位を入れ替えた UUID は同じ node。address は持ち主の NBT にあり、狙って作れる）。そのため差し替え（下の「差し替え」）は開いたパスの最後の名前（address）で引き、node は stat・一覧と、`statNode`（node が同じデバイスが1つでもつながっていれば生きている）にだけ使う
- 既知の制約: 衝突した2つは、一覧と stat で同じ node に見える（`ls -i` や、inode で同じファイルと見なすプログラムでは同じに見える）。node は計算で決まり、62 ビットには単射にできないので直さない。開く・差し替えは名前で引くので、どちらも正しいデバイスが開く
- パスで stat すると `CHARACTER_DEVICE`（`ls -l` 向け）。fd で `fd_fdstat_get`・`fd_filestat_get` すると `UNKNOWN`（デバイスのハンドルの fd。下の「fd とパスで種類が違う」）

## 差し替え（`FdTable.openFile`）

`/dev/tty` と `/dev/device/<address>` は、開いた fd がファイル（`OpenFile`）ではなく、別のカーネルオブジェクトを指す。

- ファイルシステムが `FileSystem.special(node, name)`（`SpecialFile`。旧 `isTerminal` を一般化した。`name` は開いたパスの最後の名前。#693）で差し替え先を返し、`FdTable.openFile` の1か所で差し替える。ABI 層（`path_open`、後の p2・p3）はこの口を通るだけで、`/dev` を知らない
- `special` はカーネルロックの中から呼ばれる（I/O をしない。デバイスの表はロックなしで読む）。ロックの中から呼んでよい口の一覧（`FileSystem` の KDoc）の `isTerminal` を `special` に置き換えた
- `tty`: プロセスの制御端末（コンソールの `Tty`）の参照を1つ増やす。端末がなければ `NXIO`（#485）
- `device/<address>`: 新しい `DeviceHandle(address, kind)` を fd に入れる。`kibi:device` の `open` で開くものと同じ型（Q5 の「同じ fd」）。`kind` は差し替えるとき（ロックの中）につないでいるデバイスの種類
- 開く（`Vfs.open`。ロックの外）から差し替える（ロックの中）までの間にデバイスが外れたら `NOENT`（stat と同じ。`NXIO` ではなく、パスの上から消えたものとして扱う）。node が同じ別のデバイスが残っていても、開いたパスの名前のデバイスが外れていれば `NOENT`（#693）
- 満杯なら `MFILE`（表もオブジェクトの表も変えない）。開いた `OpenFile` は呼び出し側が閉じる（`/dev` は開いたことを数えないので、捨てるだけ）
- `DeviceBus.attach`・`detach` はカーネルロックの中から呼ばない（ADR 0065 のロックの順）。ここでは `find`・`list` を読むだけ

### device の fd の権利と読み書き

- パスで開いたときの権利は、`path_open` が求めた READ・WRITE をそのまま渡す（`/dev/tty` と同じ）。`kibi:device` の `open` は READ だけ（ADR 0066）
- device の fd の `read`・`write` は `NOSYS`（Q5。`FdIo.readLocked`・`writeLocked`）。WRITE の権利を渡すので、`echo x > /dev/device/<address>` は `BADF` ではなく `NOSYS` になる。`kibi:device` で開いた fd も同じオブジェクトなので、読むと `NOSYS`（書くと、WRITE の権利がないので `BADF`）
- `poll` は今までどおり待てない（`INVAL`）
- 外れた後もハンドルは残り、呼び出しは `detached`（ADR 0066）。`close`・`dup` は普通の fd と同じ

### fd とパスで種類が違う

- パスの stat（`ls -l /dev/device`）は `CHARACTER_DEVICE`、device の fd の `fdstat` は `UNKNOWN`
- fd を `CHARACTER_DEVICE` にすると、wasi-libc の `isatty` がデバイスの fd を端末と見なす。`CHARACTER_DEVICE` を返す fd は `Tty` だけにしておく

## 保存

- `/dev` の開いたファイルは `(マウントの ID, node)` で保存される（ADR 0051・0082）。node の番号は固定で、変えない・使い回さない（変えると、保存した `/dev/null` などの fd が `STALE` になる）。#54 で 5〜7 を足した（既存の形の中の小さな追加）
- device の node が保存に乗ることはない（開くと必ず `DeviceHandle` に差し替わる）。`DeviceHandle` は今までどおり `(address, kind)` で保存する（ADR 0065 の Q6）
- 復元では `DevFileSystem(entropy, DeviceDirectory.of(devices))` を作り直す（起動のときと同じ引数。渡し忘れると、復元した後だけ `random` と `device/` が空になる）

## 1,000 台規模

- `/dev` は tick を持たず、購読・キャッシュもない。`ls /dev/device` は、そのときに表を読むだけ
- 乱数は全マシンで1つの `SecureRandom`（中で排他する）。量は燃料で抑える
