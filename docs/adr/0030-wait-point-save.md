# 0030: 待機点で保存する方式（検証の結果）

- 状態: 採用（方式として成り立つことを確認）。本番の保存処理は #81・#82
- Issue: #30（PoC）。依存: #91
- 番号は Issue 番号にそろえている

## 背景

コンピューターの状態をワールドと一緒に保存したい。WASM のスタック（値スタック・呼び出しのフレーム）は Endive の外に取り出せないので、
「プロセスがイベントを待っていて、WASM のスタックが空のとき（待機点）」に、線形メモリなどだけを保存する方式を考えた。
これが成り立つか、保存に何を含めるべきか、サイズと時間の目安を確かめた。

## 測定

測定用のコードは `poc/wait-point-save/`。`./gradlew :poc:wait-point-save:run` で表を出す（結果は `poc/wait-point-save/results.md`）。
動作の確認は `./gradlew :poc:wait-point-save:test`（CI の `build` で走る）。

- 待機点 = ホストが呼んだ export から戻った時点。検証用に reactor 形式（`-mexec-model=reactor`）の WASM を2つ作った
  - `waiter.c`: C だけ。malloc したリスト、静的変数、libc の stdout のバッファ（改行まで出ない）に状態を持つ
  - `lua_host.c`: Lua 5.4 のライブラリ（`lua.c`・`luac.c` を除く）とリンクする。core の `lua.wasm` と同じコンパイル設定（WASM の例外処理で setjmp/longjmp）。メインチャンクをコルーチンで動かし、`kibi.wait()`（C 関数から `lua_yield`）で `poc_resume` から戻る
- 入れ子のコルーチンの待ちは、メインチャンク（と `coroutine.wrap` の呼び出し元）が `kibi.WAIT` を受けて `kibi.wait()` で出し直す（Issue の回答の選択肢 A）。ホストに見えるのは常にメインチャンクの待ちだけ
- WASI は PoC 用の最小実装（MiniWasi）。状態（イベントキュー、タイマー、仮想時間、乱数、標準入出力のバッファ、プロセスの状態）はすべて PoC 用のカーネル（MiniKernel）に持つ
- 復元は、同じモジュールから `withStart(false)` で新しいインスタンスを作り、メモリ・可変グローバル・テーブル・drop 済みセグメントを上書きする。`_initialize` は呼ばない
- #91 の `lua.wasm`（コマンド形式）も MiniWasi で動かし、待ち方を確かめた

## 結果

- **保存・再開できる。** 各イベントの前に毎回保存して戻しても、保存しなかった実行と標準出力・線形メモリの中身が一致した。バイト列に変換して読み直しても、インタプリタとランタイムコンパイラの間で保存と復元を入れ替えても同じ
- 1,000 個の子コルーチンが `kibi.wait()` の中で止まった状態、`pcall`・`coroutine.wrap` の入れ子の中で止まった状態からも、続き（ローカル変数・戻り値を含む）が動く。復元後の `pcall` の中の `error`（longjmp）も正しく捕まる
- 復元後に `_initialize` を呼ばなくても、malloc のヒープと stdout のバッファ（線形メモリの中）は続きから使える。呼んではいけない（静的変数が初期化される）
- ホスト関数の中で待っているとき（`kibi_poc.block`、`fd_read`）は「WASM の中」と判定して保存を拒める
- 別のモジュール（SHA-256 が違う）への復元は拒める

サイズと時間（抜粋。ランタイムコンパイラ、Java 17）:

| 状態 | 線形メモリ | Deflate | 1イベント後の差分 | 取り出し | Deflate の時間 | 書き戻し（生成込み） |
| --- | ---: | ---: | --- | ---: | ---: | ---: |
| Lua が待つだけ | 1.5 MB | 30 KB | 6 ページ（Deflate 25 KB） | 0.3 ms | 10 ms | 1.3 ms |
| Lua コルーチン 1,000 個 | 3.1 MB | 112 KB | 8 ページ（44 KB） | 0.6 ms | 28 ms | 0.6 ms |
| Lua がデータ 10 MB を持つ | 66 MB | 13 MB | 7 ページ（60 KB） | 12 ms | 1.1 s | 15 ms |
| Lua がデータ 50 MB を持つ | 258 MB | 58 MB | 7 ページ（60 KB） | 46 ms | 4.8 s | 63 ms |

- 線形メモリは縮まず、free した領域も 0 にならない。Lua がデータを持つと、線形メモリはデータの数倍になる（50 MB 相当で 258 MB）。全部 0 のページの省略は、確保だけして触っていない領域にしか効かない
- 1イベントで変わるページはデータの量によらず少ない（3〜8 ページ）。差分保存がよく効く
- 取り出し・書き戻しは速いが、Deflate（レベル 6）は大きなメモリで秒単位になる

## 結論

1. **待機点で保存する方式は成り立つ。** 本番（#81・#82）はこの方式で保存する
2. **保存に含めるもの**: 線形メモリ（ページ数と中身）、可変のグローバル（`__stack_pointer` など）、テーブル（関数の番号）、drop 済みのデータ・要素セグメント（今の WASM にはパッシブなセグメントはないが、`memory.init` を使うモジュールのために要る）、カーネルの状態（fd 表・イベントキュー・タイマー・時刻・乱数・入出力のバッファ・プロセスの状態）、モジュールの識別子（ハッシュ）。WASM のスタックと例外のタグは要らない
3. **WASI の状態はカーネルが持つ。** Endive の `WasiPreview1` は内部状態を取り出せないので、本番も自前の WASI（カーネル）の上に作る
4. **同じモジュールにしか戻せない。** 保存データにモジュールのハッシュを入れ、違えば復元を拒む。MOD の更新で `lua.wasm` が変わったときの扱いは #88 で決める
5. **時間の目安**: 取り出し（コピー）は tick の中でできる大きさ（〜50 ms / 258 MB）。圧縮は別スレッド（#84）にするか、差分（#83）にしてから行う。圧縮方式（Deflate のレベル、zstd など）は #83・#84 で比べる
6. **ブロッキング型**: ホスト関数の中で待っているプロセスは待機点にないので、この方式では保存できない。扱いは #86

### #91 の `lua.wasm` の扱い

今の `lua.wasm` は `lua.c` の `main` を持つコマンド形式で、REPL も `lua foo.lua`（`io.read` など）も `fd_read` の中で待つ。export は `_start` と `memory` だけで、途中から入り直す口がない。
つまり、**今の形のままでは待機点に来ず、#86 のブロッキング型になる。**

本番の `lua.wasm` で待機点保存を使うための形の候補（どれにするかは ABI と合わせて #63・#72 で決める。ここでは推奨まで）:

- (1) reactor にする（**推奨**）。`lua.c` の `main` の代わりに、初期化とイベントを渡して再開する口を export する。メインチャンク（`lua foo.lua` のファイルも、REPL の1行ごとの実行も）をコルーチンで動かし、待つ API は C 関数から `lua_yield` で戻す。PoC の `lua_host.c` がこの形で、保存・再開と、入れ子のコルーチンでの待ちの出し直しが動くことを確かめた。条件: `io.read` など C の中で待つ標準ライブラリは、yield する版に差し替える（またはブロッキング型に残す）。REPL は `lua.c` の読み込みループをやめ、行の入力をイベントとして受ける形に書き直す。入れ子のコルーチンでの待ちは、スケジューラー（ライブラリ側で用意できる）で出し直す必要がある
- (2) Asyncify（binaryen）のように WASM のスタックを線形メモリに退避する変換をかける。コマンド形式の C プログラムをそのまま対象にできるが、コードのサイズと速度のコストがかかる（PoC では測っていない）
- (3) `lua.wasm` はブロッキング型のままにし、待機点保存は reactor 形式の別のプログラムだけで使う

(1) を推すのは、保存との相性（Lua のプログラムはほぼすべて待機点で保存できる）と速度（変換のコストがない）で (2) より良く、(3) では Lua のコンピューターがほとんど保存できないため。

その形をシステムコールとしてどう出すか（export の名前、イベントの渡し方、p1 の import と WIT の `kibi:*` の対応、p2・p3 の非同期との関係）は、ここでは決めない。#63・#72 と WIT（#257）で決める。
PoC の名前（`poc_step`・`poc_load`・`poc_resume`・`poc_alloc`、import モジュール `kibi_poc`）は仮のもので、ABI ではない。
