# 0083: 線形メモリの圧縮と、変わった区画だけの差分の世代

- 状態: 採用
- Issue: #83（task）。前提: ADR 0030（状態保存の PoC。結論 5「圧縮方式は #83・#84 で比べる」）、ADR 0081（世代のファイル・印・残す世代）、ADR 0082（節の中身。インスタンスの状態は書き換えた 4 KiB の区画だけ）、#407・#370（`WrittenPagesMemory`）
- 後続: #84（書き込み・圧縮を別スレッドに移す）、#85（差分の世代から戻す）、#251（仮の値の確定）

## 決めたこと（要約）

1. **差分の形は「最後の全体保存」からの累積の差分。** 差分の世代は1つの全体の世代（基準）だけを指す。戻すのに読むのは最大 2 ファイル。
   鎖（直前の世代を指す）にしないのは、読むファイルの数と、1つ壊れたときに戻せない範囲が増え、残す世代の規則も鎖をたどる必要が出るため
2. **変わった区画の見つけ方は、全体保存のときに区画を読み取り専用に戻し、次に書いたときの例外で拾う。** `WrittenPagesMemory.parkWritten` が
   書き換えた区画を同じ配列を指す読み取り専用の見え方（`asReadOnlyBuffer().order(LITTLE_ENDIAN)`。バイト順は引き継がれないので付け直す）に差し替え、
   元のバッファを横の表 `parked` に置く。次に書くと `parked` から戻す（RAM は数え直さない・写さない）。
   なので「書ける区画 = 基準から変わった区画」。読み書きの速い道に分岐を足さない（ゼロ・ROM の区画と同じ仕組み）
3. **全体保存に切り替える規則**: 「基準から変わった区画の数 ÷ 書き換えた区画の数」が `MachineSaveConfig.fullSaveChangedRatio`（仮 0.5。確定は #251）を超えたら全体。
   置き場が基準を知らない（初めての保存・サーバーの再起動の後・ID の振り直しの後）、持ち主・epoch が合わない、世代の上限でも全体
4. **圧縮は JDK の Deflate（raw、レベル 1 = `BEST_SPEED`）。** 依存が増えず Java 17 の `core` でそのまま使える。
   #84 までは符号化がメインスレッドなので速いレベル 1。方式の番号（u8）を書くので、後で zstd などを足すときに版を上げずに済む。レベルは書かない
5. **プロセスの基準（`ProcessRuntime.memoryBase`）**: `None` / `Pending(取り出しの番号, インスタンス)` / `Committed((UUID, 世代), インスタンス)`。
   全体保存の取り出しで区画を読み取り専用に戻したプロセスは `Pending`、置き場が書けたら（`MachineSnapshotSource.committed`）`Committed`。
   差分の取り出しでは `Committed` の基準が差分の基準（UUID と世代の組）と同じで、今のインスタンスが同じプロセスだけ `CHANGED`（変わった区画だけ）で取り、ほかは全体の形
6. 差分の世代は、基準の世代・基準のファイルの長さ・CRC32C を書き、読むときに照らす
7. 伸ばすときの区画の数の上限は `min(ページ数 × 16, マシンの RAM の上限 ÷ 4,096)`。保存データ全体の合計と、合成の後も同じ上限
8. 基準が使えないとき（`DeltaBaseUnavailableException`）は、その場で全体を取り直して書く（`MachineSaveStore.captureAndWrite`）
9. 置き場は基準をメモリにしか覚えない。サーバーの再起動の後の最初の保存は全体

## データ形式

外枠（ADR 0081。形式の版 1）は変えない。

### `DELTA_BASE` 節（種類 5、版 1）

差分の世代にだけ、外枠の直後（節の並びの先頭）に1つ書く。全体の世代には書かない。

| 中身 | 型 |
| --- | --- |
| 基準の世代 | i64 |
| 基準のファイルの長さ | i64 |
| 基準のファイルの CRC32C | i32 |

- 基準の UUID は書かない（外枠の UUID と同じ）
- `MachineSnapshot.deltaBase` で持ち、`sections` には入れない（`KILLED` 節と同じ扱い）。書き手は必ず先頭に1つだけ書く
- 先頭に置くのは、残す世代を決めるときに、ファイル全体を読まずに基準を引けるようにするため（`MachineSnapshot.readDeltaBase`）

二つの読み手の判断:

| 節の並び | `readFrom` | `readDeltaBase` |
| --- | --- | --- |
| 先頭が `DELTA_BASE`（版 1・長さ 20） | 差分 | 中身を返す |
| 先頭が `DELTA_BASE` で版か長さが違う | `SnapshotFormatException` | `SnapshotFormatException` |
| 2 つ目以降に `DELTA_BASE` がある | `SnapshotFormatException` | 見ない |
| `DELTA_BASE` がない | 全体 | `null` |

`readDeltaBase` が 2 つ目以降を見なくてよいのは、そのようなファイルは `readFrom` が拒むので、読める保存データにならないから。
二つの読み手の判断は、読める保存データの上で一致する。

### `PROCESS_ABI` 節の p1 の層の版 2

`PROCESS_ABI` 節そのものの版 1 は変えない。p1 の層の版を 2 にし、インスタンスの状態の線形メモリの部分だけを変える。読むときは版 1 も読む（全体・圧縮なしとして）。

| 中身 | 型 |
| --- | --- |
| メモリがあるか | bool |
| ページ数 | i32 |
| 形 | u8。0 = 全体（書き換えた区画すべて）、1 = 差分（基準から変わった区画だけ。ファイルに `DELTA_BASE` 節が要る） |
| 区画の数 | u32 |
| 区画の番号の並び | i32 × 数（昇順、ページ数 × 16 未満） |
| 圧縮の方式 | u8。0 = なし、1 = Deflate（raw）。ほかは壊れた保存データ |
| 圧縮した長さ | u32（残りの長さ以下） |
| 中身 | 区画の中身を番号の順につないだもの（数 × 4,096 バイト）を、方式で圧縮したもの |

- 圧縮した方が小さくなければ方式 0 で書く
- 伸ばすときは区画ごとに 4,096 バイトの配列を確保し、ちょうど埋まるまで伸ばす（ひとつながりの「数 × 4,096」の配列は作らない）。
  埋まる前に終わる・伸ばし終えた後に入力が余る・余分に伸びる（爆弾）なら壊れた保存データ
- グローバル・テーブル・drop 済みのセグメントは版 1 と同じ形で、毎回全部書く
- `TMPFS` 節とカーネルの節は差分にせず、圧縮もしない（毎回全体を書く）

### 合成

`InstanceStateMerge.merge(基準, 差分, 上限)`: ページ数は差分のもの（基準以上）、区画は「基準 ∪ 差分」で同じ番号は差分が勝つ、グローバル・テーブル・drop 済みは差分のもの。
差分の形のプロセスは、基準の世代に同じ pid の p1 の層があり、入口が 0 でなく、線形メモリが全体の形で、元のハッシュ・後のハッシュが同じでなければ壊れた保存データ。

## 残す世代（ADR 0081 の規則の拡張）

印が進んだ（`ADVANCED`）ときの掃除を、差分が指す全体の世代を消さないように広げた。

1. **候補**: ディスクの世代のうち、K =（今の印・前の印 2 つ・覚えている最新）に入るものと、今の印より大きいもの
2. **候補の基準**: 置き場が覚えていればそれ（`baseOf`）、なければファイルの頭（`readDeltaBase`）から読んで覚える
3. **keep** = 候補 ∪ 候補の差分が指す基準 ∪ 置き場が覚えている今の基準
4. keep に入らず、今の印より小さい世代を消す
5. 2. で頭を読めなかったら（`IOException`。`SnapshotFormatException` を含む）、**その回はその UUID の世代を 1 つも消さない**

- 読めなかったときに「基準なし」として扱わないのは、その差分が前の印で、ディスクのチャンクの NBT がまだそれを指していると、
  基準の全体の世代を消せば #85 で戻せなくなるため。一時的な I/O エラー（Windows のウイルス対策ソフトによる共有違反など）で基準を失わないよう、
  種類で分けずに「その回は消さない」にする（ADR 0081 の「残す」側に倒すだけ）
- 掃除が止まり続けない理由: 頭を読めない世代は、それが**今の印なら 3 回、前の印なら 2 回、2 つ前の印なら 1 回**、印が進めば K から外れ、
  候補にならないので頭を読まなくなる。そこで掃除が再開し、読めない世代そのものも消える（最大 3 回）
- 「覚えている最新」は頭を読まなくてよい: 最新はこのサーバーが書いた世代で、書いたときに覚えている（再起動後の最初の保存は全体なので、再起動前の世代が最新になることはない）
- **`baseOf` の忘れる規則**: `baseOf`（UUID → 世代 → 基準の世代）はファイルの頭の写し（キャッシュ）で、忘れても読み直すだけ。
  消せた世代（と、もうディスクにない世代）・`delete`・`assignNewId`（`claim` の新しい UUID を含む）・`write` での振り直しの元の UUID で忘れる。
  今の基準（状態）は、`delete` と振り直しでだけ変わる。ディスクに残るのは K と印より大きい世代とそれらが指す基準だけなので、UUID 1 つにつき数個で止まる

## 比べた案

- 変わった区画の見つけ方: (a) 書くたびに印を付ける（速い道に分岐が増える）、(b) 区画ごとのハッシュを覚えて比べる（全区画を読む。衝突すると黙って壊れる）、
  (c) 前回の中身を覚えて比べる（メモリが倍）。どれも採らなかった
- 圧縮方式（AGENTS.md の PoC の順: サーバーへの負荷 → 状態保存との相性 → 実装の単純さ → 速度）: zstd（`zstd-jni` はネイティブ、
  `aircompressor` は新しい実行時ライブラリで両接続層の `jarJar` が要る）は速度で勝つが、差分で 1 回に圧縮する量は小さく差は小さい。
  Deflate は依存が増えず、実装も単純

## コスト

- 横の表 `parked`（区画 1 つに参照 1 つ）と、読み取り専用の見え方のオブジェクト（全体保存で `parked` にした区画 1 つに 1 つ）
- 全体保存の後に初めて書く区画ごとに例外 1 回（ゼロの区画に初めて書くときと同じ）

## 申し送り

- #84: 差分は基準が書けた（fsync した）後に書き、書く待ちの差分が指す基準は消さない。`committed` は書けた後に呼ぶ。圧縮を書き込みのスレッドに移す
- #85: 差分の世代を戻すときは `MachineSaveStore.readGeneration` で基準を読み、確かめて合成する（上限は `MemoryAccount.limitPages`）。
  戻した後のプロセスの基準は `None` でよい。引き継ぐなら、基準の区画を `parkWritten` し差分の区画を書ける区画にして `Committed` にする
- #251: `fullSaveChangedRatio`（仮 0.5）
