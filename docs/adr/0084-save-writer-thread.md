# 0084: 保存の符号化・圧縮・書き込みを別のスレッドに移す

- 状態: 採用
- Issue: #84（task）。前提: ADR 0030（状態保存の PoC）、ADR 0081（待機点保存。世代のファイル・印・残す世代）、ADR 0082（節の中身）、ADR 0083（圧縮と差分の世代）
- 後続: #85（復元。下の申し送り）、#564（残ったディレクトリとモジュールの置き場の掃除）、#251（仮の値の確定）

## 決めたこと（要約）

1. **書き込みのスレッドはサーバーに1本**（`SaveWriter`。名前 `KiBi Computers save writer`、デーモン）。仕事は FIFO の1本の列に入り、同じ ID の順序は列の順で決まる。
   仕事には ID を持たせる（足りなくなったら ID で振り分けて本数を増やせる）。スレッドは台数に比例しない。待っている台のコストは増えない
2. **メインスレッドに残すのは、取り出し（カーネルロックの中のコピー）、世代の予約と持ち主・基準の確かめ（メモリだけ）、完了の受け取り、claim の `owner.bin` の書き込み（まれ）だけ。**
   区画の圧縮と ABI 層の符号化（`AbiPayload.encode`）、保存データの符号化、世代のファイルの書き込み（tmp → fsync → `ATOMIC_MOVE`）、新しく振った ID の `owner.bin`、
   古い世代の掃除（頭の読みを含む）、ディレクトリの削除は書き込みのスレッドで行う
3. **圧縮をカーネルロックの外に出す。** `SnapshotCapableDriver.capturePayload` は符号化を後でする `AbiPayload`（見積もり `estimatedBytes` と `encode()`）を返し、
   `KernelStateCopy.buildSnapshot`（書き込みのスレッド）で `encode` する。p1 は区画の写し・非同期スタック・待ちの写しを持ち、`encode` で `P1SectionCodec.write` を呼ぶ。
   方式・レベル・形式は変えない（Deflate、レベル 1）
4. **保存データの形式は変えない。** 変わるのは、NBT が指す世代とディスクの関係の規則（規則 4・9・10）だけ。世代の番号には欠番ができうる（失敗した予約）
5. **書き込み待ちのメモリに上限を置く**（`writerMaxPendingBytes`、仮 256 MiB）。台ごとに、取り出しの直前に「待ち中の見積もりの合計 < 上限」を見る
6. **自動保存の予算** `autosaveWritesPerTick` の意味を「tick ごとに書き込みに回す回数」にし、仮の値を 1 から 4 に上げる（メインスレッドのコストは取り出しだけ。確定は #251）
7. **CI の負荷試験は、壁時計の MSPT で見る**（ADR 0081 の「書き込みを除いた MSPT」をやめる。書き込みはメインスレッドの外になったため）

## 整合の規則（クラッシュしたとき）

1. 世代のファイル・`owner.bin` は、名前が見えた時点で中身が全部ある（tmp → fsync → `ATOMIC_MOVE`。#81 のまま）
2. **自動保存**: ケースの `identity`（NBT に書く世代）を進めて `setChanged` するのは、書き込みのスレッドで rename が終わったと分かってから。書き込み中にチャンクが保存されても、NBT は前の世代を指す
3. **停止**: `ServerStoppingEvent` で全台を取り出して書き込みに回した後、列が空になるまで待ち（`flush`。上限 `writerFlushMillis`、仮 30 秒）、終わった分を受け取って `identity` を進め `setChanged` してから、
   `ChunkUnloadDrain` と `saveAllChunks` に進む。`ServerStoppedEvent` でスレッドを閉じて join する（チャンクの保存が積んだ掃除を流すため。上限は同じ、超えたら warn）
4. **アンロード（`ChunkEvent.Unload`）だけは、書き込みの終わりを待たない。** 予約した世代を `identity` にして `setUnsaved(true)` を付ける（NBT は書き込み中の世代を指しうる）。
   自動保存の予約が書き込み中のときも、その予約の世代を採る。クラッシュ・書き込みの失敗で NBT の世代のファイルがないときは、規則 9 に落ちる
5. **FULL でなくなったチャンク（#545）**: 2. と同じく、終わってから `identity` を進め、チャンクに `setUnsaved(true)` を付ける。終わる前にアンロードが来たら 4.
6. **読み込み直し**: 世代のファイルを読む側（#85）は先に `awaitWrites(id)` でその ID の仕事を待つ。`claim` はメモリの `owners` を先に見る（予約の時点で入れる）
7. **同じ ID の仕事の順**: 世代の書き込み・新しい ID の `owner.bin`・掃除・ディレクトリの削除は、列に入れた順に走る。削除より前に入れた書き込みは削除より先に走り、削除で消える。
   「消した ID」の集合は持たない。走らせなかった仕事（閉じた後に入れた仕事、7b の後続）と仕事の中の例外は、すべて失敗の完了（`SaveCompletion`）で返す。
   完了が置き場の表（`latest`・`bases`・`baseOf`、`committed`）を進めるのは、その予約を作った登録（claim・`assignNewId` で作り、`delete` で消す内部の印）が今も同じときだけ
   - 7a. **claim の `owner.bin`**: その ID の仕事が列に残っていれば、ディスクの `owner.bin` を読む前と書く前に、その ID の仕事を待つ（上限 `writerFlushMillis`）。
     そのうえでメインスレッドで同期に書く（まれなので）。待ちが上限を過ぎたら、その ID は使わずに新しい ID を振る（`NEW_ID_UNREADABLE`、warn）
   - 7b. **新しく振った ID の `owner.bin` が書けなかったとき**: 書き込みのスレッドがその ID を「使えない」にし、後続の仕事は書かずに失敗で返す。メインスレッドは完了を受けて、
     `owners`・索引・登録・`reserved`・`inFlight` からその ID を外す。ケースは前の `identity` のままで、次の保存でまた振り直す
   - 7c. **書き込み中のケースの「今の ID」**は `currentIdentity = pendingSave?.identity ?: identity`。次の予約の `current`・削除・索引の外し・`plannedWrites` はこれを使う。
     新しい台の自動保存の書き込み中にアンロード・停止・破壊が来ても、2 つ目の ID を振らず、同じ ID の次の世代を予約し、削除・索引の外しもその ID に効く
8. **残った tmp**: 書き込みのスレッドが、このサーバーで初めて書くディレクトリで、書く前にそのディレクトリの `*.tmp` を消す
9. **戻す世代の選び方**: NBT の世代 G のファイルがあれば G。なければ、G より小さい世代のうちディスクにある最大のもの（warn）。それもなければ冷えた起動。
   G が差分の世代で基準が読めない・合わないときは冷えた起動（#85 で確かめる）。`MachineSaveStore.restorableGeneration`。ADR 0081 の「NBT が指す世代のファイルがなければ冷えた起動」を改める
10. **巻き戻しの世代を掃除で消さない**: 掃除の候補 K（今の印・前の印 2 つ・覚えている最新）のうち、ディスクにない世代 g があれば、g より小さい世代のうちディスクにある最大のもの
    （と、それが差分ならその基準）も残す
11. **書き込み待ちの世代と基準を消さない**: 掃除の keep に、予約して完了を受け取っていない世代（`inFlight`）と、それが差分なら指す基準を足す
12. **差分は基準が書けた後に書く**: 今の基準（`bases`）と `committed` は、全体の世代の書き込みの完了を受け取ったときに（メインスレッドで）進める。全体の書き込みが失敗したら、基準は変えない

## 完了の扱い

完了はメインスレッドで、毎 tick の始めに受け取る（`ServerMachines.processCompletions`）。書けた世代を `identity` に採るかは `adoptsCompletion(identity, currentIdentity, completed)` で決める。

1. 完了の ID が今の ID（`currentIdentity`）と違えば採らない（壊した・登録し直した後の遅れた完了など）
2. そうでなく、`identity` が null か、`identity` の ID が完了の ID と違えば（振り直し・新しい台の完了）**世代を比べずに採る**。振り直した ID は世代 1 から始まるため
3. 同じ ID なら、完了の世代が `identity` より大きいときだけ採る（規則 4 で後の世代を先に採った後の、遅れた先の完了は採らない）

書けなかったときは NBT を変えない（前の世代のまま。warn）。どちらでも、最後の予約の完了なら `pendingSave` を外す。消えたケースへの完了は数えるだけ。

| 失敗したもの | `owners`・登録・索引 | 世代の表 | ケース | 次の保存 |
| --- | --- | --- | --- | --- |
| 世代のファイル（符号化・圧縮の例外を含む） | 変えない | `latest`・`bases`・`committed` は進めない。`reserved` は戻さない（欠番） | `identity` は前のまま | 同じ ID の次の世代 |
| 新しく振った ID の `owner.bin`（7b） | その ID を外す | その ID の `reserved`・`inFlight` を消す。後続は失敗で返る | 前の `identity` のまま | 振り直す |
| claim の `owner.bin`（同期、7a） | 新しい ID にする（#81 のまま） | — | — | — |
| 掃除・ディレクトリの削除 | 変えない | 変えない | — | 影響なし（warn） |

## 世代の数え方

置き場は ID ごとに、予約した最大の世代 `reserved`、書けた最大の世代 `latest`、予約して完了を受け取っていない世代の集合 `inFlight` を持つ（どれもメインスレッドだけが触る）。

- 次の世代（`nextGeneration`）と持ち主の確かめは予約（`reserved`）で決める（自動保存の書き込み中にアンロードが来ても、同じ世代を二重に予約しない）
- 掃除の「覚えている最新」と差分の基準は完了（`latest`・`bases`）で決める（まだないファイルを指さない）
- 書き込みのスレッドとメインスレッドの両方が触るのは、ID ごとの未完了の数と、待ち中の見積もりの合計（`pendingBytes`）だけ。頭の写し `baseOf`・初めて書いたディレクトリの集合・「使えない ID」は書き込みのスレッドの持ち物

## メモリの上限

- `pendingBytes` は、予約で見積もり（`AbiPayload.estimatedBytes` と `/tmp` の中身のバイト数の和）を足し、書き込みのスレッドで仕事が終わった時点（成功・失敗のどちらでも）に引く。
  メインスレッドが上限を待っている間も減る
- 書き込みに回してよい条件は「`pendingBytes` < 上限」。**台ごとに、取り出しの直前に**見る。列が空なら必ず通る（1 台で上限を超える台も通る）
- **自動保存**: `AutosaveTarget.writeIfReady` が余地がなければ取り出さずに `NO_CAPACITY` を返し、`AutosaveRotation.tick` はその台と後ろの台を止めたまま次の tick に回す（予算は使わない）
- **アンロード・停止**: 延ばせないので、台ごとに取り出しの前に余地ができるまでメインスレッドで待つ。待ちの上限（`writerFlushMillis`）は、アンロードならそのチャンクの台すべてで、
  停止なら全台で**1つの期限を共有する**。過ぎたら warn を出して、残りの台は待たずに回す
- 期限を過ぎない限り、**待ち中の写しの合計は「上限 + 1 台の見積もり」以下**（期限を過ぎたアンロード・停止だけが例外）

## 比べた案

- **アンロードでも書き込みの終わりを待つ**: メインスレッドが fsync を待つので、#81 の測定（1 tick に 48 台で 1.1 秒）が解けない
- **アンロードでは NBT を前の世代のままにし、読み込みで新しい世代を採る**: NBT が指す世代と戻す世代が食い違い、印・epoch の規則を作り直すことになる
- **スレッドを台ごと・プールにする**: 同じ ID の順序を別に守る必要があり、台数に比例するスレッドは目標に反する
- **圧縮だけロックの中に残す**: 線形メモリの大きい台ほどロックを長く持つ
- **今の基準を予約の時点で覚える**: 全体の世代の CRC32C と長さは符号化の後にしか分からず、書けなかったときに存在しない基準を指す差分ができる
- **「消した ID」を覚えて、削除の後の書き込みを捨てる**: 同じ ID が claim で登録し直されたときに、正しい書き込みを黙って捨てる。FIFO の順で足りる
- **claim の `owner.bin` も列に入れる**: claim の結果が、`owner.bin` が書ける前に決まる。まれなので、その ID の列を待つ同期の書き込みの方が単純
- **書き込みが失敗したら、どれでも ID を振り直す**: 一時的な IO の失敗で自動保存のたびに UUID が変わり、古いディレクトリが孤立して差分の基準も失う
- **`pendingBytes` を完了の受け取りで減らす**: メインスレッドが上限を待つ間は減らず、止まったままになる
- **見積もりを足した後の合計で判定する**: 1 台で上限を超える台がいつまでも入れられない
- **メモリの上限を tick（チャンク）ごとに 1 回だけ見る**: 1 tick で予算の台数分が上限を超えて入り、「上限 + 1 台」が成り立たない
- **完了の世代を、ID にかかわらず `identity` の世代と比べる**: 振り直しの完了を採れず、自動保存のたびに新しい UUID のディレクトリが孤立する
- **`PendingSave.reassigned` で振り直しの完了を見分ける**: 振り直しの後の 2 回目の予約は `reassigned = false` になり、新 ID の世代 1 が失敗して世代 2 だけ成功したときに採れない
- **ID だけは予約の時点で `identity` に採る**: `owner.bin` が書ける前の UUID が NBT に載る窓ができる

## 失う場面

- アンロードの窓（規則 4）で予約した世代が書けなかった・クラッシュした: NBT は欠番を指し、読むときに直下の世代に戻る（規則 9・10）
- そのうち、新しく振った ID の `owner.bin` だけが書けなかった（7b）: NBT が `owner.bin` のない ID を指して保存される。読むと戻す世代がなく冷えた起動になる。
  新しい台には戻す前の状態がないので、同期で書いていたときと結果は変わらない。振り直しでこれが起きると元の ID の世代へは戻れない

## コスト

- 書き込みのスレッド 1 本（仕事がなければ寝ている）
- 書き込み待ちの写し（上限 + 1 台。仮 256 MiB）
- 予約ごとの小さな表の項（`reserved`・`inFlight`・未完了の数）
