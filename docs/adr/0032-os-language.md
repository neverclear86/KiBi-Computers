# 0032: 標準 OS の実装言語

- 状態: 採用
- Issue: #32（PoC）。結果を使うのは #98（標準 OS のソース構成とビルド）と、その上のシェル・コマンド（#100〜#112）
- 番号は Issue 番号にそろえている

## 背景

標準 OS（init、シェル、基本コマンドなど）を WASM で書く言語を、Zig と MoonBit で比べた。オーナーは「パフォーマンスで大きな不利がなければ MoonBit を使いたい」としていたが、最後の判断では好みを外し、次の2つの観点で比べた。

1. 軽量で、プレイ体験を損なわない（ゲームの中の速さは燃料で決まる。#28）
2. 今後の開発で負債にならない

測定の詳細は `poc/os-language/results.md`。同じ振る舞いの echo・cat・ls・shell・kmem を両方の言語で書き、カーネルの上（待機点型・RAM の数え方）と最小の WASI ホストの上（燃料・時間）で測った。

## 測定の要点

- #424（SIMD の関数だけをインタプリタに回す）と #425（multi-value のブロックの待機点への変換）の後は、MoonBit も Endive のランタイムコンパイラで動き、すべて待機点型になる。サーバーへの負荷と状態保存では差がない
- 残る差は燃料。素直な MoonBit は Zig の 4〜6 倍（shell 2,000 行で 4.5 倍、ls 200 ファイルで 6.5 倍）
- 原因は MoonBit のコンパイラ（moonc）の最適化の弱さ:
  - 範囲検査を `array_length`・`check_range` の関数呼び出しで出し、インライン化しない（`buf[i]` 1 回で約 23 命令。shell の燃料の約 27%）
  - 写しの伝播や小さな関数のインライン化をしない（同じソースに wasm-opt `-O3` をかけるだけで 2〜3 割減る）
  - 語ごとのタプル・Option の確保（shell の約 11%）、起動時のアロケーターの初期化（1 プロセス約 1 万）
- 書き方（確保をやめる、`blit_to`、ビューの for-in）と wasm-opt `-O3` で、shell は 1.47 倍まで縮む。ls は自然な書き方で 2.46 倍が最良で、2 倍に入るのは C に近い書き方だけ
- 大きさは 1 コマンド約 8 KB（Zig の約 8 倍）、shell が入力を待つまでに書き換える RAM は 20 KiB（Zig は 4 KiB）

## 決定

**Zig にする。**

1. 軽量・プレイ体験: Zig は何もしなくても燃料・大きさ・RAM・起動が最小。MoonBit は書き方の規約と `-O3` を守り続けて、ようやく 1.5〜2.5 倍に収まり、規約を外れるとすぐ 4〜6 倍に戻る
2. 負債: Zig はすでにリポジトリのツールチェーン（#9。Lua のビルドとテスト用の WASM）で、手元でもエージェントの環境でもビルドできる。MoonBit は 0.10 系と若く、速さが moonc の癖に左右され、この環境では手元でビルドできない（CI の往復が要る）。ツールチェーンも2つになる

Zig の弱い点（1.0 前で版ごとに標準ライブラリが変わる、メモリを手で管理する）は、版の固定（`gradle/zig.properties`）と、WASM の中で壊れても影響がそのプロセスに閉じることで受け止める。

ほかに Rust・C・TinyGo・AssemblyScript・Lua・Emela も机上で比べた。Rust は燃料と負債では有力だが、1 コマンドの大きさ（数 KB〜数十 KB）と、ツールチェーンが増えることから、測らずに見送った。

## PoC の扱い

- MoonBit のビルド（`gradle/moonbit.properties`、`kibiWasm.moonbit`）と比較用のソースは、記録として `poc/os-language/` に残す。`-Pkibi.moonbit=true` のときだけビルドし、CI ではビルドしない
- 関数ごとの燃料の計測（`Profiler.kt`）は、OS のコマンドの燃料を調べるときに使える

## 考え直す条件

- MoonBit のコンパイラが、範囲検査のインライン化と写しの伝播をするようになり、素直な書き方で Zig の 2 倍以内に入ったとき
- Zig の版の変更が、OS の保守の負担になりすぎたとき
