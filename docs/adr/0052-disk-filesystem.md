# 0052: ホストのディレクトリを背面にしたディスク FS と、VFS をカーネルロックの外で使う決まり

- 状態: 採用
- Issue: #52（task）。前提: ADR 0051（VFS の中核）、0053（`/tmp`）、0070・0071（WASI p1 の fd・path）
- 後続: #124（ディスクの識別子・ワールドフォルダの中の置き場所・ディスクの種類ごとの容量）、#56（抜き差しと `/mnt`）、#82（開いたファイルの保存と復元）、#251（容量・上限の確定値）
- 方針はオーナーの回答（Issue #52、2026-11-05）による: **CC: Tweaked と同じ仕様**。ホストのファイルを正とし、書いたらその場でホストに書く。ディスクの中は普通のファイルだけ

## 決めたこと（要約）

- `DiskFileSystem`（`core.kernel.vfs`。`internal`）が、ホストのディレクトリ1つをそのまま FS として見せる。中身のキャッシュも、ワールドの保存との同期もない。管理用のファイルは置かない
- **カーネルロックの中は µs 単位にし、I/O は置かない。** そのため VFS（`Vfs`）の、FS に届く操作はすべてカーネルロックの外で呼ぶ形に変えた（下の「VFS とカーネルロック」）
- ホストの I/O は、プロセスのスレッド（CPU と許可は持ったまま、カーネルロックは持たずに）と起動用のスレッドで同期に行う。I/O 用のスレッドと完了オブジェクト（#358）は使わない
- ホストのファイルは、fd で開いている間だけ開いたままにする（CC と同じ）。数はマシンごと（128）とサーバー全体（2,048）の枠で数え、超えたら `MFILE`・`NFILE`（仮の値。確定は #251）
- 名前の規則は OS によらず同じ（CC より厳しい）。Windows で使えない名前は `INVAL`、大文字小文字だけ違う名前は同じ名前
- 公開 API・ABI・保存形式は変えない（新しいシステムコール・errno はない。マシンの保存に何を持たせるかは #82）

## VFS とカーネルロック

ホストの I/O は ms かかることがあり、カーネルロックを持ったまま行うと、1台の遅い I/O がメインスレッドの tick、共有のタイマー・ディスパッチャー、ほかの計算を待たせる。そこで:

- `FileSystem` は、カーネルロックの**外**で、同じマシンのいくつものスレッドから同時に呼ばれる。FS が自分で排他する（`TmpFileSystem`・テストの FS は `@Synchronized`、`ImageFileSystem` は変わらないので要らない、`DiskFileSystem` はリースの I/O のロック）
- カーネルロックの中から呼ばれるのは、I/O をしない `sizeHint`（`poll` の `nbytes`）・`revoke`（停止）・`onUnmounted` だけ
- `Vfs` は、FS に届く唯一の口（`locate`・`fsOf`・マウントの根の `stat`）で、カーネルロックを持っていないことを確かめる（持っていれば `IllegalStateException`）。マシンの `Vfs` は `lock::isHeldByCurrentThread` を受け取る
- マウントの表を変える操作（`mountLocked`・`unmount`・`attach`・`revokeAll`）はロックの中。変えるたびに表と FS の写しを作り直して `@Volatile` で公開し、パスの操作はその写しだけを見る
- マウントは「ロックの外で位置を確かめる（`checkMountPoint`。下の FS の `stat`）→ ロックの中で表を変える（`mountLocked`。FS を呼ばない）」の2段。確かめてからの間に位置が変わることは防がない（マウントすれば、その位置はマウントの根として見えるので壊れない）。4 引数の `mount` は両方をまとめた口（マシンを使わないテスト用）
- `OpenFile.position` は、fd から使うものはロックの中でだけ読み書きする。読み書きは「ロックの中で位置を読む → ロックの外で `pread`・`pwrite` → ロックの中で位置を進める」（`FdIo.read`・`write`）
- 位置を使う fd の読み書きと `fd_seek` は、開いたファイルごとのロック（`OpenFile.withPositionLock`。開いたファイルのモニター）で1本ずつにする（#431。Linux の `f_pos` のロックと同じ）。ないと、同じ開いたファイルを分け合う2つのスレッド（親と子が、受け継いだ stdout を append でないファイルにリダイレクトしたときなど）が同じ位置を読んで、互いのバイトを上書きする。順番は「開いたファイルのロック → カーネルロック」で、カーネルロックを持ったまま開いたファイルのロックを取らない。待つのは同じ開いたファイルを使うスレッドどうしだけで、ほかの台・ほかのファイルには広がらない。読みも同じロックに入れる（読みが位置を進めるときに、同時の書き込みが進めた位置を巻き戻さないため。同じ範囲を二度読むこともなくなる）。`pread`・`pwrite`（位置を渡すもの）は位置を使わないので、ロックを取らない
- `/tmp`（`TmpFileSystem`）は、外したら（`onUnmounted`）この後の操作をすべて `IO` にする（#432）。外す前に場所を見つけたスレッドが外した後に作る・書くと、RAM を確保したまま返す時がなくなるため（ディスクの `revoked` と同じ）
- 開いたファイルの数の上限（`MFILE`・`NFILE`）で open が失敗するときは、ファイルを作らず、切り詰めもしない（#434）。`O_CREAT` で作る前に枠を取り（`FileSystem.reserveOpen`。作れなければ `cancelOpen` で返す。取った枠は `retain(node, writable, reserved = true)` が引き受ける）、あるファイルは開いたことを知らせて（`retain`）から切り詰める
- WASI p1 の `fd_*`・`path_*` は、ロックの中で fd（基点のディレクトリ）を引くだけにし、VFS はロックの外で呼ぶ。`spawn` の作業ディレクトリ・preopen、`exec` の実行ファイルの読み込み、`changeDirectory` の確かめもロックの外（作業ディレクトリ・preopen を指定する `spawn` は、ロックを持たずに呼ぶ）

### ロックの外に出すと競合する複合操作

| 操作 | 直し方 |
| --- | --- |
| `O_CREAT`（`O_EXCL` なし）の「なければ作る」 | `createFile` が `EXIST` なら引き直して、あるものを開く（最大 8 回） |
| `O_TRUNC`、パスの `setTimes` | 間に置き換えられて `STALE` なら引き直す |
| 追記 | FS の `append`（大きさを読んで書くまでを不可分に） |
| `fd_allocate` | FS の `allocate`（伸ばすだけ。不可分に） |
| `path_rename` の末尾の `/` | FS の `rename(requireDirectory)`（確かめと名前の変更を FS の中で不可分に） |
| `path_unlink_file` の末尾の `/` | どちらにしても失敗するので、FS の削除を呼ばない |
| `path_open` の `MFILE` | ロックの中で満杯か見る → 外で開く → 中で fd に入れる。fd の表を変えるのはそのプロセスのスレッドだけなので、間に満杯にならない |
| `seek(END)`、`fd_readdir`、`stat` など | 読むだけ。それぞれの時点の結果を返す（POSIX でも同じ競合がある） |

### 閉じたファイルの知らせ

- `FileSystem.tracksOpenFiles` の FS（ディスク）は、普通のファイルを開いたら `retain(node, writable)`、最後の参照が外れたら `release(node)` で知らされる。外した・止めた後は `retire()` でホストの資源を閉じる
- 最後の参照が外れるのはカーネルロックの中（`ObjectTable.release` → `OpenFile.onLastClose` → `WakeSink.fileClosed`）なので、`Vfs.releaseLater` で積み、ロックの外で行う。マシンは積まれたら起動用のスレッドに1つだけ仕事を積み（`Machine.scheduleVfsDrain`）、FS に届く操作の始めでも行う
- 復元した開いたファイル（`OpenFile.retained` は実行時だけの印で保存しない）は知らせないまま使う。FS は、開いていない node の操作もその都度開いて受け付ける

## ディスク FS（`DiskFileSystem`）

### ホストの上の形

- ディスクのディレクトリには、普通のファイルとディレクトリだけを置く。名前はゲームの中の名前のまま。管理用のファイルはない
- node はマウントのたびに 1（根）から、初めて見たときに割り当てる（使い回さない）。名前を変えたら、その下の木ごと付け替える（node は変わらない）。外で消されたら `STALE`
- 開いたファイルの node → パスは `pathOf` で引ける（#82 の保存で使う。ADR 0051 の「node は保存と復元をまたいで同じファイル」は、パスで引き直してそちらで満たす）
- 時刻はホストの属性。ctime は mtime と同じ（Java の基本属性に ctime がない）

### 容量

- 使用量 = 普通のファイルの大きさの合計 ＋ 項目（ファイル・ディレクトリ。根は除く）1つあたり 256 バイト。項目の数も数える
- 仮の値: 1 ディスク 2 MiB・4,096 項目（`MachineLimits.DISK_CAPACITY_BYTES`・`DISK_MAX_ENTRIES`。ディスクの種類ごとの値は #124 で渡す。確定は #251）
- マウントのときに木をたどって数え直し、その後はメモリ上の数で管理する。外での変更は次のマウントまで数に入らないことがある（CC と同じ）
- 数え直しも、一覧・引くときと同じ規則（名前の順で最初の見せるもの）で数え、見せないもの（使えない名前、リンクなど、大文字小文字だけ違う名前で隠れた側）の下はたどらない（#607）。ディレクトリごとに名前を並べ、明示的なスタックでたどる（深い木でもスタックがあふれない）。名前と属性は、ディレクトリごとに深さ1の `Files.walkFileTree` で集める（Windows のホストでは列挙で得た属性をそのまま使え、項目ごとに属性を読み直すより約 20 倍速い）。読めないディレクトリはその下を数えずに続け、マウントを失敗させない
- 使用量を減らす操作（消す・名前の変更で置き換える・縮める `setSize`・書き込みの後の大きさの差）は、バイトも項目数も 0 で止める。マウントの後に外で置かれたものや、隠れていて数えていなかった大文字小文字違いが見えるようになったものを消す・縮めると、数えていない分を引くことになるため（#607）
- 上限を超える書き込みは、入る分だけ書く短い書き込み。1バイトも入らなければ `NOSPC`。`allocate`・伸ばす `setSize` は全部入らなければ `NOSPC`。作成は項目数か 256 バイトが足りなければ `NOSPC`。外で上限を超えて置かれていても読め、伸ばさない上書きはできる

### 名前（OS によらず同じ。CC より厳しい）

- `INVAL`（作る・名前を変える先）: Windows の予約名（`CON`・`PRN`・`AUX`・`NUL`・`COM0`〜`COM9`・`LPT0`〜`LPT9`、上付きの `¹²³` も、`CONIN$`・`CONOUT$`・`CLOCK$`。大文字小文字によらず、拡張子付き・拡張子の前の空白付きも）、使えない文字（`< > : " \ | ? *`、U+0000〜U+001F）、末尾の `.`・空白、Windows の 8.3 形式の短い名前の形（#433）
  - 8.3 の形: 最初の `.` の前が 2〜8 文字で `~` と1つ以上の数字で終わり、その後は無いか、`.` と 3 文字以下（`.` を含まない）。大文字小文字によらない。例: `ABCDEF~1`・`ab12~1.txt`・`~1`。`foo~bar`・`abcdefghi~1`・`a~1.html` は使える
  - 理由: Windows では、この形の名前が長い名前のファイルの別名として当たる（`abcdefghij.txt` の `ABCDEF~1.TXT`）。作成の先にすると衝突し、置き換えの move の先にすると別名の先の長い名前のファイルが消えうる。Linux ではそのまま作れる。どの OS でも同じにするには、この形をどこでも使えない名前にするしかない
  - `CONFIG$`・`KEYBD$`・`SCREEN$`・`$IDLE$` などの古い DOS の装置名は入れない（今の Windows では予約されていない。広げるほど、既存のファイルが見えなくなる）
  - 今のディスク（Linux のサーバー）にこれらの名前のファイルがあれば、見えなくなり、使用量にも数えなくなる。v0.0.x でリリース前なので受け入れる
- 引くときは、そういう名前は `NOENT`（ホストに渡さない）。一覧に出さない
- 大文字小文字: 1文字ずつ `Character.toUpperCase` でそろえて比べる。違いは保つ（作った名前のまま置く）。そろえて同じ名前があれば作成は `EXIST`、名前の変更は置き換え。大文字小文字だけの名前の変更（`a` → `A`）は、一度別の名前を通して行う。外から大文字小文字だけ違う名前が2つ置かれたら（Linux）、名前の順で先のものだけを見せる
- **引くときと一覧は同じ規則で選ぶ（#433）**: ホストの名前の一覧から、そろえると同じ名前を候補にし、名前の順（UTF-16 の順。`A` が `a` より先）で最初の「見せるもの」（使える名前の、普通のファイル・ディレクトリ）を選ぶ。返す名前と属性は同じ項目のもの（Linux で `a` がディレクトリ・`A` がファイルなら、`/a` は `A` のファイル。`A` がシンボリックリンクなら `a`）
  - 引くときに属性を読むのは候補だけ（ふつうは1つ）。1段あたりのホストの I/O は「名前の一覧1回＋属性1回」で、項目ごとの属性は読まない。1,000 項目のディレクトリの下のファイルの `stat` は、手元の Windows で 1回 34 ms → 0.85 ms
  - 完全に同じ名前があっても一覧は省けない。Linux では大文字小文字違いが並ぶことがあり、名前の順で先のものを選ぶには一覧が要る。Windows・macOS では完全一致の属性の読み取りが、違う大文字小文字や 8.3 の別名にも当たり、実際の名前は一覧でしか分からない（一覧は長い名前しか返さないので、8.3 の別名は候補に出ない）
  - 一覧のキャッシュ（ディレクトリの mtime で見るなど）は採らない。時刻の粒度で外の変更を見落とし（「外で編集したものはすぐに見える」に反する）、1,000 台でヒープも使う。`toRealPath` で実際の名前を取る形も採らない（根までの全段をたどる）
- macOS の Unicode の正規化（NFD）は扱わない

### シンボリックリンクとパスのサニタイズ

- `VfsPath` は正規化済み（`..` なし）で、名前の検査で `\`・`:` を落とすので、文字列としてディスクのディレクトリの外は指せない
- ホストのものは `NOFOLLOW_LINKS` で属性を読み、普通のファイル・ディレクトリ以外（シンボリックリンク、ジャンクション、デバイスなど）は無いものとして扱う。パスは根から1段ずつ確かめるので、途中にリンクを置かれても外へ出ない。開くときも `NOFOLLOW_LINKS`

### 開いたままのホストのファイル

- `retain` で `FileChannel` を開き（書くために開いたなら読み書き、ほかは読むだけ）、同じ node は1つを参照の数で分け合う。`release` で数が 0 になったら閉じる。開いていない node の読み書きは、その都度開いて閉じる
- 数は `HostFileBudget`（マシンごとに1つ、サーバー全体の数と一緒に数える）。マシン 128・全体 2,048 を超えたら `MFILE`・`NFILE`（仮の値）。待っているだけの台は、fd を開いていなければ何も持たない
- `FileChannel` は Windows でも削除の共有（`FILE_SHARE_DELETE`）付きで開くので、開いたままのファイルを外のエディタが置き換え（別のファイルに書いて名前を変える）で保存でき、外から消すこともできる
- **外で置き換えられたファイルを見分ける。** 開いたままのものを使う前に、パスの属性と、開いたときに記録した値（POSIX は `fileKey`、ない環境＝Windows は作成時刻と大きさ）を比べ、違えば開き直す。開いたままの fd からも、外で保存した新しい中身が見える（ホストのファイルが正）。Windows のトンネリングで作成時刻が引き継がれ、大きさも同じだった置き換えは見分けられず、その fd を閉じるまで古い中身を読むことがある
- 属性を読んでから読み書きするまでの間（µs）に外で置き換えられると、その1回は古いファイルに対して行われる。外のプログラムとの排他はない（CC と同じ）

### 排他とリース（持ち主の世代）

- `HostDiskLeases`: ホストのディレクトリ（`toRealPath`）ごとに1つのリース（世代と I/O の `ReentrantLock`）。`DiskFileSystem.open` が世代を進める。ホストに触る操作は、このロックを取ってから「世代が自分のものか、止められていないか」を確かめ、違えば `IO`
- 電源を切ってすぐ入れたとき・別の台へ挿し替えたときに、止まり切っていない古いカーネルの I/O は、新しい世代の最初の操作より先に終わる（同じロックで直列）
- 1つのディスクの I/O はこのロックで1本ずつ行う。待つのは同じディスクを使うスレッドどうしだけ。複合操作（作成の「名前があるか → 作る」、追記、`allocate`、`rename(requireDirectory)`）は、このロックの中で不可分になる
- 停止（`Machine.stopLocked` → `Vfs.revokeAll`）と外す（`onUnmounted`）は、印を付けるだけで I/O をしない。開いたままのファイルは `retire` が、ロックの外で閉じる。起動で選ばなかった候補のディスクも閉じる
- **取り消された開き手は世代を進めない（#588）**: 起動の手順（`BootSequence.findBootVolume`・`mountHome`）と復元の前段（`MachineRestore.openMounts`）は「取り消しを確かめる → ロックなしで開く」の形で、確かめた後・開く前に止まった古い手順が、後から新しいマシンの世代を追い越して締め出すことがありえた（世代は戻らないので、新しいマシンのディスクが以後ずっと `IO`）。そこで、開き手は自分の取り消しの確かめを `BootVolumeOpener.open(diskId, cancelled)` → `DiskFileSystem.open(..., cancelled)` → `HostDiskLeases.acquire(root, cancelled)` に渡し、`acquire` は **このロックの中で、世代を進める直前に** それを見る。真なら世代を進めず、取った分（`users`）を返して `DiskOpenCancelledException` を投げる。呼び手は開けなかったとき、まず自分の取り消しを確かめ、取り消されていれば失敗に流さずに黙って抜ける（`mountHome` は `/home not mounted` を書かない、復元の `openMounts` は冷えた起動の `MOUNT` にしない。起動の候補を探す `findBootVolume` は、次の周の頭の確かめと、取り消されていれば失敗を知らせない `endBoot` で同じになるので、専用の確かめは置かない）
  - 確かめは volatile を読むだけ（起動は `Machine.isBootCancelled`、復元は `Machine.isRestoreCancelled`）。カーネルロックを取らない（このロックの中でカーネルロックを取らない規則のまま）。足す負荷は、開くときに volatile を1回読むことだけ
  - 正しさは次の順序に乗る: **古い台の取り消しの印が立つ（`stopLocked`）→ 新しい台がディスクを開く（`boot`・`restore` の手順）**。新しい台が世代を進めるのはこのロックの中なので、古い台がその後でこのロックを取れば、必ず取り消しが見える（印 → 新しい台の `acquire` のロックと unlock → 古い台の lock の happens-before）。古い台が取り消しより前に開いたなら、それは新しい台より前なので、新しい台が勝つ。新しい台に一瞬も `IO` は見えない。基準は新しい台の「作成」ではなく「ディスクを開く」ことで、呼び手（接続層）の規則は「古い台を止めてから、新しい台の `boot`・`restore` を呼ぶ」である。`MachineManager.attach` の置き換えは、新しい台を作ってから古い台を止める（`createMachine` → `stopEntry`）が、新しい台の `boot`・`restore` は `attach` が返った後なので、この順序は崩れない
  - 「開いた後に取り消しを見て、世代を戻す」形は採らない。戻すまでの間、新しい台の操作（起動の `init` の確かめを含む）が `IO` になり、戻してよい相手（3つ目の開き手がいないか）も見分けられないため。古い手順が終わるのを新しい台の起動用のスレッドで待つ形も採らない（起動用のスレッドは `maxConcurrentMachines` 本しかない）
  - 同じディスクの複製を2台で同時に使っているとき（どちらも取り消されていない）は、今までどおり後から開いた側が勝つ
  - 将来の注意: アンロードの間の休止（#132）などで、古い台を止める前に新しい台がディスクを開く形になると、上の順序が崩れる（古い台の印がまだ立っていないので、古い台が後から世代を進められる）。抜き差し・ランタイムのマウント（#56）で別の口からディスクを開くときも、同じ取り消しの確かめを `cancelled` で渡す（#56 で実装。予約 `DiskClaim` の取り消しを渡す。ADR 0056）

### 割り込み

- 停止とシグナルは、プロセスのスレッドを `Thread.interrupt()` で起こす。`FileChannel` は割り込まれると閉じる
- 割り込まれたスレッドの操作は、開いたままのチャンネルに触る前に `IO` にする（同じマシンのほかのプロセスと分け合うチャンネルを閉じないように）。操作の途中で割り込まれて閉じたときは、ほかのスレッドの次の操作が開き直す

### 名前の変更（#433）

- 自分の下へ移すかは、解決した結果を大文字小文字をそろえた鍵で比べる（`/d` → `/D/x` も `INVAL`。ホストには触らない）。`Vfs.rename` の自分の下へ移すかの確かめ（`to.startsWith(from)`）は大文字小文字を区別したまま（`/tmp` などは区別するので、FS に任せる）。マウントに関わる確かめ（マウントの位置かその祖先なら `BUSY`、またげば `XDEV`）は、ADR 0051 の規則で、ディスクの中では区別せずに比べる（#606）
- ホストの操作を先に済ませ、node の表と使用量は最後に直す。途中で失敗しても、表と使用量がホストと食い違わない
- 置き換え先がなければ、置き換えない move。こちらの規則では無くても、ホストに見せていないもの（シンボリックリンク、使えない名前、Linux の大文字小文字違い）があれば `EXIST`（外のものを消さない）
- ファイルの置き換えは、置き換え先の実際の名前への `ATOMIC_MOVE` の1手（POSIX は `rename(2)`、Windows は `MoveFileEx(MOVEFILE_REPLACE_EXISTING)`）。`REPLACE_EXISTING` だけの move は先に置き換え先を消すので、移すのに失敗すると置き換え先が消える
- 空のディレクトリの置き換えは、Windows が既存のディレクトリへの置き換えをできないので、どの OS でも「古いものを一時的な名前へ退かす → 移す → 退かしたものを消す」。移すのに失敗したら、退かしたものを戻す。退かしたものを消せなければ、空のディレクトリが残る（置き換えは成功。残ったものは見える項目なので、使用量には数えたままにする）。戻せなければ、退かしたものの表を一時的な名前へ付け替えて失敗にする
- 置き換え先の大文字小文字が違えば（`Foo` を `foo` で置き換える）、置き換えてから大文字小文字だけの変更をする。それに失敗しても置き換えは済んでいるので、元の大文字小文字へ戻せたなら古い大文字小文字のまま成功にする（そろえれば同じ名前）。戻すのにも失敗して一時的な名前に残ったときは、表をその名前に付け替えて失敗にする
- 大文字小文字だけの変更は一時的な名前（`.kibi-rename-*`）を通す。2手目は置き換えない（Linux で、見せていない大文字小文字違いが外から置かれていれば失敗する）。2手目が失敗したら元の名前へ戻し、操作は失敗にする

### エラーの対応

`NoSuchFileException` → `NOENT`、`FileAlreadyExistsException` → `EXIST`、`DirectoryNotEmptyException` → `NOTEMPTY`、`NotDirectoryException` → `NOTDIR`、`AccessDeniedException` → `ACCES`、書けないチャンネル → `ACCES`、ほかの `IOException` → `IO`。置き換えの規則（`ISDIR`・`NOTDIR`・`NOTEMPTY`、根は `BUSY`）は `TmpFileSystem` と同じで、ホストに渡す前に自分で確かめる

## 起動ディスクとしての接続

- `BootVolumeOpener.forDisks(disks, budget)`: `image:` の識別子は同梱イメージ、ほかは `MachineEnvironment.disks`（`DiskResolver`）が返すディレクトリを `DiskFileSystem` として開く（なければ作る）。起動の手順の既定はこれ。取り消しを見る形 `open(diskId, cancelled)` で呼ぶと、取り消された開き手は世代を進めずに `null` を返す（上の「排他とリース」。#588）。差し替えの口（テスト）は `open(diskId)` だけを実装すればよい（既定の `open(diskId, cancelled)` は取り消しを見ずに `open(diskId)` を呼ぶ）
- 接続層（`platform-*`）は変えない。ディスクの識別子とワールドフォルダの中の置き場所は #124、抜き差しは #56

## 採らなかったもの

- **マウントのときに中身をメモリに読み込む**: 1,000 台・大きなディスクでヒープを大きく使う（オーナーの回答）
- **I/O 用のスレッド＋完了オブジェクト（#358）**: p1 の path・fd のすべての呼び出しを止まりうる import（asyncify の巻き戻し）にする必要があり、1回のシステムコールの費用が大きく、変更も広い。ローカルのディスクの I/O は µs〜ms で、CC も計算のスレッドで同期に行っている
- **ハンドルの置き場（LRU）と後片付けのスレッド**: 世代をまたぐ鍵、閉じている途中のハンドル、Windows の共有違反などの扱いが複雑になる（Issue #52 のプランのレビュー）。fd を開いている間だけ持つ形（CC と同じ）にした
- **`RandomAccessFile`**: 割り込みでは閉じないが、Windows で削除の共有を付けて開けず、開いている間は外で保存・削除できない
