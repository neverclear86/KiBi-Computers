# 0105: 標準 OS のエディタ（nano 相当）

- 状態: 採用
- Issue: #105（task。Epic #97）。前提: ADR 0098（標準 OS のビルドと `kibi` ライブラリ）、0060（TTY）、0061（端末の解釈。対応範囲は `docs/terminal.md`）、0427（`kibi:io/tty`）、0071（`path_rename`）
- 番号は Issue 番号にそろえている

## 決めたこと（要約）

- `/bin/nano`（`os/bin/nano.zig` と `os/bin/nano/`）。`nano [+行[,桁]] [ファイル]`。Lua をその場で書く・直すための、小さな nano 風のエディタ
- 使うのは既存の import だけ（p1 の fd・path、`kibi:io/tty`、`kibi:computer/memory`）。新しいシステムコール・保存形式・公開 API は足していない
- 画面は nano と同じ形: 1 行目がタイトル（反転）、本文、状態の行、いちばん下の 2 行がキーの案内（初心者向け。Issue の要件）
- 案内・知らせの言葉は、ほかのコマンドの知らせにそろえて英語（nano と同じ言葉を使う）
- テキストはバイト列のまま持ち、表示のときだけ解釈する。編集していないバイトは、保存しても 1 バイトも変えない。末尾に改行を足さない
- 待っている間は標準入力の読み込み（待機点）で止まるだけ。時計・`poll_oneoff` のタイムアウトでは起きない
  - 追記（#87）: 標準入力と「保存から戻った」のキューを `poll_oneoff`（fd 2つ、時計なし）で待つようにした。時計では起きないのは変わらない
- vi（#104）でも使う部品を `kibi` ライブラリに足した: `text`（厳しい UTF-8 の読み方と文字の幅）、`keys`（キーの読み方）

## 起動と終わり

1. 引数を読む。`+行[,桁]`、`--`、`-h`/`--help`。ファイルが 2 つ以上・知らないオプションは使い方の誤り（2）
2. 標準入力・標準出力の両方が TTY でなければ、知らせて 1
3. ファイルを全部読む。ない名前は新しいファイル（保存するときに作る）。ディレクトリ・大きすぎる（下の「上限」）・RAM が足りない・読めないときは、**画面を切り替える前に**標準エラー出力に知らせて 1（途中まで読んだものは開かない。保存で切り詰めないため）
4. 元のモードを覚えて raw（出力の LF → CR LF だけ残す。シェルの行の編集と同じ）にし、`CSI ?1049h`（代替画面）・`CSI ?7l`（折り返さない）で描く
5. 終わるときは `CSI r`・`CSI 0m`・`CSI ?7h`・`CSI ?25h`・`CSI ?1049l` を送ってから、元のモードに戻す（1049 はカーソルしか戻さない。ADR 0061）。`defer` でまとめ、どの道で抜けても通る
6. 入力が終わった（TTY が閉じた）ときは、変更があれば `<名前>.save`（名前がなければ `nano.save`）に書いて終わる

## キー

並びは xterm 形式（core の `TerminalKeyEncoder`）。`^` は Ctrl、`M-` は Alt（Alt を押しながら打つ。Esc を押してから別にキーを打っても M- にはならない。素の Esc を別のキーと見るため。下の「素の Esc の見分け方」）。

| キー | 動き |
| --- | --- |
| ^G・F1 | ヘルプ（上下・PgUp・PgDn・^Y で送る。^X・^G・^C・Esc・q・Enter で戻る） |
| ^X | 終わる。変更があれば `Save modified buffer?` を聞く（Y・N・^C）。Y で名前がなければ名前を聞く。保存に失敗したら終わらない |
| ^O | 名前を聞いて書き出す（今の名前が初めの値）。別の名前で、そのファイルがあれば上書きしてよいか聞く |
| ^S | 今の名前で保存（名前がなければ ^O と同じ） |
| ^W | 後ろに探す（終わりまでなければ頭から。ASCII の大文字・小文字は区別しない）。空の入力は前の語 |
| M-W | 前の語で次を探す |
| ^K | カーソルの行を切り取る。続けて押すと切り取ったものに足していく |
| ^U | 切り取ったものを貼り付ける |
| ^_・M-G | 行へ移る（`行[,桁]`。桁は表示の桁） |
| ^C | 位置を出す（行・桁・バイト） |
| 矢印・^F ^B ^P ^N | 動く。上下は前に居た表示の桁を目指す |
| Home・^A / End・^E | 行の頭 / 終わり |
| PgUp・^Y / PgDn | 前 / 次のページ（本文の行数 − 2 行。画面ごと動かす） |
| M-\\・Ctrl+Home / M-/・Ctrl+End | テキストの頭 / 終わり |
| Backspace（DEL・^H） | 前の文字を消す（行の頭なら前の行とつなぐ） |
| Delete・^D | カーソルの文字を消す |
| Enter（CR）・^J（LF） | 改行を入れる（貼り付けの LF は CR で届くので、どちらも同じ） |
| Tab | タブを入れる |
| ほかの制御文字 | `Unbound key` と出して何もしない（raw では ^Z・^Q などもただのバイトで届く。ADR 0060） |

nano から変えたところ:

- ^V（次のページ）はクライアントが貼り付けに使うので届かない（`KeyboardInputScreen`）。案内には PgDn を出し、^V は届いたときだけ次のページにする
- 素の Esc に大事な機能を割り当てない。1 tick にまとめて届いたキーはつながって見え、Esc の後に速く打った x が M-x に見えるため
- 自動の字下げはしない（nano の既定もしない）。端末に貼り付けの目印（bracketed paste）がなく、貼り付けた Lua の字下げが二重になるため

### 素の Esc の見分け方

1 つのキーのバイト列は、1 回の入力として TTY に入る（`KeyboardDevice.input`）。そのため、読んだかたまりの最後が ESC なら素の Esc と見て、続きを待たない。
かたまりがエスケープシーケンス・UTF-8 の途中で切れていたら（読む領域 4 KiB が埋まったときだけ起こる）、続きを読んでからつなぐ。

## 表示

- 行ごとに中身を作って FNV-1a のハッシュを取り、前に描いたものと違う行だけを書く。キーごとに全画面を書かない（ADR 0031 のキーフレーム・#352 の送信量の予算を食わないため）
- 本文が縦に動いたときは、スクロール領域（`CSI t;b r`）と `CSI S`・`CSI T` で動かし、出てきた行だけを書く
- 読んだキーは全部処理してから、まとめて 1 回描く（貼り付けで 1 文字ごとに描かない）
- 画面の大きさは、描く前に `get-size` の `generation` を比べ、変わっていれば全体を描き直す。`tty-resize` のイベントは待たない（`kibi:kernel/events` をライブラリに出していないため）。大きさを変えても、次のキーまで描き直さない
- 色は使わない。タイトル・知らせ・キーの案内は反転（SGR 7）で分ける（単色のティアでも区別できる）
- タブは端末に HT を送らず、8 桁ごとの位置まで空白にして描く（タブの位置は端末の状態なので、送るとカーソルの計算がずれる。幅は `cat` で見たときと同じ 8）
- 制御文字は `^X`（2 セル）、DEL は `^?`、不正な UTF-8 は 1 バイトごとに U+FFFD（1 セル）、C1 の制御文字（U+0080〜U+009F）と前に文字のない幅のない文字は U+FFFD で見せる。ファイルの中のバイトを端末にそのまま送って端末の状態を変えない（`ESC c` など）。ファイルの名前・検索の語・知らせも同じ扱い
- UTF-8 は厳しく読む（overlong・サロゲート・U+10FFFF より上・途中で切れたものは不正）。不正なものは原文のバイトを送らない（端末の側で別の文字に読まれないため）
- 結合文字など幅のない文字は、前の文字と 1 つにまとめる（カーソルはその間に止まらない）
- 文字の幅は `kibi.text`。全角の表は core の `CharWidth` と同じ（端末が幅 0 にする文字を除く）で、`StandardOsTest` が全部のコードポイントで確かめる。幅のない表は主な範囲だけ（Unicode の Mn・Me・Cf のうち表にないものは 1 セルと見るので、その行ではカーソルがずれる。`sh` の行の編集と同じ制限。`sh` を `kibi.text` に寄せるのは #610）
- 長い行は、nano の既定と同じく、カーソルのある行だけを横に送る。送った行の左端と、続きがある行の右端に `$` を出す。送る量は「画面の幅 − 8」ずつ。右端の 1 セルに入らない全角の文字は書かない（折り返しを切ると右から 2 セル目に上書きされるため）
- キーの案内は縦に 2 つずつ組にし、前から「どの項目も切らずに入る」数の組を並べる（50 桁で 3 組、80 桁で 5 組、160 桁で 6 組）。入らない分はヘルプにある。画面が 8 行より低ければ案内を出さない

## テキストと上限

- ギャップバッファ。領域は静的に置き、使う範囲（長さ + ギャップ）だけを `kibi:computer/memory` の `commit` で 64 KiB ずつ先に数える。数えられなければ `Not enough memory` と出して、その入力・貼り付けを断る（RAM の上限を超えて書くとトラップで落ち、保存していない編集を失うため。#407）
- ギャップは 64 KiB ずつ広げる。触る区画は「長さ + 64 KiB」を超えない（待機点の保存の差分を小さく保つ。ADR 0083）。起動時に領域を埋めない（.bss は触るまで数えない）
- 上限は 4 MiB（仮の値。4 段目の HDD 8 MiB より小さい）。開くときに超えれば開かない。編集で超えるなら `The buffer is full` と出して断る。切り取ったものの領域も 4 MiB（同じく触った分だけ数える）
- 行の番号・行の数は増減で持つ（キーごとにテキスト全体をなめない）。キーごとの処理はカーソルのある行の長さと画面の大きさに比例する。とても長い 1 行（数 MiB）では、キーごとにその行をなめる
- 実行ファイルは約 31 KB（`ReleaseSmall`・`-fstrip`）

## 保存

1. `lstat` で調べる。ディレクトリなら誤り
2. シンボリックリンクなら、置き換えるとリンクが切れるので、先にそのまま書く（開いて切り詰めて書く）。今の VFS にはシンボリックリンクを作る口がないので、テストはない
3. それ以外は、同じディレクトリの一時ファイル `.<名前>.nano<0-9>` を排他で作って全部書き、閉じてから `rename` で置き換える（同じマウントの中なら不可分。ADR 0071）。失敗したら一時ファイルを消す
4. 一時ファイルの分の容量・項目がない（`NOSPC`・`DQUOT`）か、名前が長すぎるときは、元のファイルより大きくならない場合に限って、元のファイルに直接書く（1 段目の HDD 1 MiB・1,024 項目で、大きなファイルを直せるように）
5. 失敗したら（読み取り専用のマウント `ROFS` など）状態の行に `Error writing <名前>: <説明>` と出し、バッファはそのままで編集を続ける。^O で別の名前に書き出せる

## 今の制限

- 元に戻す（M-U・M-E）、置き換え（^\）、範囲の選択（M-A）、ファイルの挿入（^R）、外のコマンド（^T）はない
- 画面の大きさを変えても、次のキーまで描き直さない
- ~~一度に貼り付けられるのは 4 KiB まで。非 canonical の TTY の入力は合わせて 4 KiB までで、あふれた分は捨てられる（ADR 0060「入力の上限」）。6,000 バイトを貼ると 4,096 バイトだけ入ることをテストで確かめた。エディタの側では直せないので、#609 に分けた~~
  - 追記（#609）: TTY が入りきらない貼り付けを待たせ、読むたびに続きを入れるようにした（ADR 0060「入りきらない貼り付けの待ちの列」）。1回の貼り付けの上限（8 KiB）まで欠けずに入る。`NanoEditorTest` で、多バイト文字を含む約 6,000 バイトの Lua を一度に貼って全部入ることを確かめた
- ^V は使えない（クライアントの貼り付け）。PgDn を使う
- 待機点で保存・復元したときに編集を続けられるかは、ほかの待機点型のプログラムと同じ仕組み（ADR 0081・0085）に任せていて、このエディタだけのテストはない
  - 追記（#87）: 起動中ずっと `restored` だけを受け取るキューを開き、`nextKey` で、読んだバイトが残っていない（`keys.Reader.idle()`）ときだけ標準入力とキューを `poll_oneoff` で待つ。`restored`（source `""`）か `dropped > 0` を受けたら、`view.enter()`（`?1049h`・`?7l`）を出し直してから全体を描き直す（戻した表示のデバイスは初期の状態のことが多いため）。キューを開けなければ標準入力だけを待つ。待ちや取り出しに失敗したら（ハンドルが不正なときだけ）、閉じずに手放して標準入力だけを待つ。`core` の `StandardOsRestoreTest` で、保存・復元をまたいで描き直して編集を続けられることを確かめた（ADR 0087）
