# 0100: 標準 OS の /sbin/init

- 状態: 採用
- Issue: #100（task）。前提: ADR 0049（起動シーケンス。init は pid 1・環境変数なし・cwd `/`・標準入出力はコンソール）、0098（標準 OS のビルドと `kibi` ライブラリ）、0074（`kibi:process`）、0427（`kibi:io/tty`）
- 後続: #101（シェル `/bin/sh`）、#107（インストーラ。HDD に `/etc/inittab` を写す）、#306（停止・再起動のシステムコール）
- 番号は Issue 番号にそろえている

## 決めたこと（要約）

- ソースは `os/sbin/init.zig`。同梱イメージ `os` の `/sbin/init` になる
- 設定は `/etc/inittab`（1 行 1 項目の、この OS 独自の簡単な書式）。既定の内容を `os/etc/inittab` としてイメージの `/etc/inittab` に入れる（`os/etc/` はそのままイメージの `/etc/` に入る）
- init は TTY の初期化（cooked・前景なし）→ `run` を順に → `daemon`・`respawn`・`shell` を起こす → 子を待って起こし直す、を行う
- シェルはログインなしで起こす（ログインは置かない。マシンの中は1人の持ち主。ADR 0046）
- 新しいシステムコール・保存形式・公開 API は足していない。init の状態は WASM の線形メモリの中だけ（待機点の保存でそのまま戻る）

## inittab の書式

```
env NAME=VALUE        子に渡す環境変数を足す・置き換える（既定は PATH=/bin:/sbin、HOME=/）
run PATH [ARGS...]    起動時に、書いた順に 1 つずつ、終わるまで待って動かす
daemon PATH [ARGS...] 後ろで 1 回起こす
respawn PATH [ARGS...] 後ろで起こし、終わったら起こし直す
shell PATH [ARGS...]  コンソールのシェル（1 つだけ）。前景で起こし、終わったら起こし直す
```

- `#` で始まる行と空行は飛ばす。語は空白・タブで区切る（引用符・行の途中のコメントは使えない。シェルが要る書き方は `run /bin/sh /etc/rc` のようにシェルに任せる）
- PATH は絶対パスで書く（init は `PATH` で探さない）
- init はファイル全体を読んでから子を起こすので、`env` は書いた位置に関わらず全部の子に効く（上の行の項目にも効く。同じ名前は後の行が勝つ）
- 分からない種類・形の違う `env`・2 つ目の `shell`・上限超えは、`init: /etc/inittab:<行>: <理由>` を書いて、その行だけ飛ばす。警告は 1 行に 1 つ（語の数の上限を超えた行は `too many words` だけを書いて捨てる。分からない種類は語を集める前に `unknown entry` とする）
- inittab がなければ（`NOENT`）`shell /bin/sh` だけの既定で動く。読めない・大きすぎる（8 KiB 超）ときは `init: /etc/inittab: <errno>; using the default` を書いて既定で動く（直すためのシェルが起こせるように）
- inittab があって `shell` の行がなければ、シェルは起こさない（後ろの常駐プログラムだけのマシン）
- 上限（仮の値）: 項目 32、全部の語 512、環境変数 32、1 項目の引数 4,096（`process.MAX_SPAWN_ARGS`。#101 で 64 から、#501 で 256 から上げた。全部の語 512 の方が先に効く）

## 子の起こし方

| 種類 | 標準入力 | 標準出力・エラー | 前景（Ctrl+C の相手） | 終わったら |
| --- | --- | --- | --- | --- |
| `run` | コンソール | コンソール | その子 | 次の項目へ |
| `daemon` | なし（閉じる） | コンソール | ならない | そのまま |
| `respawn` | なし（閉じる） | コンソール | ならない | 起こし直す |
| `shell` | コンソール | コンソール | その子 | 起こし直す |

- 子の cwd は `/`。ただし `shell` の子（ログインシェル）は `HOME`（絶対パスのディレクトリでなければ `/`。起こすたびに見る。#486）、環境変数は `env` の行と既定（init 自身は環境変数を持たない。ADR 0049）。根の preopen（fd 3）は渡す（`kibi` の既定）
- TTY の初期化: `run`・`shell` を起こす前と、`shell` が終わった後に、コンソールを cooked（`tty.Mode.cooked`）に戻し、前景を 0 にする。前のシェルが raw のまま落ちても、次のシェルは cooked で始まる。起動のたびにも行う（コンソールの TTY は再起動をまたいで残る。ADR 0049）
- 前景は子を作ってから設定するので、子の最初の一瞬は前景でないことがある（シェルは前景を確かめてから待てばよい）
- 起こし直し: 起こしてから 1 秒未満で終わった子は、1 秒おいてから起こし直す（すぐ落ちる子で回り続けないため。仮の値）。待つ間は `poll_oneoff` の時計で待つ（待機点）
- 起こせない（`NOENT` など）ときは `init: cannot start <PATH>: <errno>` を書き、その項目は起こし直さない
- コード 0 以外で終わった・シグナルで止められた・落ちた子は、`init: <PATH> exited with code <n>` / `was killed by <signal>` / `crashed` を書く。コード 0 は黙る。マシンの停止・再起動で止められた子は何も書かず、起こし直さない
- 待ち方: 動いている子のハンドルすべてを `poll_oneoff` の `FD_READ` で一度に待ち、起きたら各子の `status` を見る（ADR 0074 の Q1-A）。init は子の終わりを刈り取り、ハンドルを閉じる
- 動いている子も起こし直す予定もなくなったら、`init: nothing left to run` を書いて 0 で終わる（カーネルがマシンを止め、`kibi: init exited with code 0` を書く）

メッセージは英語の固定の 1 行で、標準エラー出力（コンソール）に書く（カーネルのメッセージ ADR 0049 に合わせた）。

## 今の制限

- `/bin/sh` は #101 で入った（ADR 0101）
- 停止・再起動のコマンド（#306）、ランレベル・サービスの依存順・ログのファイルは置かない（必要になったら足す）
- 環境変数 `TERM` は既定で渡さない（端末の名前は docs/terminal.md。使うプログラムができたら inittab の既定に足す）

## 確かめ方

`core` の `InitTest`: 起動の手順（#49）で、メモリのディスクに置いたイメージの `/sbin/init` を pid 1 として動かす。子は `os/test/initprobe.zig`
（前景か・標準入力・TTY のモード・環境変数を書く）。inittab なしの既定、イメージの inittab、各種類の振る舞いと順序、警告、cooked に戻すこと、起こし直し、
動かす子がなくなったら終わること、シェルがないとき。
