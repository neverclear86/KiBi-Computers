# 0129: 隣接ブロックのデバイスの検出と接続

- 状態: 採用
- Issue: #129（task）。前提: ADR 0065（デバイスのモデル）、0066（接続数の上限）、0067（接続・切断のイベント）、0085（読み込みでの復元）、0355（表示デバイス）、#360（キーボードの持ち主）
- 仮の結線 `TestComputerWiring`（#307）を、この ADR の登録表と結線に置き換えて消した
- 後続: #130（ケーブル。候補の出し元を差し込む）、#131（持ち主と権限）、#138（大型モニター）、#153（他 MOD のブロック）、#224（1.20.1 への移植）

## 決めたこと

### 登録表（`core.device.wiring.DeviceRegistry`）

- 位置のキー（接続層では（ディメンション、座標）の `GlobalPos`）から、デバイスの持ち主（`DeviceHolder`。画面・キーボードのブロックエンティティ）を引く。
  `HashMap` を1回引くだけで、割り当てない
- 持ち主は、サーバーで読み込まれたら（`onLoad`）載り、壊れた・置き換えた・アンロードした（`setRemoved`・`onChunkUnloaded`）ら外れる。
  載るたびに新しい世代（`Entry.generation`）を振るので、壊して同じ座標に置き直したもの・チャンクを読み込み直したものは別の登録になる
- 結線は、つないだデバイスの登録（`Entry`）を持ち、使うたびに登録表の今の登録と照らす（ブロックエンティティの参照を持ち続けない）
- **世代と、誰がつないでいるかは保存しない**（実行時だけ。ADR 0065 の Q6 と同じ）。address は今までどおり持ち主の NBT に書く

### 排他

- 組み込みのデバイス（画面・キーボード）は、つながるマシンを1台に限る（`Entry.owner`）。ほかのケースは、持ち主が手放すまでつながない。
  他人のキーボードの隣にケースを置いても、打った内容は読めない。他人の画面の隣に置いても、表示は乗っ取れない
- 共有の口は作らない（公開 API に「共有できる」印を足すのは #153 で人に聞く）
- 手放す（電源を切った・止まった・ケースが消えた・アンロードした・候補から外れた）と、そのキーを見張っているほかの結線に知らせ、
  tick の終わりにつなぎ直させる（空いたら次へ）
- **危険（受け入れる）**: 誰が持っているかを保存しないので、サーバーを再起動すると、復元の順番待ち（`ServerMachines.offerRestore`）で先に来たケースが持つ。
  2台のケースが同じキーボードに隣り合っていると、再起動の後に持ち主が入れ替わりうる。本当に直すのは持ち主と権限（#131）。
  #131 でデバイス側に持ち主を持たせるかを決めるときに、ここも見直す

### 候補と順番（`core.device.wiring.MachineWiring`）

- 候補は、ケースの隣の6方向（**下・上・北・南・西・東**の決まった順）と、そこでつないだ画面の中継（`DeviceHolder.relayKeys`）。
  中継は画面の正面の前、その1つ下（机の上）、画面の下・上、左右、後ろの順（`KeyboardInput.keyboardSpots`。右クリックで GUI を開くときの探し方と同じ）
- 中継で届いたものは、中継してよいもの（`DeviceHolder.relayable`。キーボードだけ）だけつなぐ。中継は1段だけ（画面から画面へは伸びない）。
  OpenComputers と同じく、画面の前のキーボードは、その画面をつないだマシンのものになる。今の置き方（ケースの上の画面と、その前のキーボード）がそのまま使える
- 隣の画面・キーボードは**すべて**つなぐ（上限まで）。つないだ順に `DeviceBus` に入るので、最初につないだ画面がコンソールの出力先（`primaryScreen`）。
  出力先の画面が外れたら、次につないだ画面が出力先になる
- 中継していた画面が外れたら、それを通してつないでいたキーボードもすぐに外して手放す（ケースの隣にもあるなら残る）
- ケースの内蔵スピーカーは隣接の仕組みの外。ケースの address で、電源が入っている間ずっとつなぐ（今までどおり）

### つなぐ時機

- つなぐのは「電源を入れた」「保存から戻した（`RestoreReady` の中。起動はしない）」ときと、頼まれたつなぎ直し（`CaseWiring.rewire`）だけ
- つなぎ直しは、結線が見張っているキー（候補）にデバイスが載った・手放されたとき、自分のデバイスが外れたとき（断った候補の見直し。ADR 0066）に
  頼まれ（`DeviceWiring.schedule`）、**サーバーの tick の終わり**（`ServerTickEvent.Post`）にまとめて行う。同じ結線は1回にまとめる。
  `onLoad` やチャンクの読み込みの途中ではつながない（隣のチャンクを読みに行かない）。置いたブロックのデータ（address）は `setBlock` の後で読み込まれるが、
  tick の終わりにはそろっている（#535）
- 頼まれない台は何もしない。tick ごとの巡回も、`generation` の見比べもしない。ケースの `neighborChanged` も見ない（デバイスを置けば登録表から知らせが来る）
- つなぎ直すのは、ケースの今のマシンがこの結線のマシンで、止まっていない（`Machine.isRunningBootingOrRebooting` を1回だけ読む。#625・#626）ときだけ。
  再起動の途中もつなぐ。止まったマシン（CRASHED・ゲストが止めた・起動に失敗した）はケースが外し、結線も外す（#640・#641）

### address の重なり

- 同じマシンにもう同じ address のデバイスがつながっていたら、**後から来たほう**（今つなごうとしているもの）の address を振り直してつなぐ
  （`DeviceHolder.reassignDeviceAddress`。NBT の `DeviceAddress` の値が変わるだけで、保存の形は変わらない）。例外でサーバーを止めない
- サーバーを起動し直すと、読み込みの順で「後から来たほう」が替わりうる。そのとき元の側が振り直されると、ゲストが保存したそのデバイスのハンドルは `detached` になる。受け入れる
- address の形・種類の形の誤り（`IllegalArgumentException`）は、ログに出してつながずに手放す

### 外れたとき

- 登録が外れたら（壊れた・アンロードした）、すぐにマシンから外す（`DeviceBus.detach`。`device-detached` は `DeviceBus` が出す。接続層では出し直さない。ADR 0067）。
  画面は、書ききれずに取っておいた出力を捨てる（#381・#397）
- デバイスのチャンクだけがアンロードされたときは、マシンを止めない。外すだけにする。読み込み直したら、新しい世代としてつなぎ直す
- キーボードがマシンから外れるときは、開いている入力のセッションを閉じる（押したままのキーの離しは、外れる前のマシンに届く）。
  持ち主が替わった後に、打ったものが別のマシンに届かないようにする

### 入力 GUI の画面

- サーバーが、キーボードがつながったコンピューターのコンソールの画面（`KeyboardInput.connectedScreen`）を決めて、GUI を開く知らせに載せる。
  つながっていなければ右クリックした画面。クライアントは自分で画面を探さない（仮の結線への依存をなくした）

### 仮の起動

- 起動部品があるとみなすこと・同梱イメージの起動の候補は `ProvisionalBoot` に移した（#99・#125・#107・#145 まで残る）
- GameTest と負荷試験は、標準 OS とは別の試験用の起動イメージ（`ProvisionalBoot.TEST_BOOT_DISK`）を、ケースごとに明示して使う（`CaseBlockEntity.fallbackBootDisk`）

## スレッド・負荷

- すべてサーバーのメインスレッド。`DeviceBus.attach`・`detach` はカーネルロックを短く取るので、カーネルロック・デバイスのロックを持って呼ぶ経路は作らない（ADR 0067 のロックの順のまま）
- 待っているだけの台は tick ごとに何もしない。サーバーの起動時は、デバイスが載るたびに見張っている結線に頼むだけで、つなぐのは tick の終わりにまとめて行う
- 満杯（`DeviceBus.size >= limit`）なら、デバイスを作らずに断る（表示デバイスを作らない）
- 見張りの表は、動いている台ごとに候補の数（隣の6と中継の7まで）だけ持つ

## 後続をふさがないこと

- 候補の出し元は `MachineWiring.Host.neighborKeys`。ケーブル（#130）は、ここをケーブルの網の端に差し替える
- 他 MOD のブロック（#153）は、`DeviceHolder` を実装した持ち主を同じ登録表に載せれば、同じ規則でつながる
- 大型モニター（#138）は、複数の座標を1つの持ち主で載せる（登録表のキーは座標ごと、持ち主は同じもの）

## 比べた案

- **A. 結線がブロックエンティティの参照を持ち、`isRemoved` で見る（仮の結線の形）**: チャンクを読み込み直してもつなぎ直さない。退けた（#129 のオーナーのコメント）
- **B. tick ごとに全台の隣を見回る**: 台数に比例して毎 tick かかる。退けた（ADR 0066・0067）
- **C. `onLoad` の中でその場でつなぐ**: address がまだ読み込まれていない（#535）、チャンクの読み込みに再入する。退けた
- **D. 画面とキーボードを1つずつに限る**: 規則が増えるだけで、ケーブル（#130）や大型モニターにつながらない。隣のものは全部つなぐ形にした
