**WASI p2 command components run with exec (#687). p3 and the p2 interfaces of `kibi:*` are not available yet.** This page describes the current status and the plans. Once the shapes are settled, they will be added to this reference.

## Current status

- Only command components that export `run: func() -> result` of `wasi:cli/run@0.2.<n>` run. If it is missing, exported more than once, or has another type, exec fails with `NOEXEC`. The exit code is 0 when `run` returns `ok`, 1 for `err`, and the given value when the program calls `wasi:cli/exit`
- Only `wasi:*@0.2.<n>` can be imported. Imports the host does not provide (including `kibi:*`) and `wasi:*@0.3.x` (p3) fail at load time with `NOEXEC`
- As with p1, a loaded component is shared across the server, and fuel metering code is inserted when it is loaded
- A component process uses one thread even while it waits (a blocking process; waiting without a thread is [#757](https://github.com/neverclear86/KiBi-Computers/issues/757)). Once the server-wide limit of blocking processes is reached, no more can be created (`spawn` of `kibi:process` returns `nfile`)
- Its state is not saved. A generation save stops such a process, and it is gone after a restore ([#269](https://github.com/neverclear86/KiBi-Computers/issues/269))

## Direction

- p1, p2, and p3 are thin layers over the same kernel foundation (file descriptors, event waiting, streams). The same processes, files, and devices mean the same thing from every layer
- p2 and p3 use the same `kibi:*` WIT packages. Interfaces that work the same way as in p1 (`kibi:process/process`, `kibi:io/tty`, `kibi:computer/*`, `kibi:fs/mounts`, `kibi:device/bus`, and so on) are imported as they are
- Waiting differs per layer. p1 waits on fds with `poll_oneoff`; p2 is planned to wait with `wasi:io` pollables, and p3 with async functions. The p2 and p3 ways of waiting are in separate interfaces so that the shared ones do not depend on `wasi:*`
- The p1-only interfaces (`kibi:io/fd`, `kibi:io/pipe`) are not used in p2 or p3

## Provisional interfaces

The following interfaces exist only as WIT and are not implemented. They cannot be imported from p1 (`NOEXEC`). **Their shape (interfaces, functions, types, and `wasi:*` versions) will change when the p2 and p3 layers are built.** Do not depend on them.

| Interface | For | Contents |
| --- | --- | --- |
| `kibi:kernel/events-poll` | p2 | A pollable for an event queue |
| `kibi:kernel/timers-poll` | p2 | A pollable for a timer |
| `kibi:kernel/events-async` | p3 | Wait for and take events |
| `kibi:kernel/timers-async` | p3 | Wait until a timer fires |
| `kibi:process/process-poll` | p2 | A pollable for a child's exit, and a `spawn` that passes p2 handles to the child |
| `kibi:process/process-async` | p3 | Create and wait for children |
| `kibi:io/pipe-streams` | p2 | Return a pipe as `wasi:io` streams |
| `kibi:io/pipe-async` | p3 | Return a pipe as a `stream<u8>` |
| `kibi:device/bus-poll` | p2 | A pollable for a queued call |
| `kibi:device/bus-async` | p3 | Wait for the result of a call |

The p1 layer and the Component Model layer report some argument mistakes differently ([Common rules](./kibi-abi.md#errors)).
