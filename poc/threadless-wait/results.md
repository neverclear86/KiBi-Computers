# 入力待ちの p1 プログラムにスレッドを持たせない方式の測定結果（#316）

- `./gradlew :poc:threadless-wait:run` の出力。Endive 1.2.0。JVM 引数: -Xms4g -Xmx4g -XX:+UseG1GC -XX:NativeMemoryTracking=summary

- 仮想スレッド: 使える

中央値。`prompt bench` は関数ポインタ経由の呼び出しと qsort（どちらも変換の対象）。Lua はフィボナッチと文字列・テーブルの処理（`luaV_execute` などが変換の対象）。

| プログラム | 実行方式 | 変換なし | 変換あり | 比 |

| prompt bench | インタプリタ | 417 ms | 656 ms | 1.58 |
| lua | インタプリタ | 2257 ms | 2628 ms | 1.16 |
| prompt bench | ランタイムコンパイラ | 635 ms | 986 ms | 1.55 |
| lua | ランタイムコンパイラ | 7771 ms | 13153 ms | 1.69 |

## 4. 1000 台が入力待ち（prompt、ランタイムコンパイラ）

差は、何も動かしていないときからの増分。tick は模擬サーバー（20 TPS、1 tick に 5 ms の計算と 32 MiB のごみ）を 5 秒。起こす時間は、全台に1行渡して全台が次の待ちに戻るまで。
A の再開は固定のワーカー（CPU のスレッド数の半分）で行う。A のスレッドの増分はこのワーカー（台数によらない）。B の増分は仮想スレッドを載せるキャリア（ForkJoinPool。CPU のスレッド数まで）

| 方式 | 待ちに入るまで | スレッド | スレッドのスタック（確保済み） | ヒープ | MSPT 平均 / 最大 | GC（回数 / 合計） | 全台を起こす |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| （なし） | - | 7 | 2 MiB | 68 MiB | 8.0 / 10.2 ms | 1 / 2 ms | - |
| C: プラットフォームスレッド | 167 ms | +1000 | +69 MiB | +1276 MiB | 8.9 / 13.8 ms | 1 / 2 ms | 14 ms |
