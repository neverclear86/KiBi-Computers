# 燃料計測の方式の測定結果（#28）

`./gradlew :poc:fuel-metering:run` の出力（Java 21、1回）。Endive 1.2.0。

- WASM と Lua のスクリプトは #26 と同じ（`bench.wasm`、`lua.wasm`。`fib.lua`・`tables.lua`・`strings.lua`）
- 時間は、ウォームアップ（1.5 秒以上）の後に 3 秒以上かつ 3 回以上測った中央値
- 燃料は十分に配って測った（表 4 を除く）。Lua は時計と乱数を固定している（Lua はハッシュの種に `time()` を混ぜるので、固定しないと実行のたびに命令数が変わる）
- 命令の重みはすべて 1（燃料 1 = WASM の命令 1 つ）
- A（グローバル）: 引くたびに燃料のグローバルを読み書きする。A（ローカル）: 関数の中ではローカル変数に写して引き、呼び出し・戻る前にだけグローバルに書き戻す
- B は Endive のインタプリタの `ExecutionListener`（命令ごとに呼ばれる、実験的な口）で数えた。ランタイムコンパイラ・ビルド時AOT には同じ口がない
- 確かめる間の最大命令数: 燃料が負かを確かめるのは関数の入口と `loop` の先頭だけなので、その間に実行されうる命令数の最大（燃料の行き過ぎの上限）

## 補足: JVM の大きなメソッドの制限（`-XX:-DontCompileHugeMethods`）

lua.wasm に A（ローカル）を入れると、ランタイムコンパイラで約 2 倍遅くなる。C のベンチマーク（1.0〜1.1 倍）より大きいのは、HotSpot が 8,000 バイトを超えるメソッドを JIT コンパイルしない（`DontCompileHugeMethods`）ためで、挿入で Lua の大きな関数がこの上限を超える。`-XX:-DontCompileHugeMethods` を付けて測ると（`-Pbench.args=quick "-Pbench.jvmArgs=-XX:-DontCompileHugeMethods"`、1回ずつ）:

| スクリプト | ランタイムコンパイラ / なし | A（グローバル） | A（ローカル） |
| --- | ---: | ---: | ---: |
| lua fib.lua | 181 ms | 1400 ms（7.72x） | 160 ms（0.88x） |
| lua tables.lua | 343 ms | 3335 ms（9.72x） | 244 ms（0.71x） |
| lua strings.lua | 190 ms | 1488 ms（7.82x） | 169 ms（0.89x） |

計測なしの速さは変わらず（上限を超える関数がない）、A（ローカル）はほぼ差がなくなる。MC のサーバーに JVM の引数を求めることはできないので、実装では挿入するコードを小さく保つ（ADR に記載）。
